## 읽기 전용 시장 분석 CodeAct (D-176, 2026-09-19)

- **발견·리서치 연결(D-180~182)**: `/discover`의 자연어 입력 → 후보 목록/차트 → 기업 조사 → 사용자 판단으로 연결한다. 도크·옴니바에서 진입하며 `/chat?mode=analysis`는 쿼리를 보존해 리다이렉트한다. 50개 전략 도구·이력은 Sheet, 저장/추천/조사는 라이브러리로 제공하고 기존 전략 버전·후속 검색·백테스트를 유지한다. `candidate`·`run`, 기업의 `discovery`·`research`·`researchTab`·`lane`을 URL로 보존한다. `DiscoveryNavigationMemory`는 목록 복귀 스크롤/포커스를 탭 단위로 기억한다. **검색 스레드(D-184)**: `GET /runs/:id/thread`(RunStore.thread, 뿌리+모든 후속 생성순)로 후속 검색을 같은 화면에 턴으로 쌓고 `run=` 턴만 펼친다(`useAnalysisThread`, `ThreadTurn`). 후보 목록은 TanStack Table(시총 정렬). 기업 조회 기본 레일은 접고 차트/근거 조사/내 판단을 우선한다. 기업 개요 카드 '기업 개요'는 `company/CompanyOverview`(D-188 웹 조사 보고서: 개요·사업 구성·제품/고객·경쟁·동인/리스크·최근 사건·출처, '웹으로 다시 조사')이고 조사 준비 목록에 `web` 레인이 표시된다. 계약은 [검색 UX·수집](specs/market-codeact.md#12-발견조사-ux-개편과-필요한-자료-준비-2026-09-19)·[기업 리서치](specs/company-research.md)에 있다.
- `expression.py`·`expression_screen.py`: 최대 12개 조건의 AND/OR/NOT·사건 순서·연속 유지를 결정적으로 계산한다. 결측의 NOT은 미평가이며 OR의 확인된 참은 통과다. 후속 검색은 `parent_run_id`와 변경분을 저장하고 원 유니버스/직전 후보·같은 스냅샷/최신 자료를 구분한다. 전체 조건의 모델 재작성은 거절한다. 순위는 기존 AND 목록에서만 지원한다.
- `discovery_store.py`·`discovery_service.py`·`routers/discovery.py`: 전략 버전·발견·사용자 판단·근거 조사를 원본 DB 밖에 트랜잭션·멱등키·수정 버전 충돌 검사로 보존한다. API `/api/analysis/discovery`; GET은 조회만 한다. 연구 worker는 단일 파일 잠금·취소·중단 복구를 사용하며 과거 연구/사용자 메모를 재작성하지 않는다.
- `discovery_research.py`: 원본 SQLite의 `mode=ro`·`query_only` 트랜잭션에서 시장/전방/실적/콜/수출입의 제한된 실제 발췌·수치를 고정하고 연결을 닫은 뒤 도구 없는 Claude에 전달한다. 공개 시점·콜 추정일·HS 연결/단위·자료 없음은 명시하며 주장별 실제 근거 ID를 검사한다. 사용자 판단은 근거와 별도다. 후속 조사에서 같은 ID의 내용 변경까지 비교한다. 제한 검색과 원천 시점/귀속 공백 때문에 현재 결과는 `partial`이다. 명시적 조사 요청의 자료 준비는 다음 항목을 따른다. 자동 질문 확증·전체 후보 조사·개인화 추천은 추가하지 않았다.

- `discovery_preparation.py`(D-182): `POST /cases`의 `start_research=true`는 발견과 첫 조사를 원자적으로 만들거나 재사용한다. 기존 `POST /cases/:id/research`는 새 후속 조사다. 수집→읽기→정리 phase와 자료별 상태를 연구 이력에 남긴다. 수집기는 선택 기업의 최근 3개 연도/분기 재무와 최근 1년 공시 제목(최대 300건)만 확인한다. 원본 DB에는 검증된 누락 행만 `INSERT OR IGNORE`하고 기존 수치/공시는 보존한다. `logs/market-discovery/preparation.sqlite`의 append-only receipts에는 공개 접수번호·수집 시각·원 응답·만료를 남긴다. 성공 24시간/명시적 미제공 6시간, 오류는 캐시하지 않는다. 기업별 flock, 30요청/90초/5MB응답 제한과 취소 후 저장 차단을 둔다. 과거 기준일에는 새 수집을 건너뛴다. 생성 코드·모델은 이 수집기에 접근하지 않으며 GET/재진입은 새 작업을 만들지 않는다. 국내 콜 자동 수집·기업/HS 자동 귀속·기존 수치의 최신 정정 확인은 미지원이다.

- **전략 비교 백테스트(D-179)**: 시장 분석 → `/analysis/backtests`. 단순 보유·SMA 교차·20일 돌파·20일 수익률·52주 돌파·역헤드앤숄더 추가·20일선 유지 추가의 7개 전략을 독립 초기 자금의 개발/평가 구간에서 비교한다. `backtest_engine.py`의 순수 계산은 판단일 종가로 수량을 정하고 다음 관측일 시가로 순매매하며 비용·현금 부족·결측·미체결을 보존한다. `backtest_data.py`는 해시 검증된 Parquet만 읽는다. `backtest_runner.py`는 사전 조건/코드/입력 고정, OS 격리 2회 재실행, 종료 후 입력 해시 재확인과 `backtest_verification.py`의 별도 체결·평가 검산을 거친다. `/api/analysis/backtests`의 생성·조회·취소·등록 산출물 API와 `BacktestPage`/`useBacktest`를 연결했다. 원본 DB 밖 `logs/market-backtests/`에 이력·JSON/CSV를 보존하며 모델·임의 코드·SQL을 받지 않는다. 첫 실제 비교·관련 백엔드 123개 검사·프론트 빌드와 브라우저 확인 완료. 짧은 표본·생존 편향·시총 이력 공백 때문에 결과는 항상 잠정이다. [계약·검증 기록](specs/market-backtest.md).

- **전략 도구(D-178)**: `GET /api/analysis/strategies`의 60개(가격 구조 10개 포함, D-187) 버전 관리 카탈로그를 화면·모델·검증기가 공유한다. 일봉 46개와 현재 자료가 없는 10분봉 3개·실제 거래대금 순위 1개를 구분한다. 최대 12개 조건을 AND로 평가하고, 순위들은 동일한 일반 조건 통과 집합에서 각각 계산한 뒤 교집합을 취한다. `strategies.py`의 순수 계산과 `strategy_screen.py`의 스냅샷 어댑터를 `analytics.py`와 함께 해시·격리 복사한다. 선택 실행의 `RunRequest.spec`은 모델 호출 없이 같은 실행 관찰/독립 검증/AG-UI 이력을 사용한다. 자연어는 기존 CodeAct 루프에 카탈로그를 제공한다. [정의](specs/market-strategies.md).

## Weekly 분석 하네스 실험 (D-162, 2026-09-15)
