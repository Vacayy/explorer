# Stock Explorer — Product Requirements Document

> 최종 수정: 2026-06-15

---

## 1. Problem Statement

### 문제 정의
한국 주식 시장의 전문 투자자(펀드매니저, 리서치 애널리스트)는 투자 의사결정 과정에서 **여러 도구를 오가며 작업**한다:
- 재무 데이터 조회: FnGuide, CompanyGuide (유료, 월 수십만원)
- 공시 확인: DART (원시 데이터, 가공 안 됨)
- 밸류에이션: 엑셀 직접 작업
- 투자 메모: 노션, 워드, 개인 파일
- 동종업계 비교: 수동 취합
- 모니터링: 뉴스, 공시 개별 확인

이 파편화된 워크플로우는:
- **전환 비용**이 크고 (도구 간 이동, 데이터 재입력)
- **인사이트 단절**이 발생하며 (데이터는 여기, 메모는 저기)
- **반복 작업**이 많다 (같은 종목을 매번 처음부터 조회)

### 해결하지 않으면
- 투자 판단 속도가 느려진다
- 중요한 시그널을 놓친다 (공시, 내부자 거래)
- 분석의 일관성이 떨어진다 (기억에 의존, 구조화 부재)

## 2. Target User

### Primary: 기관 전문투자자
- **직책**: 사모펀드 PM/애널리스트, 자산운용사 리서치팀, 증권사 리서치센터
- **행동 패턴**: 일일 10~30종목 스크리닝, 5~10종목 심층 분석, 분기별 포트폴리오 리뷰
- **기존 도구**: Bloomberg, FnGuide, CompanyGuide, 엑셀, 사내 시스템
- **핵심 니즈**: 정확한 데이터 + 빠른 비교 + 구조화된 리서치 기록
- **기대 수준**: Bloomberg 급 데이터 정확성, 그 이상의 UX 직관성

### Secondary: 개인 전문투자자 (슈퍼개미)
- **행동 패턴**: 주간 5~10종목 모니터링, 월간 신규 아이디어 탐색
- **기존 도구**: 증권사 HTS/MTS, 네이버증권, Butler
- **핵심 니즈**: 유료 서비스 대체, 한 곳에서 모든 정보 조회
- **기대 수준**: 무료이되, FnGuide 수준의 데이터 커버리지

## 3. Product Vision & Phases

### Vision
**"투자 아이디어 발굴부터 의사결정까지, 하나의 도구에서."**

### Phase 1 (현재): 데이터 기반 + 워크플로우 통합
- 정확한 재무/주가/공시 데이터 (FnGuide 대체)
- 투자자 워크플로우에 맞는 3단계 네비게이션 (발굴 → 분석 → 리서치노트)
- 로컬 실행, 무료

### Phase 2 (향후): AI 인사이트
- 이상치 자동 감지 (급격한 마진 변화, 비정상 내부자 거래)
- 자동 투자 시그널 추천
- 자연어 리서치 질의 ("최근 3년 영업이익률이 꾸준히 개선되는 반도체 장비주는?")

### Phase 3 (장기): 협업 플랫폼
- 팀 공유 워치리스트, 리서치노트
- 실시간 알림 (공시, 가격 알림)
- 클라우드 배포

## 4. Success Metrics

### North Star
- **주간 활성 사용 세션 수** (Weekly Active Sessions)
- 목표: 개인 사용 기준 주 5회 이상 접속

### Primary Metrics
| 지표 | 정의 | 목표 |
|------|------|------|
| 발굴 → 분석 전환율 | 산업군/스크리너에서 기업 상세로 진입한 비율 | > 40% |
| 분석 체류 시간 | 기업 분석 페이지 평균 체류 시간 | > 3분 |
| 워치리스트 등록률 | 분석 진입 종목 중 워치리스트 추가 비율 | > 20% |
| 리서치노트 작성률 | 워치리스트 종목 중 메모 작성 비율 | > 30% |

### Guardrail Metrics (깨지면 안 되는 것)
| 지표 | 기준 |
|------|------|
| 페이지 로딩 시간 | 캐시 히트 시 < 1초, 미스 시 < 5초 |
| 데이터 정확성 | DART 원본과 불일치율 < 1% |
| API 일일 호출 | DART 10,000건 한도 이내 |

## 5. Information Architecture

```
Stock Explorer
│
├── 발굴 (Discovery) ─────────── "무엇을 살까?"
│   ├── 산업군맵 (/discover/industry)
│   ├── 스크리너 (/discover/screener)
│   ├── 시그널피드 (/discover/signals)
│   └── 대안데이터 (/discover/alt-data)
│
├── 분석 (Analysis) ──────────── "이 회사, 살 만한가?"
│   ├── 요약 (/analyze/:code/summary)
│   ├── 재무정보 (/analyze/:code/financials)
│   ├── 밸류에이션 (/analyze/:code/valuation)
│   ├── 사업정보 (/analyze/:code/business)
│   └── 공시 (/analyze/:code/disclosures)
│
└── 리서치노트 (Research) ────── "판단을 기록하고 추적한다"
    ├── 워치리스트 (/research/watchlist)
    ├── 투자메모 (/research/memos)
    └── 카탈리스트 (/research/catalysts)
```

### 네비게이션 원칙
1. **모드 전환은 최상위에서** — 발굴/분석/리서치는 동시에 하지 않는다
2. **분석은 기업 선택이 전제** — 기업 없이 분석 모드 진입 불가
3. **워치리스트는 항상 접근 가능** — 우측 사이드바로 모든 모드에서 표시
4. **URL이 상태의 진실** — 모든 화면은 고유 URL, 북마크/공유 가능

## 6. Scope

### Phase 1 Scope (이번 구현)

#### P0 — Must Have
- [x] 3단계 네비게이션 (발굴/분석/리서치노트)
- [x] 산업군 스크리너 테이블 (재무지표 컬럼 + 히트맵)
- [x] 기업 요약 Hero KPI 카드 (현재가, 시총, PER, PBR, OPM, ROE)
- [ ] 워치리스트 (DB 저장, 확신도/목표가/한줄논점)
- [ ] 스크리너 (조건 기반 전 상장사 필터링)
- [ ] 투자메모 구조화 (Bull/Bear/Catalyst/Risk 섹션)

#### P1 — Should Have
- [ ] 시그널피드 (워치리스트 종목 주요 공시 통합 피드)
- [ ] 요약 페이지에 Metrics 차트 통합
- [ ] 밸류에이션에 MarketCap 차트 통합
- [ ] 카탈리스트 캘린더

#### P2 — Nice to Have
- [ ] 다중 기업 비교 (VS 모드)
- [ ] CSV/Excel 내보내기
- [ ] 키보드 단축키 (/ 검색, 숫자키 탭 전환)

### Out of Scope (이번에 안 만드는 것)
| 항목 | 이유 |
|------|------|
| 포트폴리오 관리 (보유 종목, 수익률) | 별도 대형 기능, Phase 2에서 |
| 실시간 주가 알림 | 로컬 서비스에서 push 인프라 부재 |
| 다크모드 | 차트 색상 체계 재설계 필요 |
| 모바일 반응형 | 전문 투자자 → 데스크톱 우선 |
| 사용자 인증/계정 | 로컬 단일 사용자 |
| AI 자동 분석 | Phase 2 범위 |

## 7. Data Sources & Freshness Policy

| 데이터 | 소스 | 갱신 주기 | 캐시 TTL |
|--------|------|---------|---------|
| 기업 목록 | DART corp_codes | 수동 시딩 | ∞ |
| 재무제표 | DART finstate_all | 분기별 공시 후 | 7일 |
| 공시 목록 | DART list | 매일 | 1일 |
| 주가 OHLCV | pykrx | 장 마감 후 | 1일 |
| 시가총액 | yfinance + 종가×발행주식수 | 장 마감 후 | 1일 |
| PER/PBR/ROE | 자체 계산 (재무제표+주가) | 재무/주가 갱신 시 | 연동 |
| 사업부문 매출 | 사용자 입력 | 수동 | N/A |
| IR 메모 | 사용자 입력 | 수동 | N/A |
| 워치리스트 | 사용자 입력 | 수동 | N/A |

## 8. Technical Constraints

| 제약 | 영향 | 대응 |
|------|------|------|
| DART API 일일 10,000건 | 대량 스크리닝 시 한도 도달 가능 | SQLite 캐싱 + 배치 ETL |
| pykrx 시총/펀더멘탈 불안정 | KRX 로그인 미지원 시 실패 | yfinance fallback + 자체 계산 |
| 로컬 실행 전용 | 네트워크 의존, 서버 리소스 제한 | 배치 ETL로 오프라인 캐시 확보 |
| SQLite 동시성 | 단일 사용자 전제 | WAL 모드로 충분 |
