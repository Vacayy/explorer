## 게이트 대기
- 무역 커넥터 ← 관세청 API 키
- RAG 고도화 ← 문서 1,000+건 (H3)
- 1M 다이제스트 ← 7D 아카이브 4주
- WR·유증매수가 ← 신주인수권증서 시세
- **다중 사용자 배포 아키텍처** ← 실제 배포 결정 시점 (2026-07-18 논의)
  주변 사람들에게 배포 시 개인화·토큰비용 우려. 검토한 두 방향:
  ① 완전 포크(사람별 별도 인스턴스) — 스키마 변경 0, 대신 수집·enrich(가장 비싼 부분)를
  N배 중복 실행 + 코드베이스 분기 유지보수 부담.
  ② 레이어 분리(권장) — 수집·인과그래프·내러티브·지식(룰 기반 게이트를 거치는 "공공재" 층)은
  공유 인스턴스 하나로 유지, 대화·질문·워치리스트 등 개인화가 새는 지점만 `user_id` 스코프.
  수집 파이프라인은 1회만 돌려 비용 공유, 판단 계층만 사람별로 격리.
  cf. 진화계획 2단계(product-v3.md, "질문의 cron화")는 반복 질문을 브리핑에 편입하는데,
  다중 사용자 환경에선 이게 user_id 스코프 없이 전역으로 새면 한 사람의 관심사가 남의
  피드에 노출되는 문제와 직결 — 배포 결정 전에 이 설계를 먼저 확정해야 함.
