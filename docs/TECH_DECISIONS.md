# 기술 의사결정

무엇을 만들었는지는 [SYSTEM.md](SYSTEM.md)에, 시간순 원장은 [DECISIONS.md](DECISIONS.md)에 있습니다.
이 문서는 그 결정들을 **어디서 나왔는지**로 묶었습니다. 원칙에서 나온 것, 비용에서 나온 것,
제약에서 나온 것, 성능에서 나온 것.

각 항목은 대체로 **선택 / 왜 / 감수하기로 한 것 / 고려했지만 선택하지 않은 것** 순으로 적었습니다.
고장에서 배운 결정은 **증상 / 원인 / 선택** 순입니다.
'감수하기로 한 것'을 매번 적는 이유는, 무엇을 포기했는지 안 적힌 결정은 나중에 재검토가
안 되기 때문입니다.

**차례**

- [출발점](#starting-point) — 무엇을 만들려 했고, 무엇을 처음부터 배제했나

- [로컬 1인이라는 제약에서 나온 결정](#from-local-constraints) — 단일 SQLite · 하이브리드 검색 · launchd · 프로세스 락
- [성능에서 나온 결정](#from-performance) — 읽기 경로 · 상태 파생 · 캐시 무효화 단위

<a id="starting-point"></a>
## 출발점

목표는 혼자서도 리서치센터를 갖는 것이었습니다. 읽고 모으고 연결하는 노동은 기계에게 넘기고,
판단은 사람이 하는 구조입니다.

직접 써보면서 확인한 패턴 하나가 범위를 결정했습니다.

> 기계가 **읽고·모으고·연결**하는 것 — 잘 됐습니다.
> 기계가 **종합 판단**하는 것 — 아직 이릅니다.

그래서 이 도구는 결론을 생산하지 않습니다. 판단의 재료를 모아 잇고, 그 재료의 출처와 확신 수준을
함께 기록합니다. 한 문장으로 줄이면 *"믿는 자동 오라클이 아니라, 출처 달린 가설을 추적하는
인과 세계모델"* 입니다([PHILOSOPHY.md](PHILOSOPHY.md)).

**하지 않기로 한 다섯 가지.** 자동매매, 가격 예측, 전종목 실시간, 근거 없는 AI 답변, SaaS화.
처음부터 배제해둔 덕분에 이후 결정의 선택지가 크게 줄었습니다.

**지표는 정확도가 아닙니다.** 북극성은 주간 열람일수(5일 만점)이고, 당면 지표는
"홈이 조용한 날" 비율을 10% 아래로 두는 것입니다. 답변 품질을 지표로 삼지 않은 건
문서가 충분히 쌓이기 전에는 측정이 무의미해서입니다.

**해자는 코드가 아니라 축적입니다.** 개인 소스 조합, 키워드, 가설 그래프, 시계열 아카이브가
쌓일수록 나중에만 가능한 분석이 열립니다. 이 판단이 "지금 SaaS화하지 않는다"로 이어졌습니다.

전제 조건은 세 줄입니다 — **1인 사용, 로컬 실행, 월 운영비 0원.**
아래 결정 대부분은 이 세 줄을 넣고 보면 설명됩니다.

<a id="from-epistemology"></a>
## 인식론에서 나온 결정

시장은 물리가 아닙니다. 그래서 정답을 뱉는 기계가 아니라 가설을 추적하는 기계를 만들었습니다.
[PHILOSOPHY.md](PHILOSOPHY.md)의 직접적인 구현입니다.

<a id="epistemic-type"></a>
### epistemic_type을 1급 컬럼으로

**선택.** 모든 엣지와 산출물이 `fact` / `observed` / `hypothesis` 중 하나를 갖습니다.
LLM이 만든 건 전부 `hypothesis`이고 `confidence`와 `source_doc_id`가 필수입니다.
`observed`는 널리 수용된 역사 해석으로, 시장 가설보다는 강하고 순수 사실보다는 약한 중간 티어입니다.

**왜.** 사실과 가설을 한 테이블에 같은 모양으로 넣으면 월드모델이 "그럴듯한 쓰레기"가 됩니다.
반 년 뒤에 어느 쪽이 관측이고 어느 쪽이 추측이었는지 알 수 없게 됩니다.

**감수하기로 한 것.** 스키마가 복잡해집니다. 모든 쓰기 경로가 이 컬럼을 채워야 하고,
모든 읽기 경로가 이걸 구분해서 렌더해야 합니다.

<a id="four-axes"></a>
### 인과 주장 하나를 네 축으로 쪼개기

**선택.** `confidence`(참이라는 확신), `effect_direction`(정/부), `effect_strength`(크기, 범주형 3단계),
`obs_confirmed_at`(실측 확인 여부)을 각각 독립 컬럼으로 뒀습니다.

**왜.** 단일 confidence로는 "약하지만 확실"과 "강하지만 불확실"을 구분하지 못합니다.
그 값을 곱해 만든 경로 점수는 causal impact가 아니라 epistemic reliability 랭킹인데,
둘을 섞으면 *가장 믿을 만한 경로*가 *가장 중요한 경로*로 오독됩니다.

**감수하기로 한 것.** 단일 점수의 편리함을 잃었습니다. 정렬도 필터도 시각화도 전부 다축을 다뤄야 합니다.

**고려했지만 선택하지 않은 것.** `effect_strength`를 0~1 float으로 두는 안입니다.
거짓 정밀이라 버렸습니다. LLM이 0.73과 0.68을 구분해 판정할 근거가 없어서 3단계 범주형으로 고정했습니다.

<a id="salience-conviction"></a>
### 주목과 확신을 직교 축으로

**선택.** 지식을 `salience`(시장 주목, 최근 언급량) × `conviction`(근거 강도 — 독립 관측·소스 다양성·반박 감점)
2축 4상한에 놓습니다. 하나의 "지식 점수"로 합치지 않습니다.

**왜.** 반복되는 뉴스는 *세상이 주목한다*는 신호이고, 영향력 있는 사람의 단발 통찰은
*진리에 가깝다*는 신호입니다. 둘은 다른 축입니다. 합쳐버리면 '붐비는 합의'와 '소외된 엣지'를
구분할 수 없습니다. 그리고 그 둘의 갭이야말로 찾으려는 것입니다.

**고려했지만 선택하지 않은 것.** 승격 기준을 더 정교한 단일 점수로 만드는 안입니다.
두 축을 뭉개면 정보가 소실됩니다.

<a id="time-anchoring"></a>
### 시간은 태깅과 같은 콜에서 뽑기

**선택.** 문서를 태깅할 때 `time_orientation`(회고/현재/전망)과 `reference_period`를 함께 추출합니다.

**왜.** 발행일과 사건 발생일은 다릅니다. 이게 없으면 위에 쌓는 모든 종합이
**전망을 방금 일어난 사건으로** 착각합니다. 별도 콜로 빼지 않고 태깅에 붙인 건 추가 비용이 0이라서입니다.

<a id="facts-vs-lenses"></a>
### 사실은 그래프로, 프레임은 렌즈로

**선택.** 역사적 사실 체인(2018년 관세 부과)은 그래프 노드로 넣고, 해석 프레임(투키디데스 함정)은
별도 모듈(`lenses.py`)로 분리해 프롬프트에 주입합니다.

**왜.** 프레임을 확증된 지식으로 그래프에 넣으면 반증 규율과 충돌합니다. 정설도 하나의 관점입니다.

<a id="from-cost"></a>
## 비용에서 나온 결정

반복 실행되는 시스템에서 LLM은 무한히 비쌉니다. 30분마다 도는 체인에 opus 호출 하나를
잘못 걸면 그 비용이 영원히 반복됩니다.

<a id="subscription-auth"></a>
### 구독 인증으로 한계비용을 0에 붙이기

**선택.** API 키 대신 Claude Code headless(`claude -p`)를 구독 인증으로 호출합니다.
`ANTHROPIC_API_KEY`가 있으면 API 모드로 자동 전환하는 경로는 코드에 있습니다.

**감수하기로 한 것.** 실행 환경의 자유도입니다. 구독 자격증명이 macOS 키체인에 있는 탓에
**스케줄러 선택까지 제약됩니다**([cron이 아니라 launchd](#launchd-not-cron)). 인증 방식이 인프라를 강제한 사례입니다.

<a id="model-tiers"></a>
### 티어는 용도로 고정

| 용도 | 모델 | 근거 |
|---|---|---|
| 태깅·분류·판정 요약 | haiku | 기계적 작업, 문서당 1회 |
| RAG 질의응답 | sonnet | 사용자가 기다리는 중이라 지연에 민감 |
| 브리핑·렌즈·교차 종합 | sonnet | 품질은 필요하지만 하루 몇 회뿐 |
| 내러티브·시나리오·리포트 | opus | 심층 종합. 배치나 버튼으로만 |
| 임베딩 | 로컬 fastembed | API 불필요, 이 규모에선 품질도 충분 |

지연이 중요하면 sonnet, 품질이 중요하고 빈도가 낮으면 opus, 빈도가 높으면 무조건 haiku입니다.
세 축이 충돌할 때는 **빈도가 이깁니다.**

<a id="hash-gates"></a>
### 모든 종합에 해시 게이트

**선택.** 재생성 가드를 캐시마다 걸었습니다. `content_hash`, `doc_ids_hash`, `inputs_hash`,
`members_hash`, `principles_hash`, 그리고 **프롬프트 자체의 서명**까지.

마지막 건 실패에서 배웠습니다(D-114). 재생성 조건을 날짜로만 해싱하면 프롬프트 템플릿을 고쳐도
캐시에 걸려 옛날 산출물이 나옵니다.

**감수하기로 한 것.** 신선도입니다. 입력이 안 바뀌면 결과도 안 바뀌니, 모델이 좋아져도
자동으로 반영되지 않습니다. 수동 refresh 경로를 따로 뒀습니다.

<a id="measured-changes"></a>
### 측정하고 나서 옮긴 것들

추정이 아니라 실측으로 뒤집힌 결정들입니다. 이 절이 문서에서 가장 실용적인 부분입니다.

| 발견한 것 | 조치 |
|---|---|
| 새 문서 **1건**만 들어와도 `doc_ids_hash`가 바뀌어 내러티브 opus가 재발화. 7일간 52회, 누적 **16.1시간**으로 측정된 LLM 시간 1위 | 전량 배치를 주 1회로 분리하고 체인엔 이벤트 트리거만 남김(쿨다운 3일) — D-122 |
| 진행 중인 구간을 대상으로 다이제스트를 계산해 같은 요약을 반복 생성(같은 종목이 7일간 7회) | **닫힌 구간만** 계산. 문서 집합이 고정이라 첫 생성 뒤로는 LLM 0콜 — D-124 |
| 구독 채널 신규 영상을 전부 opus로 정리 — 아무도 안 읽는 것까지 | 문서를 열 때만 정리 — D-115 |
| 기계적 호출의 output 토큰 과다 | `--effort low` 적용해서 **89% 절감** — D-117 |
| "실패하면 재시도" 규칙이 사용량 소진 상황에서 **611콜** 소모 | 연속 실패 차단기. 임계를 넘으면 그 회차를 포기 — D-119 |

여기서 얻은 규칙은 하나입니다. **반복 실행되는 경로의 비용은 추정하지 말고 측정한다.**

<a id="code-judges-llm-narrates"></a>
### 판정은 코드가, 서술만 LLM이

**선택.** 시장 국면 포스처, 거래대금 쏠림, 진자 판정, 내러티브 랭킹, 버전 드리프트 diff,
4상한 분류는 전부 LLM을 쓰지 않습니다.

**왜.** 판정을 코드가 하면 재현 가능하고, 감사할 수 있고, 공짜입니다. 같은 입력에 같은 답이 나옵니다.
LLM은 서술이 필요한 곳에만 씁니다.

<a id="approval-gate"></a>
### 비싼 노동은 사람의 승인 뒤로

**선택.** 감지는 값싸게(LLM 0), 실행은 승인 뒤에 합니다. 어휘 병합, 지식 승격, 리서치 후보,
모순 판정이 전부 승인 큐를 거치고 **자동 적용 경로는 아예 없습니다.**

리서치 후보 감지를 예로 들면 전부 공짜 SQL입니다(RS 백분위 ∩ 시총 ∩ 화두 공동언급).
승인한 것만 심층 리서치를 태웁니다. 원안이었던 "전 종목 4분면을 매일 opus로" 대비
호출이 **10배가량** 줄었습니다.

다만 이건 비용 최적화이기 이전에 역할 분담입니다. 자율을 좁게 정의했습니다 — 자동 실행이 아니라 자동 제안.

<a id="from-local-constraints"></a>
## 로컬 1인이라는 제약에서 나온 결정

<a id="single-sqlite"></a>
### 단일 SQLite

**선택.** SQLite 파일 하나입니다(WAL 모드, `busy_timeout=30s`). 400MB대에 85개 테이블,
주가 시계열 수십만 행이 들어 있습니다.

**왜.** 운영 비용이 0이고 백업이 `cp` 한 번입니다. 사용자가 한 명이라 읽기 부하가 낮고,
무거운 종합은 전부 미리 계산돼 캐시에 있습니다. 확장 두 개만 붙이면 검색까지 안에서 해결됩니다.

**감수하기로 한 것.** 동시 쓰기입니다. 실제로 수집 체인 쓰기와 API 읽기가 충돌해 락 오류가 났고
WAL + `busy_timeout 30s`로 해결했습니다. 남은 위험인 체인끼리의 겹침은 DB가 아니라
프로세스 레벨에서 막습니다.

**고려했지만 선택하지 않은 것.**

| | 이유 |
|---|---|
| 즉시 Postgres | 지금 단계에선 운영 복잡도만 늘어납니다 |
| 전용 벡터 DB | 이 규모에서는 `sqlite-vec`로 충분합니다 |
| Elasticsearch | FTS5의 BM25로 한국어 종목명 매칭이 이미 잘 됩니다 |

**뒤집어야 할 조건.** ① 사용자가 둘 이상이 되거나 ② 수집 체인이 상시로 30분을 넘기거나
③ 24/7 가용성이 필요해질 때입니다. 셋 다 아직 아닙니다.
Postgres 리프트&시프트 설계는 논의만 끝내고 보류했습니다.

<a id="hybrid-search"></a>
### 검색은 인프라 없이 하이브리드로

**선택.** FTS5(BM25)와 sqlite-vec를 **RRF**(Reciprocal Rank Fusion)로 융합했습니다.
임베딩은 `fastembed`로 로컬에서 돌립니다.

**왜.** 한국어 종목명과 별칭은 키워드 매칭이 강하고("SK하이닉스"), 문맥 질의는 벡터가 강합니다
("메모리 업황이 꺾이는 신호"). 단독으로는 어느 쪽도 recall이 부족합니다.

RRF를 고른 건 **두 랭킹의 점수 스케일을 정규화할 필요가 없어서**입니다.
BM25 점수와 코사인 유사도를 억지로 같은 축에 올리는 대신 순위만 씁니다.

**감수하기로 한 것.** 튜닝 여지입니다. 가중치를 세밀하게 조정할 수 없습니다.
대신 파라미터가 거의 없어서 잘 안 깨집니다.

<a id="launchd-not-cron"></a>
### cron이 아니라 launchd

**증상.** LLM 작업이 전부 `Not logged in`으로 죽었고, 랩탑이 자는 동안의 스케줄은 그냥 증발했습니다.

**원인.** 두 고장이 한 뿌리였습니다. cron은 GUI 세션 밖에서 돌기 때문에
**키체인에 접근하지 못하고**, **놓친 스케줄을 기상 후 재실행하지도 않습니다.**

**선택.** launchd user agent로 옮겼습니다. Aqua 세션이라 키체인이 열리고, 기상 시 놓친 회차를
실행합니다. 두 고장이 한 번에 해소됐습니다(D-106).

**감수하기로 한 것.** 이식성입니다. 이 스케줄링은 macOS 전용이라 서버로 옮기면 다시 설계해야 합니다.

<a id="process-lock"></a>
### 겹침은 프로세스 락으로

**선택.** `run_chain.sh`에서 **mkdir 원자성 + PID 생존 확인**으로 락을 구현했습니다.
`flock`이 macOS 기본에 없어서입니다. 이전 실행이 살아 있으면 이번 회차를 건너뛰고,
stale 락은 자동으로 회수합니다.

여기서도 실측으로 배운 게 있습니다. 2차 가드를 `pgrep -f 'scripts/ingest.py'`로 짰더니
그 문자열이 들어간 아무 명령(grep, 편집기, 진단 스크립트)에나 걸려서
**수집 회차를 조용히 건너뛰고 있었습니다.** 인터프리터 경로로 시작하는 줄만 매칭하도록 고쳤습니다.

조용한 skip은 조용한 실패입니다. 지금은 건너뛸 때마다 이유를 로그에 남깁니다(D-024 · D-116).

체인 순서에도 규칙이 있습니다. 값싼 운영 점검 두 개(LLM 엔진 생사 확인, 브리핑 캐치업)를
**수집보다 먼저, `&&` 사슬 밖에** 뒀습니다. 수집이 실패해도 "LLM이 죽었다"는 사실은 알려야 하니까요.

<a id="from-performance"></a>
## 성능에서 나온 결정

<a id="no-fetch-on-read"></a>
### 읽기 경로에 외부 fetch를 두지 않기

**증상.** 홈 첫 로딩이 100초 걸리는 걸 목격했습니다. 지수 API가 캐시 만료 시
yfinance 응답을 기다리고 있었습니다.

**선택.** GET은 외부 fetch를 절대 기다리지 않습니다. TTL이 만료돼도 갱신은 `BackgroundTasks`로
넘기고 저장분을 즉시 반환합니다(측정 4ms). 스탬피드는 TTL 선점으로 막고, 전부 실패하면
캐시를 무효화해서 다음 요청이 재시도하게 합니다.

같은 패턴을 20분 걸리는 컨콜 수집에도 적용했습니다. 백그라운드로 넘기고 2.5ms에 반환한 뒤
상태를 폴링합니다. 중복 클릭은 409로 막습니다. 무료 API 하루 25건을 이중으로 소모하면 안 되니까요.

**감수하기로 한 것.** 최신성입니다. 사용자는 최대 TTL만큼 오래된 값을 볼 수 있습니다.
대신 수집 시각을 화면에 항상 띄워서 그 사실을 숨기지 않습니다.

<a id="state-from-data"></a>
### 상태는 프로세스가 아니라 데이터에서 파생

**선택.** 어떤 지수가 "지연됨"인지를 워커 상태로 판단하지 않고,
*수집 시각이 다른 지수보다 1시간 이상 오래됐는가*로 판정합니다.

**왜.** 프로세스 상태에 의존하면 프로세스가 죽었을 때 그 사실조차 알 수 없습니다.
데이터에서 파생하면 무엇이 죽든 화면에 드러납니다.

<a id="semantic-invalidation"></a>
### 캐시 무효화 단위를 시간이 아니라 의미로

지수 갱신 주기는 개장 중 10분, 휴장 60분입니다. 그리고 기준이 데이터 날짜가 아니라
**fetch 시각**입니다. 데이터 날짜로 잡으면 주말과 휴장일에 계속 재요청하게 됩니다.

<a id="deferred"></a>
## 미뤄둔 결정

<a id="two-worlds"></a>
### 두 세계를 공존시키기

저장소에는 사실 데이터 모델이 두 개 있습니다.

- **도메인 원본(옛 세계)** — `companies`, `financial_statements`, `stock_prices`, `disclosures`.
  초기 대시보드 시절의 관계형 테이블이고, 종목 디테일과 스크리너가 여전히 씁니다.
- **그래프 척추(새 세계)** — `entities`, `entity_relations`, `raw_documents`, `enrichments`.

**선택.** 한꺼번에 갈아엎지 않고 척추가 원본을 **읽기 참조**하게 했습니다.

**왜.** 마이그레이션은 완료될 때까지 아무 가치도 만들지 않습니다. 1인 프로젝트에서
몇 주짜리 전면 이관은 그동안 도구를 못 쓰게 만듭니다.

**감수하기로 한 것.** 어휘가 두 벌이 됩니다. KSIC 기반 `companies.sector`와 키워드 기반
`entities(type='sector')`가 따로 있고 `sector_map`이 접착제 노릇을 합니다. 인지하고 있는 부채입니다.

<a id="no-deploy"></a>
### 배포하지 않기

AWS 이전(EC2 + SQLite 리프트&시프트)은 설계 논의만 끝내고 보류했습니다.
지금 옮기면 여기저기 흩어진 로컬 전제 — 키체인 인증, 파일 락, vault 경로, 미디어 로컬 보관 — 을
동시에 정리해야 합니다. 그 비용을 낼 시점은 멀티유저 트리거가 당겨질 때입니다.

<a id="open-problems"></a>
## 지금 열려 있는 문제

설계한 대로 전부 돌고 있지는 않습니다.

<a id="unclosed-loop"></a>
### 환류 고리의 마지막 마디가 닫히지 않았습니다

구조는 이렇게 설계했습니다. 종합이 인과를 주장하고 → 문서 추출이 독립적으로 대조하고 →
반복 확인되면 지식으로 승격되고 → 승격된 지식이 다음 종합의 전제로 주입되고 →
**실데이터 관측이 그 인과를 확증한다.**

앞의 네 마디는 돌고 있습니다. 교차검증 증거가 수천 건 쌓였고 승격된 엣지도 나왔습니다.
그런데 다섯 번째가 **0건**입니다.

원인은 코드 버그가 아니라 조건의 교집합이 비어 있는 것입니다.
확증이 발화하려면 `확정 판정 도달 + 내러티브에 묶여 있음` 두 가지가 동시에 필요한데,
관측이 쌓인 질문은 사람이 주입한 것이라 내러티브에 안 묶여 있고, 내러티브에 묶인 질문은
관측이 없습니다.

그 위에 재료 기아가 겹칩니다. 확정 층을 먹이는 수치 관측이 미국 컨콜 한 곳에서만 나오는데
그 컨콜이 무료 API 하루 25건에 묶여 있습니다.
**무료 데이터 소스의 한도가 시스템의 검증 능력 상한을 그대로 결정하고 있는 셈입니다.**
코드로 풀 문제가 아니라 데이터 소스 결정입니다.

<a id="other-open"></a>
### 그 밖에

- 시나리오 엔진이 "제3의 인과 공급원"으로 문서화돼 있는데 실제 적재분이 0건입니다.
  교차검증은 독립 공급원의 수가 곧 신뢰도라, 하나가 빠지면 승격이 실제보다 보수적으로 나옵니다.
- `models`(살아있는 모델) 테이블은 스키마만 있습니다.
- 어휘 병합이 표기 변형(현대자동차↔현대차)만 잡습니다.
  의미 변형(엔비디아↔NVIDIA)은 임베딩 코사인 0.32로 후보에도 못 듭니다.
