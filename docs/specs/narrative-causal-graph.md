## 0. 왜 지금 — 현재 상태의 병목

- `entity_relations`에는 **`MEMBER_OF`(기업→섹터) 3,233개뿐**, 인과 엣지가 하나도 없다.
- 내러티브 7개는 **마크다운 한 덩어리**(source_digests kind='narrative')로 저장된다.
- 즉 opus가 매번 뽑는 "인과 구조 A→B→C, 수혜/피해 주체"가 **프로즈 텍스트 안에만 갇혀 있어** 질의·연결·추적·재사용이 불가능하다. 매 생성마다 인과를 처음부터 다시 추론하고, 끝나면 버린다.

이 문서의 모든 아이디어를 관통하는 단 하나의 병목이자 기회: **인과관계를 프로즈에서 꺼내 그래프로 물질화**하는 것.

## 1. 관통 프레임 — "하나의 인과 그래프, 두 개의 속도"

분류·머지·교차검증·인과 양 끝·지식 연동 — 전부 한 가지를 요구한다:

- 내러티브 생성 시 opus가 뽑는 인과 고리를 `entity_relations`에 **`CAUSES` / `BENEFITS_FROM` 엣지**로 적재 (epistemic_type=hypothesis, confidence, source_doc_id — D-005 규약 그대로 확장).
- 그러면 내러티브는 "md 문서"가 아니라 **인과 그래프 위의 한 뷰(subgraph)**가 된다.
- **내러티브(빠른 층)와 지식(느린 층)은 같은 인과 그래프의 두 속도**다 — CLS(해마/신피질) 설계 그대로.

## 2. 인과는 시간에 종속된다 — 시간-인과 축 (2026-07-17 추가 통찰)

**핵심 통찰(stakeholder)**: 인과관계는 필연적으로 시간 개념에 종속된다. 원인은 결과에 선행한다. 따라서 인과 엣지는 시간 스탬프 없이는 반쪽이다.

- 이미 있는 토대(D-021): 문서마다 **`time_orientation`(past/current/forward/mixed)**과 **`reference_period`(수집일이 아닌 '정보가 가리키는 실제 시점')**를 enrich가 추출한다. "수집된 시간 ≠ 사건 발생 시간"의 분리가 이미 되어 있다.
- **아직 반영 안 됨**: 이 시간 메타가 (존재하지 않는) 인과 엣지엔 붙어있지 않다. 인과 층에선 새 적용이다.

### 설계 반영

1. **각 인과 엣지에 시간 스탬프**: `time_orientation` + `reference_period`를 엣지 속성으로. 원천 문서에서 상속하거나, opus가 인과 구조 생성 시 엣지별로 부여(reference-time은 LLM 지능 필요 — 불가피, 하지만 D-021 파이프라인 재사용).
2. **시간 그래디언트 = 체인의 읽기 순서**: 인과 체인은 자연히 **과거 뿌리 → 현재 → 전망 효과**의 시간 기울기를 갖는다.
   - 앞의 끝(근본 원인)은 대개 **past/structural** (이미 실현·고착).
   - 뒤의 끝(수혜)은 대개 **forward/hypothesis** (아직 안 온 미래) — 그래서 가설 영역이고, 그래서 **바로 거기에 엣지(기회)가 있다**.
3. **배열 vs 그래프의 화해** (stakeholder 질문): 둘 중 하나가 아니다.
   - **캐노니컬 저장 = 그래프**(시간 스탬프 붙은 방향 엣지) — 순회·머지·교차검증에 필요.
   - **내러티브가 '걸어간 경로' = 그 엣지들의 시간순 정렬 배열** — 이게 배열 형태가 자연히 담는 "이 노드가 전후 어디로 이어지는가". 배열은 그래프에서 시간 정렬로 재구성 가능한 *뷰*이자, 내러티브의 1급 산물(walked path).
   - 즉 **그래프는 모든 경로를 누적, 배열은 한 내러티브의 시간순 독법**. "머지 = 공유 서브그래프"가 이래서 성립.
4. **시간 정합성 검증 (공짜로 얻는 방어)**: 주장된 원인의 reference_period가 결과보다 **뒤**면(효과가 원인보다 앞섬) 유사인과 적신호. 수집일이 아니라 **참조 시점**으로 재는 게 D-021의 핵심 — 인과에 그대로 적용.
5. **salience×conviction과의 연결**: forward + 미검증(low corroboration) 하류 노드 = 가설 = **투자 프론티어**. 시간 방향이 곧 "이미 반영됐나(past·priced) vs 아직 안 왔나(forward·edge)"의 판별자.

**주의(반영 시 결정)**: 시장은 반사적(reflexive)이다 — 가격→내러티브→가격. 순수 DAG 가정이 깨질 수 있다(피드백 루프). 사이클 허용 여부 or 시간 버전으로 접기 — 착수 시 결정.

## 3. 능력별 설계

### 3-1. 카테고리 + 트래킹 (1차)
- **카테고리**: ⓐ 당장 — **도메인 렌즈**(매크로·지정학·산업·수급·기술·정책, 지식 A-7 live vocab). 교차 도메인 내러티브는 가중(lollapalooza). ⓑ 더 강함 — **공유 루트 원인별 emergent 클러스터**(미리 정하지 않고 근본 원인 수렴으로 자동 묶임).
- **트래킹**: 현재는 재생성 시 덮어씀(역사 소실). **내러티브를 버전 보존 1급 객체(`narratives` 테이블)로 승격** → "2주 전엔 '유가'가 핵심 고리였는데 지금은 '금리'로 이동" 같은 **내러티브 드리프트** 관측. ← 최대 아키텍처 결정.

### 3-2. 머지 / 교차검증
- **머지**: 두 내러티브가 인과 노드를 공유하면 이미 한 그래프의 두 경로 → 상위 "세계관 내러티브" = 공유 서브그래프. (지식의 공고화 claims→knowledge를 내러티브 층에 적용.)
- **교차검증**: 다른 출처가 같은 인과 고리를 주장 → 그 엣지 confidence 비선형↑ (A-3 독립성). 상충 → `contested` (ACH를 인과 엣지에).

### 3-3. 인과 체인의 양 끝
- **앞의 끝(근본 원인)**: `CAUSES` 상류 순회, **정지 규칙 = pace_layer가 regime/structure인 노드**. "유가↑ ← 호르무즈 ← 미-이란 재편(regime)"에서 regime이 루트. 무한 후퇴("인간의 탐욕") 방지 — 루트 = 가장 깊은 관측가능·구조적 노드.
- **뒤의 끝(수혜) — 권고 정책**: **단일 종목 강제 금지** (거짓 정밀 = 이 시스템이 피하려는 것). 대신 ⓐ 근거가 지지하는 가장 구체적 노드까지만 하강(섹터 or 종목), ⓑ 하류는 hypothesis 태깅, ⓒ 종착 = **수혜 후보 랭킹 + 각 conviction + 이 논지를 깨는 반증 조건**. `value_chains`(94개 기존)·MEMBER_OF로 섹터→종목 해석. Marks 2차적 사고(§G.2 "너머 보기").

### 3-4. 메르식 형식
- 본질 = 체인을 앞→뒤로 걸으며 점을 잇고 끝은 항상 투자 함의. 그래프 백본이 깔리면 프롬프트가 **실제 순회 경로를 서사로 풀어쓰는** 형태로 진화. 근거가 그래프라 "왜 이 결론인지" 1클릭 역추적 — 메르가 수동으로 하던 걸 시스템이.

### 3-5. 내러티브 ↔ 지식 루프 (살아있는 월드모델)
가능할 뿐 아니라 CLS 설계가 이미 그 모양 — 같은 인과 그래프의 빠른/느린 층:
- **내러티브 → 지식**: 여러 내러티브·문서에서 독립 반복된 인과 주장이 knowledge로 승격(structure/regime 층).
- **지식 → 내러티브**: 생성 시 corroborated 지식을 검증된 전제로 주입(knowledge_block 배선 기존), 지식의 falsifier가 내러티브 반증 조건, contested 지식이 내러티브 불확실성 표시.
- **닫힌 루프**: 내러티브가 인과 제안 → 공고화가 단단한 것을 지식으로 → 지식이 다음 내러티브 지지 → falsifier 감시 → 반증 시 지식 흔들림 → 내러티브 재생성. = 진화계획 3단계(자율 에이전트).

## 4. 단계별 진행 계획

> **Phase 2는 필수(commit)** — 미룰 수 있는 옵션이 아니다 (stakeholder 명시 2026-07-17, D-023).
> Phase 1은 데이터를 쌓는 토대일 뿐, 이번 고민(인과 양 끝·세계관 내러티브·상호 지능)의 가치는 Phase 2에서 실현된다.

- **Phase 1 (토대)**: 인과 그래프 물질화 — narratives 1급 객체 + 노드 타입(macro·policy·event) + `CAUSES`/`BENEFITS_FROM` 엣지 적재(+시간 스탬프 §2) + 카테고리(도메인 렌즈) + 최소 구조 뷰. → docs/specs/narrative-causal-phase1.md
- **Phase 2 (필수)**: ① 양 끝 순회 — 루트 원인↑ / 수혜 섹터↓ ② 메르식 서사(순회 경로를 서사로) ③ 버전 드리프트 트래킹 ④ 내러티브 머지·교차검증(공유 서브그래프) ⑤ **내러티브 ↔ 지식 루프**(승격·주입 양방향). 착수 시 Phase 2 기획서 별도 작성.

## 5-0. 결정 확정 (2026-07-17 stakeholder)

1. **내러티브 = 1급 객체** — `narratives` 테이블(버전 보존·supersedes). source_digests 덮어쓰기 폐기.
2. **인과 노드 = 예약 타입 활성화** — company·sector·theme·person에 **macro·policy·event** 추가(온톨로지 D-004 reserved 채움). 파편화는 임베딩 dedup + 기존 노드 주입으로 방어.
3. **뒤의 끝 = 섹터에서 종착** — 종목 하강은 후속 기능(종목 노드·리서치 성숙 후). 앞의 끝 = regime/structure급 루트에서 정지.
4. **카테고리 = 도메인 렌즈** — 매크로·지정학·산업·수급·기술·정책(A-7 live vocab). 교차 렌즈 가중. 루트 원인 emergent 클러스터는 그래프 성숙 후.
5. **반사성 = 시간으로 푸는 DAG** — 인과 엣지에 참조 시점(§2). 피드백은 사이클이 아니라 '같은 노드의 다른 시점' 시간순 체인으로 표현. 무한루프 없음, 루트/종착 정의 명확.

## 5. (원) 착수 전 못 박을 결정 — 위 5-0에서 확정됨

1. **내러티브를 1급 객체(`narratives` 테이블)로 승격할 것인가** — 트래킹·머지·그래프 연결의 전제. (강력 추천)
2. **뒤의 끝 정책** — 단일 종목 강제 금지, 후보 랭킹+반증 (§3-3). 동의 여부.
3. **카테고리 축** — 도메인 렌즈 시작 vs 처음부터 emergent 클러스터.
4. **인과 노드의 정체** — 엔티티(company/sector/theme)만인가, **이벤트 노드**('호르무즈 봉쇄')가 필요한가. 필요 시 node 타입/이벤트 엔티티 결정 (온톨로지 D-004 reserved vocab 확장).
5. **반사성(reflexivity)** — 인과 그래프에 사이클 허용 vs 시간 버전으로 DAG 유지 (§2 주의).
