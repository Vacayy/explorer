# 텔레그램 아침 브리핑 — 읽는 브리핑에서 **누르는 브리핑**으로

> 상태: 구현 (D-107 → **v3 D-109**) · 관련: D-106(발송 신뢰성·launchd) · D-095~097(미국장 브리핑) · D-028(내러티브)

## 1. 문제

v1 브리핑은 초창기(D-056) 재료에 멈춰 있었다 — `기계의 3줄` + 오늘 일정 + 업데이트 **건수**뿐,
실측 155~322자. 그 사이 홈은 어젯밤 미국장 브리핑(D-095~097)·시장 국면(D-076)·매크로 유동성(D-101)으로
크게 자랐는데 텔레그램은 따라가지 않았다. 정작 출근길 폰에서 가장 값진 게 미국장 브리핑인데 빠져 있었다.

또한 v1은 **읽고 끝**이었다. "홈에서 확인"이라 써놓고 링크는 로컬(`localhost:5173`)이라 폰에서 열리지 않는다.
가방 속 랩탑 앞에 앉기 전까지 브리핑은 죽은 텍스트였다.

## 2. 방향

브리핑을 **작업 착수점**으로 만든다. 관심 가는 항목을 그 자리에서 눌러 생성을 걸어두면,
결과가 다시 텔레그램으로 온다. 도구 앞에 앉기 전에 판단 재료가 준비된다.

- 새 파이프라인을 만들지 않는다 — 기존 생성 로직(`compute_narrative`, 유튜브 lazy digest)을 **그대로 호출**한다.
- 브리핑 조립 자체는 **LLM 0콜**. 미국장 종합은 이미 캐시된 것(`us_briefings`)을 읽기만 한다.
- 비싼 생성은 **사람이 누른 것만** (D-020 계승 — 제안 먼저, 노동은 승인 뒤).

하단 버튼 행은 없다 — 모든 액션이 본문 인라인 링크다(v3, D-109 §5).
실측 2,604자 · 액션 링크 11개.

### 주제 top 5 = 최다 3 + 급상승 2 (사용자 확정)

절대 최다만 쓰면 매일 같은 얼굴(AI·반도체·자동차)이고, 급상승(`theme_surge`)만 쓰면
"어제 무엇이 화두였나"라는 물음에 답하지 않는다. 둘을 섞어 **판의 크기와 변화**를 함께 준다.

- **최다 3**: 어제(24h) 문서에 `entity_links(link_type IN industry|topic)`로 붙은 `theme`·`sector` 노드의
  DISTINCT 문서 수 상위 3. `signals.THEME_STOPWORDS`(산업동향·실적분석·밸류에이션·수급 등 **문서유형 메타 라벨**)를
  반드시 제외 — 제외하지 않으면 상위를 라벨이 독식한다(실측: 산업동향 127 · 실적분석 80 · 밸류에이션 53).
- **급상승 2**: 최신 `theme_surge` 신호를 `share_delta_pp` 내림차순, 최다 3과 중복 제거 후 2개.

## 4. 서식 — 마크다운 → 텔레그램 HTML (v3, D-109)

생성물(내러티브·유튜브 정리본·다이제스트)은 전부 마크다운인데 v2까지 `parse_mode` 없이
평문으로 보내 `## 핵심 요약`·`**굵게**`가 날것으로 노출됐다. `pipeline/telegram_md.py`가 변환한다.

텔레그램 HTML은 **인라인 태그만** 지원한다(`b i u s a code pre blockquote tg-spoiler`).
제목·리스트·표 태그가 없으므로 의미를 보존하는 자리로 옮긴다:

| 마크다운 | 텔레그램 |
|---|---|
| `## 제목` | `<b>제목</b>` |
| `- 항목` | `• 항목` |
| `---` | `──────────` |
| `> 인용` | `▍ 인용` |
| 표 `\| a \| b \|` | `<pre>` 고정폭 (구분행 제거) |
| `**굵게**` `*기울임*` `~~취소~~` `` `코드` `` | `<b>` `<i>` `<s>` `<code>` |

**MarkdownV2가 아니라 HTML인 이유**: MarkdownV2는 `_ * [ ] ( ) ~ > # + - = | { } . !` 를 전부
이스케이프해야 하는데 본문이 한국어 산문 + 종목코드 + URL 혼합이라 누락 한 번에 400이 난다.
HTML은 이스케이프 대상이 `& < >` 셋뿐이라 실패 표면이 훨씬 좁다.

두 가지 규율:
- **이탤릭은 `*x*` 만** — `_x_` 는 `share_delta_pp`·`source_id` 같은 식별자를 오탐한다.
- **한국어 조사 대응** — `*세 가지*다` 처럼 닫는 `*` 뒤에 조사가 붙으므로 뒤쪽 word-boundary를
  요구하지 않는다. 대신 여는 쪽에서 앞 word char를 금지해 `2*3*4` 오탐을 막는다.

**분할**: 태그 중간이나 열린 태그 안에서 자르면 텔레그램이 400을 뱉고 **메시지가 통째로 유실**된다.
`split_html()`은 문단 경계로 모으고(`<pre>`는 원자 취급), 상한 초과 블록은 강제 절단 후
열린 태그를 닫고 다음 조각에서 다시 연다. 실측: 10,327자 정리본 → 5조각, 태그 균형·텍스트 무손실.

**최후 안전망**: 그래도 400이 나면 태그를 벗겨 평문으로 1회 재발송한다. 서식을 잃더라도
내용이 유실되는 것보다 낫다.

## 5. 인터랙션 — 본문 인라인 딥링크 (v3, D-109)

v2는 하단 inline keyboard 버튼이었다. v3는 **본문 안 하이퍼링크**로 옮긴다.

**제약**: 텔레그램 인라인 텍스트 링크는 **URL만** 걸 수 있다 — 콜백을 못 쓴다. 로컬 서버라
웹앱 URL도 폰에서 안 열린다. 그래서 `https://t.me/<bot>?start=<payload>` **딥링크**로
봇에게 `/start <payload>`를 되돌려준다. 이것이 본문 인라인으로 봇 액션을 거는 유일한 정식 수단이다.

| 본문 링크 | URL | 동작 |
|---|---|---|
| 주제명 (`AI`) | `t.me/<bot>?start=n_{entity_id}` | `compute_narrative(name)` — 멱등(문서집합 불변이면 캐시) |
| 영상 제목 | 유튜브 원문 URL | 외부 링크 (액션 아님) |
| `▸ 정리본 생성` | `t.me/<bot>?start=y_{doc_id}` | `spine_doc.get_document` — digest 미완성이면 그 자리에서 opus 재시도 |

payload는 `A-Za-z0-9_-` 64자 제한이라 `n:4740`이 아니라 **`n_4740`**을 쓴다.
봇 핸들은 `TELEGRAM_BOT_USERNAME` 우선, 없으면 `getMe` 1회 조회 후 캐시 —
못 구하면 링크 없이 라벨만 나가고(평문 열화) 발송 자체는 막지 않는다.

**디스패처는 하나**: 딥링크(`/start n_4740`)와 구 inline 버튼 콜백(`n:4740`)이 모두
`start_action(kind, id, chat_id)`로 모인다. 구 콜백을 남긴 이유는 v2로 이미 발송된 메시지의
버튼이 계속 동작해야 하기 때문.

### 응답 규약

생성은 opus라 수십 초~수 분이다:
1. 즉시 `"🔎 … 생성 중… 1~2분 걸립니다"` 반환 (콜백 경로는 `answerCallbackQuery`도 함께)
2. **데몬 스레드**에서 생성 → 완료 시 결과 메시지 (폴링 루프를 막지 않는다)
3. `_inflight`(chat×kind×id) 잠금 — 연타로 opus가 중복 기동되지 않게

폴링 루프의 "🔎 찾아보는 중…" 선응답은 `/`로 시작하는 입력에는 보내지 않는다 —
핸들러가 자체 선응답을 주므로 중복이 된다.

### 알고 수용한 제약

- 버튼→링크 전환으로 **탭이 1회 늘 수 있다**. 텔레그램이 딥링크를 열 때 하단에 START 버튼을
  띄우는 것이 문서화된 동작이라 클라이언트에 따라 2탭이 된다. 사용자가 본문 인라인을 우선해 확정.
- 콜백/딥링크 처리는 **백엔드 서버가 떠 있을 때만**. 발송은 launchd라 서버와 무관하지만
  봇 폴링은 FastAPI startup 스레드다. 서버가 꺼져 있으면 `getUpdates` 백로그(최대 24h)에 남아
  **켜지는 즉시 처리** — 즉시성은 없어도 유실은 없다.

## 6. 5-state

브리핑은 화면이 아니지만 같은 규율을 적용한다.

| 상태 | 처리 |
|---|---|
| Empty | 모든 섹션이 비면 발송하지 않는다(`compose_briefing() → None`, `job_runs=skipped`) |
| Loading | 링크 탭 즉시 선응답("생성 중… 1~2분") |
| Partial | 섹션 단위 독립 — 미국장 종합이 없으면(캐시 미생성·LLM 미가용) 그 섹션만 스켈레톤(쏠림·이슈)으로, 유튜브 0건이면 섹션 생략 |
| Error | 생성 실패 시 사유를 그대로 회신("문서 3건 미만이라 생성 불가" 등 status별 문구). 발송 실패는 3회 재시도 후 `job_runs=error` → 체인 캐치업이 재시도(D-106) |
| Ideal | 위 §3 |

## 7. 비용

| 항목 | LLM |
|---|---|
| 브리핑 조립(주제 집계·유튜브 목록·미국장 읽기·마크다운 변환) | **0콜** — 전부 SQL + 캐시 읽기 |
| 미국장 종합 | 0콜 (홈이 이미 만든 `us_briefings` 캐시를 읽기만. 없으면 생략) |
| 주제 링크 | opus 1콜 / 누른 것만 · 문서집합 불변이면 0콜(캐시) |
| 유튜브 링크 | opus 1콜 / 누른 것만 · 이미 `digest_status='ok'`면 0콜 |

일일 고정비는 0이고, 변동비는 사람이 누른 만큼만 — 비용 의식 설계(D-072) 유지.
