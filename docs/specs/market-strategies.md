# 시장 전략 도구 카탈로그

구현일: 2026-09-19 · 계산 규약: `explorer-strategies-v1`

사용자가 제공한 HTS 이미지의 펼쳐진 항목 50개를 독립적인 계산 도구로 구현한다. 카탈로그는 시세동향 19개, 지표신호 25개, 순위종목 6개이며, 접혀 있던 `핵심검색`의 보이지 않는 항목은 범위에 포함하지 않는다. 구현과 매개변수의 단일 원본은 `backend/pipeline/market_analysis/strategies.py`의 `catalog()`이다.

이미지는 원본 HTS의 세부 산식을 제공하지 않는다. 명확하지 않은 항목은 아래의 **Explorer 정의**를 노출한다. 원본 HTS와 같은 결과를 보장하거나 지표 이름을 수익성 검증으로 취급하지 않는다.

## 호출 계약

```python
from backend.pipeline.market_analysis.strategies import (
    catalog, normalize_condition, history_requirement, evaluate_strategy,
)

condition = normalize_condition({
    "strategy_id": "golden_cross_5_20",
    "params": {"fast": 5, "slow": 20},
    "within_days": 10,
})
required = history_requirement(condition, "2026-09-18")
check = evaluate_strategy(rows, condition)
```

`rows`는 한 종목의 기준일 이하 데이터만 날짜 오름차순으로 전달한다. 일봉 필드는 `date, open, high, low, close, volume, shares`이며 실제 거래대금이 있으면 `trading_value`를 전달할 수 있다. 순수 계산 모듈은 IO, DB 연결, SQL, 네트워크 호출을 수행하지 않는다. 스냅샷 생성과 원본 DB 읽기 전용 격리는 기존 시장 분석 경로가 담당한다.

- 조건 형식: `{strategy_id, params, within_days}`. 알 수 없는 ID/필드/매개변수, NaN/Infinity, 숫자로 전달한 bool, 범위 밖 값은 `ValueError`다. 기간은 최대 250봉, 순위는 최대 500종목, 검색 구간은 최대 250거래일이다.
- 결과 공통 필드: `status: pass|fail|unavailable`, `value`, `reference`, `date`, `reason`. 지표별로 `evidence`, `estimated`, `ranking`, `top_n`을 추가한다. 미래 봉을 참조하지 않는다.
- `within_days=1`은 기준일의 완료된 봉이다. 더 큰 값은 최근 N개 거래일 중 최신 신호 하나를 반환한다. 일봉의 최근 N일은 달력일이 아닌 입력 거래일 수이며 스냅샷 어댑터가 거래일 누락을 별도로 검증한다.
- 순위 조건과 10분봉 조건은 현재 `within_days=1`만 지원한다. 10분봉은 최신 완료 봉을 검사한다.
- 일반 조건을 모두 통과한 종목 집합에서 순위 값을 내림차순으로 정렬한다. 동률은 종목코드 오름차순으로 결정하고 `top_n`개를 선택한다. 순위의 교집합 결합은 동일한 사전 필터 집합에 대해 각각 계산한다.
- 데이터 부족과 조건 불충족은 구별한다. `unavailable`을 `fail`이나 0으로 치환하지 않는다. 종목별 상장주식수는 해당 기준일 값만 사용한다.

## 공통 수학 규칙

모든 N일 이동평균은 종가의 단순이동평균(SMA)이다. 상향 교차는 `이전 값 <= 이전 기준선` 및 `현재 값 > 현재 기준선`, 하향 교차는 그 반대다. 단순히 이미 기준선 위/아래인 상태를 새 교차로 취급하지 않는다. 신고가/신저가와 최고 거래량의 비교 구간은 **현재 봉을 제외한 직전 N봉**이다. 같은 가격/거래량을 재기록하면 갱신으로 판정하지 않는다.

비율 매개변수는 퍼센트 단위다. `3`은 3%이다. 포함 경계의 부동소수점 오차에는 기계 정밀도 수준의 허용 오차를 사용한다. 0인 분모, 잘못된 OHLC, 필요한 값의 NaN/무한대, 중복·역순 날짜는 미평가다. 계산에 필요한 구간보다 오래된 가격은 결과에 영향을 주지 않는다. 날짜 정렬의 유효성은 전체 입력에 대해 확인한다.

52주는 기존 자연어 패턴 분석의 규약과 같은 365달력일 구간이며 252개 행으로 대체하지 않는다. 연중 구간은 각 이벤트 날짜가 속한 연도의 1월 1일부터다. 두 구간은 시작 경계까지 데이터가 존재함을 확인해야 한다. `history_requirement`의 여러 날 검색용 달력 경계는 보수적인 확보 범위다. 스냅샷 어댑터는 실제 거래일 목록의 최초 검사일에 대해 다시 산출해 과도한 미평가를 줄인다.

매물대는 **일봉 근사치**다. 이전 N봉의 `(고가+저가+종가)/3` 최소·최대 범위를 기본 20개의 동일 폭 구간으로 나누고 각 일의 전체 거래량을 해당 대표가격 구간에 더한다. 최대 거래량 구간의 중심을 기준선으로 고정해 전일 종가와 당일 종가를 비교한다. 동률이면 낮은 가격 구간을 택하고 모든 대표가격이 같으면 그 가격이 기준이다. `estimated=true`와 계산 방식을 증거에 남긴다. 실제 체결가별 거래량 또는 정확한 매물대 분포로 표현하지 않는다.

추세전환 확인형은 Explorer의 공개된 휴리스틱이다. 첫 상승반전 전에 SMA 기울기가 비상승이어야 하며 확인기간 마지막 봉에서만 신호를 낸다. 이미 오래 상승 중인 종목이 매일 새로운 추세전환으로 분류되지 않는다.

EMA는 `alpha = 2/(period+1)`이며 최초 `period`개 값의 SMA로 초기화한다. 재귀 지표의 시작점 의존성을 통제하기 위해 **이벤트별 고정 준비 구간**을 사용한다. MACD는 `max(250, 5*slow + signal)`, SONAR는 `max(250, 5*period + lag + signal)`봉이다. 동일 매개변수의 0선/Signal 전략은 같은 준비 구간과 지표 값을 사용한다. 검색 구간 `within_days`나 오래된 데이터가 추가되어도 이미 계산한 이벤트 값은 변하지 않는다. 이 준비기간까지 이력이 없는 신규 상장 종목은 미평가하며 무한 과거에서 초기화한 EMA와의 완전 일치를 주장하지 않는다. 결과에 `ema_seed`, `seed_start`, `seed_sessions`를 기록한다.

SONAR는 차분 방식이며 퍼센트 ROC로 바꾸지 않는다. 이미지의 `(20,9,9)`를 EMA 기간 20, 차분 간격 9, Signal EMA 기간 9로 해석한다. MACD/SONAR의 기본 돌파 방향은 상향이고 `direction=down`을 지원한다.

Stochastic 원시 %K는 `100*(종가-기간 최저가)/(기간 최고가-기간 최저가)`다. fast %D는 원시 %K의 SMA5, slow %K는 원시 %K의 SMA5, slow %D는 slow %K의 SMA5다. 전일 %K와 %D가 모두 과매도 기준 20 이하이고 당일 %K가 %D를 상향 교차해야 기본 매수 신호로 분류한다. 저가와 고가가 같아서 분모가 0이면 미평가한다. 이미지의 slow 매개변수 끝이 잘렸으므로 `(10,5,5)`를 명시적으로 채택했다.

기본 `top_n=20`이다. 각 계산기는 순위 원시 값만 산출하고 종목 간 순위는 스크리너가 부여한다. 전일 거래량이 0이면 증가율은 미평가다. 상장주식수가 없거나 0이면 회전율은 미평가하고 다른 날짜의 값을 가져오지 않는다.

현재 가격 스냅샷에는 실제 거래대금 열이 없으므로 거래대금 상위는 `available=false`, `missing_trading_value`다. `종가*거래량`은 실제 거래대금과 다르므로 대체하지 않는다. 실제 필드가 제공되면 동일한 계산기가 처리한다.

## 가격 구조 10개 (2026-09-20, D-187)

사람이 차트에 선을 그어 보는 판단을 결정적 계산으로 옮긴 조건. 카탈로그 계약(호출·within_days·unavailable 구분)은 위와 같다.

**공통 규칙**
- 피벗(스윙 점): 좌우 `pivot_width`봉의 고가(저가)보다 엄격히 높은(낮은) 고가(저가). 동률은 피벗이 아니다. 피벗은 **우측 폭이 지나야 확정**되며, 봉 i의 판정에는 `k + pivot_width ≤ i`인 피벗만 쓴다(미래 봉 참조 금지). 탐색 구간은 `lookback`봉.
- 선: 스윙 2개는 두 점을 잇고, 3개 이상은 최소제곱 직선. 판정일까지 연장한 값이 기준이다. 연장값이 0 이하면 `fail(line_out_of_range)`.
- 교차: 전일 종가 ≤ 전일 선값, 당일 종가 > 당일 선값(하향은 반대). 기계 정밀도 안의 동률은 접촉으로 보고 돌파로 치지 않는다.
- 스윙이 부족하면 `fail(insufficient_pivots)`, 스윙이 한 방향으로 정렬되지 않으면 `fail(no_trend_pivots)`. 자료 자체가 모자랄 때만 `unavailable`.
- evidence: `pivots`(날짜·가격), `line`/`channel`(선 양 끝점), 수준·돌파일·되돌림일. 후보 차트는 이 값으로 스윙 점 마커와 점선을 그린다.

| ID | 표시명 | 기본 계산 (기본값 피벗 폭 5 · 탐색 120봉) |
| --- | --- | --- |
| `higher_lows` | 저점 높이기 | 최근 확정 스윙 저점 3개가 연속 상승 |
| `lower_highs` | 고점 낮추기 | 최근 확정 스윙 고점 3개가 연속 하락 |
| `resistance_break` | 전고점 돌파 | 직전 확정 스윙 고점 × (1+여유율 0%)을 종가가 상향 교차 |
| `support_break` | 전저점 이탈 | 직전 확정 스윙 저점 × (1−여유율)을 종가가 하향 교차 |
| `breakout_retest_rebreak` | 돌파 후 지지·재돌파 | 탐색 구간 안 가장 최근 전고점 돌파(j) 이후 되돌림 최저가가 수준 × (1+2%) 이하로 접촉, 그 사이 종가는 수준 × (1−2%) 이상 유지, 당일 종가가 되돌림 구간 최고가를 상회 |
| `trendline_break_up` | 하락 추세선 상향 돌파 | 연속 하락하는 스윙 고점 2개를 이은 선을 종가가 상향 교차 |
| `trendline_break_down` | 상승 추세선 하향 이탈 | 연속 상승하는 스윙 저점 2개를 이은 선을 종가가 하향 교차 |
| `trendline_support_hold` | 상승 추세선 지지 반등 | 당일 저가가 상승 추세선 ±1.5% 안에 닿고 종가는 선 위 |
| `channel_break_up` | 채널 상단 돌파 | `swing`: 스윙 저점 선에 평행하게, 구간 내 스윙 고점의 최대 이격을 지나는 상단선 / `regression`: 종가 회귀선(60봉) + 2σ. 종가 상향 교차 |
| `channel_break_down` | 채널 하단 이탈 | `swing`: 스윙 저점 기준선 / `regression`: 회귀선 − 2σ. 종가 하향 교차 |

실측(2026-09-20, 최근 400봉): HPSP는 `lower_highs` 통과(스윙 고점 하락), 삼성전자는 전부 fail. 종목당 10개 조건 평가 3ms.

## 검색 전략 저장·추천: 후속 설계

2026-09-19 사용자 방향(D-180), **D-181에서 저장·버전·재실행과 목적별/관측 신호별 추천을 구현했다**. 이 절의 전략은 종목 발견을 위한 재사용 가능한 검색 정의다. 카탈로그의 개별 계산 도구, 날짜별 실행 결과, 매매 규칙을 포함한 백테스트 명세와 구분한다.

- 저장 항목: 이름·조사 목적·사용자 표현, 정규화 조건과 매개변수, 도구/조건식 버전, 대상 시장·관심 집합, 최신/고정 기준일 정책, 필요한 데이터·최소 이력, 원 실행·검증 상태, 사용자 메모.
- 검색 정의는 버전으로 남긴다. 재실행은 해당 버전과 실제 데이터 기준일을 새 결과에 기록한다. 이전 결과 열람은 계산이나 수집을 시작하지 않는다.
- 생성 코드 사본은 실행 근거로 보존한다. “전략 저장”이 활성 Python 파일·검증 스킬·원본 DB를 수정하거나 재검증 없이 코드를 신뢰하는 동작이 되지 않게 한다.
- 추천 유형: **목적에 맞는 검색**(예: 돌파 후 눌림 관찰), **현재 자료로 실행 가능한 검색**, **선택 종목의 관측 신호와 비슷한 종목을 찾는 검색**. 각각 추천 이유와 조건을 먼저 공개한다.
- 역방향 탐색은 사전 정의한 도구의 관측·불충족·미평가를 보여주고 해당 조합의 재사용을 제안한다. 특정 상승 종목이 통과하도록 사후 최적화한 조건을 보편적으로 유효한 전략이라고 표시하지 않는다.
- 사용자의 저장·반복 사용·리서치로 이어진 경험은 유용성의 단서다. 사용 빈도, 자료 커버리지, 전략 간 후보 중복, 계산 검증, 과거 수익성은 각각 표시하며 하나의 매수 점수로 합치지 않는다.

화면 상태: Empty는 예시와 첫 저장 안내, Loading은 불러오기/저장/실행을 구분, Partial은 일부 조건의 자료 부족·버전 비호환 표시, Error는 사용자 입력을 유지한 재시도, Ideal은 조건 설명·이전 실행·새 실행·리서치 진입을 제공한다. 추천 보기만으로 실행·저장·팔로우를 시작하지 않는다.

구현: `discovery_service.py`·`discovery_store.py`, API `/api/analysis/discovery`, 화면 `DiscoveryLibrary`. 구체적 요청·후속 조건식·지원 범위는 [시장 검색 §11](market-codeact.md#11-승인-기획-구현-계획-2026-09-19-진행)을 따른다. 현재 추천은 검증된 조건 재사용과 4개 목적별 예시이며 사용 이력에 따른 개인화와 전체 카탈로그의 종목별 역진단은 후속 확장이다.
