## 0. 한 문장

**"읽기 폭 768px 한 컬럼, 어시스턴트는 말풍선 없이 문서처럼, 근거는 본문 번호와 카드가 연결되고, 과정은 답 위에 접혀 있다."**

## 1. 문제 (as-is, D-130~134 시점의 ChatPage)

| 증상 | 원인 | 결과 |
|---|---|---|
| 답변 한 줄이 100자를 넘음 | 본문이 셸 폭(1440−240px)을 다 씀 | 장문 종합의 가독성 저하 (권장 65~75자/줄) |
| 채팅앱처럼 보임 | 사용자=primary 말풍선, AI=hypothesis 틴트 말풍선 | "도구"가 아니라 "메신저"로 읽힘. 어시스턴트 답에 표·제목이 들어가면 말풍선 안에서 답답 |
| 인용이 본문과 끊김 | `[n]`은 본문에 텍스트로만, 칩은 아래에 따로 나열 | "이 문장의 근거가 뭐지"를 번호 대조로 찾아야 함 |

| 텍스트 10~11px 다수 | 밀도 우선 | 판독성 저하, 위계 없음 |

## 2. 방향 — 레퍼런스가 수렴한 것

1. **3영역 레이아웃**: 좌측 스레드 레일(접힘 가능) · 중앙 메시지 스트림(max-w 720~768) · 하단 고정 컴포저. 우측 패널은 없음(아티팩트 없음).
2. **말풍선 폐기(어시스턴트)**: 풀폭 마크다운 본문. 사용자 메시지만 옅은 배경으로 구분. "도구" 프레이밍.
3. **컴포저**: 내용에 맞게 성장(상한 후 스크롤), 전송 버튼은 입력 안 우측 하단, Enter 전송 / Shift+Enter 줄바꿈, 힌트는 아래 한 줄.
4. **스트리밍**: 끝에 캐럿, 상태는 답 위 한 줄. 사용자가 위로 스크롤하면 자동 스크롤 해제 + "최신으로" 플로팅 버튼.
5. **근거**: 본문 인라인 번호 칩(호버=제목, 클릭=이동) ↔ 하단 소스 카드(종류·제목). 검색 기반 답이면 소스를 반드시 보인다.
6. **과정 공개**: "Thought for Ns" 패턴 — 답 **위**에 접힌 한 줄(도구 N · 근거 M · N초). 생성 중엔 같은 자리가 라이브 status.
7. **메시지 액션**: 호버 시 복사·(사용자) 다시 질문. 모바일은 상시 노출.
8. **빈 상태**: 인사 + 중앙 컴포저 + 제안 카드(이 시스템이 잘하는 질문 유형별).
9. **스레드 목록**: 날짜 그룹(오늘/어제/지난 7일/이전), 검색, 자동 제목.

- **레일**: `lg` 이상 인라인 aside(토글로 접힘, 상태는 세션 내 useState). `lg` 미만은 헤더 [≡] → shadcn **Sheet(left)** 에 같은 `ThreadRail` 렌더. 항목 = 제목(1줄 truncate) + 채널 아이콘(텔레그램만) + 상대시각. 활성 = `bg-accent`. 검색은 클라이언트 필터(제목).
- **헤더**: 슬림 1줄. 레일 토글 · **제목(클릭하면 인라인 편집, D-145)** · 채널 배지 · 메시지 수. 새 대화가 아닐 때만. 제목 편집은 `PATCH /api/spine/conversations/{id}` — Enter 저장·Esc 취소·blur 저장, 빈 제목은 400. `chat/ThreadTitle.tsx`.
- **중앙 컬럼**: `max-w-[768px]`. 스크롤 컨테이너는 메시지 영역만(컴포저 고정).
- **컴포저**: `rounded-2xl` 카드(ring), Textarea는 보더 제거 + `field-sizing-content` 성장(`max-h-48`), 전송 = `icon` 버튼(ArrowUp), 생성 중은 Spinner로 대체·비활성. 힌트 1줄 아래.

## 4. 메시지 렌더

### 사용자
우측 정렬, `max-w-[80%]`, `bg-muted rounded-2xl px-4 py-2.5`, 텍스트 `text-[15px]`. 호버 액션(아래 우측): 복사 · **다시 질문**(컴포저에 원문 프리필).

### 어시스턴트 (풀폭, 말풍선 없음)
1. **메타 행**: hypothesis 색 점(●) + "AI 종합" + 모델 + 상대시각. → LLM 산출=hypothesis 마커 규칙(DESIGN_SYSTEM §2)을 **틴트가 아닌 라벨**로 충족. D-018의 "AI 말풍선 틴트" 적용은 이 화면에서 해제(D-135).
2. **과정 행**(route 있을 때): Collapsible 트리거 `▸ 답변 경로 · 도구 N · 근거 M · 총 N초`. 펼치면 RoutePanel(steps → process → 요약 메타 → 도구 표, D-134 그대로).
3. **본문**: shared/Markdown, `text-[15px] leading-7`. **인라인 인용 칩**: 본문 `[n]`·`[n, m]`을 전처리로 `[n](#cite-n)` 링크로 바꾸고 Markdown `components.a`에서 `#cite-` 링크만 칩으로 렌더 — `n` 표기 소형 pill, Tooltip=종류·제목, 클릭=근거 href로 이동(href 없으면 no-op). 유효 번호 밖(citations에 없음)은 텍스트 그대로.
3-1. **시세 차트 카드**(2026-09-08, TradingView 임베드 대신 lightweight-charts+우리 데이터): 근거에 `prices` 인용이 있으면 본문 아래에 자동으로 붙는다. `chat/PriceChartCard.tsx` — href `/analyze/:code/summary`에서 종목코드, 제목 "최근 N거래일"에서 기간. 종목 1=종가 라인, 2+=첫 거래일 대비 등락률(%) 비교선. 데이터는 `GET /api/stock-prices/{code}/snapshot`(stock_prices 테이블만, 답변이 읽은 것과 같은 16:10 스냅샷 → 표·본문·차트 정합). 헤더에 "16:10 스냅샷 기준"·도시에 링크. 실패·데이터 <2행이면 조용히 숨김. **기각**: TradingView 임베드 위젯 — 외부 데이터라 답변 숫자와 어긋나고, 인용·신호를 얹을 수 없고, iframe이 스레드를 무겁게 함(도시에의 '고급 차트' 토글 후보로만). **후속**: 인용 문서·신호 발생일을 차트 마커로.
4. **갭 블록**(있을 때): hypothesis 8% 틴트 박스, 항목마다 `⚠ [유형] 메모`. 갭은 이 시스템의 일급 산출(D-004)이라 작게 숨기지 않는다.
5. **근거 카드 행**: "근거 N건" 라벨 + 카드 `[n] 종류 · 제목`(Link, 종류 라벨 매핑: 문서/내러티브/인과/지식/질문/렌즈/시세/시세 추이/국면/브리핑). 기본 6개, 나머지 "+N" 토글.
6. **액션 행**(호버, 모바일 상시): 복사(본문 마크다운 원문, toast "복사됨").
7. **폰(<768) 접기**(2026-11-05, ia-redesign §4.32): 본문의 `## ` 절이 둘 이상이면 첫 절 앞(결론)만 펼치고 절은 제목 줄로 접는다(`splitSections`, 코드 블록 안 `##` 제외). '이 답에서 확인하지 못한 것 n'·'출처 n건'도 접힌 줄.
7. **드래그 인용**(D-145, 맥락 보강 D-146): 본문에서 텍스트를 선택하고 마우스를 떼면 선택 위에 `인용해서 질문` 버튼이 뜬다. 누르면 **컴포저 위에 인용 칩**으로 붙는다(입력 텍스트를 오염시키지 않는다. X로 뺄 수 있고, 인용만 있고 질문이 비면 "이 대목을 더 자세히 설명해줘"로 보낸다). 드래그 중에는 버튼을 띄우지 않는다(선택 방해). `chat/useQuoteSelection.ts`.

   **선택 문장만 보내면 안 된다** — 어느 맥락의 말인지 모른다. 네 층을 함께 싣는다.
   - **지목 문장**: 근거 칩을 걷어낸 순수 텍스트(≤500자). 칩의 DOM 텍스트는 숫자뿐이라 그냥 두면 "급증했다4."가 된다 — `[data-cite-n]` 노드를 제거하고 뽑는다.
   - **문단 맥락**: 선택 지점에서 가장 가까운 블록(`p·li·td·blockquote·h*·pre`) 전체(≤1,200자).
   - **그 대목의 근거**: 선택과 문단 안의 `data-cite-n` 번호 → 그 메시지의 citations에서 종류·제목·doc_id로 해석. **번호가 아니라 제목·doc_id로 보낸다** — 인용 번호는 턴마다 다시 매겨져 이전 [4]와 이번 [4]가 다르다.
   - **인용된 답변 전문**: `message_id`로 서버가 붙인다. 최근 대화 창은 메시지당 500자 컷인데 답변 평균이 1,002자·최대 3,041자라, 뒤쪽 문단을 지목하면 주변이 통째로 빠졌다. 전문을 싣는 대신 **`context_block(skip_ids=)`로 잘린 사본을 빼서 중복을 없앤다**(실측: 1,929자 답변이 정확히 1회만 등장).
8. **후속 질문**(D-145, **마지막 답변에만**): 종합 META의 `follow_ups` 1~3개를 카드로. 종류는 deepen(더 파고들기)·expand(넓히기)·challenge(반박·검증)·next(다음). 클릭은 **컴포저 채우기이지 전송이 아니다** — 한 턴이 100초·실비라 오클릭을 막고 문구를 다듬을 여지를 남긴다. 낡은 제안이 스레드에 쌓이지 않도록 마지막 답변에만 보인다. 제안 중 하나를 물으면 나머지는 새 답 아래 "앞 답에서 남은 질문"으로 이월된다(다음 질문이 제안 문구를 포함하면 고른 것으로 본다). 제안과 무관한 질문을 하면 이월이 끊긴다. `chat/FollowUps.tsx`.

### 생성 중 (D-130 규약: 마지막 메시지=user ⇒ 생성 중)
- 메타 행 + **과정 행 자리에 라이브 status**(Spinner + "근거 수집 중 (search_docs)…").
- 본문: SSE delta가 있으면 Markdown + 끝 캐럿(▍ 점멸). 없으면 3줄 Skeleton.
- 폴링 2.5초·SSE 가속·5분 stall 판정은 기존 로직 유지(hooks/useChat.ts로 이동).
- **정지 버튼 없음** — 백엔드에 취소 API가 없다(백로그).

### 스크롤 규칙
- 스크롤 컨테이너 하단 80px 이내 = "바닥". 바닥일 때만 새 조각·새 메시지에 자동 스크롤.
- 바닥이 아니면 우하단 플로팅 `↓ 최신으로`(rounded-full, shadow) 표시.
- 스레드 전환·내 질문 전송 직후는 무조건 바닥으로.

## 5. 5-state

| 상태 | 표시 |
|---|---|
| **Empty** (id 없음) | 중앙 인사 "무엇을 확인할까요?" + 한 줄 설명 + **컴포저를 중앙에** + 제안 카드 4장(최근 이슈 / 시세 흐름 / 내러티브·인과 / 가설 대질 — 클릭=프리필). 레일 비었으면 "아직 대화가 없습니다 — 텔레그램 봇 문답도 여기 쌓입니다" |
| **Loading** | 레일: 항목형 Skeleton 4줄. 스레드: 사용자 1 + 어시스턴트 1 형태의 Skeleton |
| **Partial** | 생성 중 = 위 "생성 중" 렌더(status·초안·캐럿). 다른 화면에 다녀와도 서버 상태로 복구 |
| **Error** | 스레드 로드 실패: shared/ErrorState + 재시도. 질문 전송 실패: 컴포저 위 destructive 한 줄 + 입력 보존. stall(5분): 인라인 안내 "생성이 멈춘 것 같습니다 — 서버 확인 후 다시 질문" |
| **Ideal** | §4 |

- **대화 목록**(`ThreadRail`, 데스크톱 칸·폰/태블릿 Sheet·AI 패널 Popover 공용): 머리 '대화' + 새 대화, 대화 검색, 최근순 한 목록(날짜 묶음 없음) — 제목 2줄 + `MM/DD · 메시지 n`(KST, 텔레그램은 아이콘). 폭 <1024는 머리 줄 '‹ 대화 목록'·'새 대화'(폰은 제목도). 데스크톱 목록 접기 토글과 '종목 발견' 버튼은 없앴다.
- **대화 머리**: 제목(h1, 눌러 편집 — D-145) · **스터디로 만들기**(새 프로젝트 = 대화 제목, 대화가 인용한 수집 자료 최대 30건을 `POST /study-projects/{id}/documents`로 넣음, 인용 자료가 없으면 마지막 답변을 '직접 붙여넣은 자료'로 — LLM 없음, 만든 뒤 프로젝트로 이동. 이미 연결된 스터디가 있으면 '스터디 열기') · **공유 링크**(`/chat?id=` 주소 복사).
- **답변 머리**: 'AI 답변' 배지 · '근거 수집 · {묶음} n건 …'(도구 호출을 묶음별로 합산 — `RoutePanel.evidenceSummary`, 같은 도구 여러 번은 한 줄, 누르면 답변 경로 패널) · 모델 짧은 이름 · KST 시각. 폰은 배지·모델·시각 한 줄, 근거 수집 다음 줄.
- **답변 행동**(늘 보임): 복사 · **저장**(저장됨 `kind='chat'`, ref = 메시지 id, url = `/chat?id=`) · **스터디로 보내기**(메뉴: 새 프로젝트 / 기존 프로젝트 8개 → 답변+출처 목록을 자료로) · **다시 답변**(마지막 답에만, 생성 중 아닐 때 — 직전 질문을 같은 대화에 다시 보낸다. 누를 때만 LLM).
- **이 답에서 확인하지 못한 것**: 테두리 상자, 줄마다 종류 배지(근거 없음 · 자료끼리 엇갈림 · 확인 안 된 주장 · 오래된 자료 · 가정) + 메모.
- **출처 n**: 상자 안 표 `[n] · 종류(시세·공시·자료 …) · 제목(원문 링크) · 날짜`. 날짜 = 수집 자료 게시일(`GET /conversations/{id}` 응답의 인용에 `published_at`을 붙임, 저장된 인용은 그대로), 시세는 답변 시각, 공시는 제목에 날짜가 있어 비움.
- **이어 물을 질문**: 줄바꿈되는 칩. 누르면 입력 채우기(전송 아님, §4-8 그대로).
- **입력 카드**(`Composer`): 첨부 칩 줄(AI 패널의 '보고 있는 화면 · …' 칩 + 붙인 대상 칩 — §9) · 자라는 입력 · '＋' · '@' · ⓘ(근거 범위·매매 처방 안 함·키 안내) · 상태 · '보내기'. 입력 아래 안내 줄은 없앴다(부연설명 금지). 폰도 입력 아래 한 줄(4k에서 시안 Mobile-Chat-Tag대로 바꿈).
- **빈 상태**: 인사 + ⓘ(설명 줄 대신) + 가운데 입력 + 제안 카드.
- `/chat` 화면 자체에는 '보고 있는 화면' 칩이 없다(보는 화면이 대화이므로). 대화 안 대상 붙이기는 §9.

## 9. 대상 붙이기 — @ · ＋ · ⌘K (2026-11-05, 화면 구조 개편 4k · ia-redesign §4.14a)

글로 '하이닉스'라고 쓰면 라우터가 이름을 추측한다. 대화 쪽에서 대상을 골라 식별자로 넘긴다.

- **대상 종류**: 국내 종목(`stock`, 종목코드) · 미국 종목(`us_stock`, 티커) · 서사(`narrative`, topic) · 질문(`question`, id) · 수집 자료(`doc`, doc_id) · 인물(`person`, 엔티티 id) · 테마·업종(`theme`, 엔티티 id) · Peer 그룹(`peer_group`, 그룹 id) · 리포트(`report`, topic).
- **들어가는 길**: ① 입력 중 `@` → 후보 팝오버(`@` 뒤 글자로 거름, 종류별 묶음 4개씩, 종류 칩 전체·종목·미국·서사·질문·자료·인물·테마·Peer·리포트 — 넘치면 가로로 밀어 봄). ↑↓·Enter·Esc는 입력 칸이 받는다. ② 입력 카드 '＋' → 같은 팝오버 + 맨 위 검색 칸. '@' 버튼은 커서 자리에 `@`를 넣는다. ③ ⌘K 종목 행동 **'AI에게 묻기'** → AI 패널을 열고(대화 화면이면 그 입력에) 종목을 붙인다. 질문은 보내지 않는다. 옛 '함께 읽는 수집 자료' 줄은 없앴다 — 자료도 칩이다.
- **규칙**: 고르면 글 속 `@검색어`를 지우고 칩을 붙인다. 같은 대상 한 번, 5개까지(꽉 차면 후보가 비활성). 칩은 대화 내내 남고 ×로 뺀다 — 보낼 때마다 지금 붙은 전체 목록을 보낸다. AI 패널의 '보고 있는 화면' 칩은 같은 줄 맨 앞, 흐린 점선.
- **칩**: 종류 아이콘 · (종목 외에는 '서사 ·', '질문 #7') · 이름(말줄임, 툴팁에 전체) · 종목 코드·등락 / 서사·자료·리포트 날짜. 사라진 대상(보관된 서사·지운 자료)은 흐린 점선 칩이고 이유는 툴팁('보관되거나 지워진 대상이라 보낼 때 빠집니다')에만 둔다(D-312, 화면 부연설명 금지). 보낼 때 뺀다.
- **보낸 질문**: 말풍선 위에 그때 붙였던 칩을 작게(`messages[].attachments`). 답변 머리 '근거 수집' 앞에 '붙인 대상 n'.
- **5-state(팝오버·시트)**: 불러오는 중 = 스켈레톤 3줄 · 결과 없음 = '‘…’과 맞는 대상이 없어요' + '⌘K로 문서 검색 ›' · 오류 = 한 줄 + 다시 시도 · 사라진 대상 = 흐린 칩.
- **폰(<768)**: `@`나 '＋' → 아래 시트(검색 칸 · 종류 칩 · 목록 체크 여러 개 · 'n개 붙이기', 머리 'n / 5'). 입력 카드는 입력 아래 '＋ · @ · 보내기' 줄.
- **종목 후보 순위(D-312)**: 이름 정확 일치 › 이름이 검색어로 시작(영문 머리 뒤 한글 첫 글자 포함 — `SK하이닉스`·`DB하이텍`은 '하이'로 시작) › 코드 접두 › 이름에 포함, 단계 안은 시가총액 내림차순. 일치하는 종목 전부를 줄 세운 뒤 자른다. ⌘K 순위는 바꾸지 않는다.
- **서버**: 후보 `GET /api/spine/chat/targets?q=&kind=`(모델 호출 없음) · `POST /api/spine/ask`의 `attachments: [{kind, ref, label}]` → `conversations.state_json.attached_refs`(자료는 `attached_doc_ids`와 같은 목록), 질문 메시지 `chat_messages.attachments_json`. 답변은 붙인 대상의 기본 자료를 식별자로 먼저 모으고(`pipeline/chat_targets.gather`) 라우터·종합 입력에 '[대화에 붙인 대상]' 블록을 넣는다. LLM 호출 수는 그대로.
- **파일**: `chat/Composer`(@ 감지·팝오버·시트) · `chat/TargetPicker`(팝오버·시트 목록, 종류 칩, 5-state) · `chat/TargetChip`(칩·보고 있는 화면 칩) · `hooks/useChatTargets`(후보 조회) · `hooks/useThreadTargets`(대화별 칩 상태·⌘K 수신) · `lib/chatTargets`(5개 제한·`@` 찾기·요청 모양) · `lib/aiPanel.attachToAi`.
