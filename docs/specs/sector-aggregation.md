# 섹터 집약 — 유니버스 그룹을 커버리지 단위로

> 2026-07-27 기획 (D-074). 배경: `topic → 1:1 내러티브 → 1:1 리포트`라 topic(잔 테마) 수만큼 파편화.
> 실측: 반도체 하나가 AI·HBM·소부장·CAPEX 4개 내러티브로 흩어짐. 리포트는 실제로 섹터 뷰/기업 뷰.
> 해법: topic을 '재료'로 강등, **유니버스 그룹(D-037)을 섹터 커버리지 단위로 승격** — 단, 소유가 아니라 **집약 뷰**.

## 관통 원칙

1. **섹터 = 유니버스 그룹** — `sector` 엔티티(402개, vocab 파편)도 잔 topic도 아니라, 사람이 큐레이션한 **유니버스 그룹**(industry_groups, 현재 6: 반도체·2차전지·바이오·방산·원전·조선)이 섹터 단위. 커버리지 의도가 담긴 안정 단위. 미커버 영역은 그룹 생성으로 확장(D-037 편입 고리).
2. **섹터는 소유가 아니라 뷰 (N:M)** — 내러티브를 한 섹터에 배정하지 않는다. `AI` 내러티브는 반도체 뷰·전력 뷰에 **동시 등장**(엔비디아·SK하이닉스는 반도체, 데이터센터 전력은 전력). 온톨로지 "렌즈=그래프 위 saved 뷰" 철학과 정합. 배정의 N:1 강제가 만드는 정보손실을 피한다.
3. **다축 공존** — 섹터(수직·단일 도메인 커버리지)와 메가 내러티브(수평·cross-sector 슈퍼사이클, D-032)는 목적이 달라 공존. 같은 `AI` 내러티브가 반도체 섹터 뷰 · 전력 섹터 뷰 · "AI 컴퓨트 슈퍼사이클" 메가에 모두 등장. 매크로·지정학·event/spot은 섹터에 안 담고 세계관/질문 축에 둔다.
4. **리포트 앵커: topic → 섹터(그룹)** — 반도체 리포트 1개가 AI·HBM·소부장 내러티브를 종합. topic마다 리포트 나던 파편화 봉합.

## 섹터 뷰 = 집약 쿼리 (LLM 0)

한 유니버스 그룹 G에 대해:
- **소속 종목**: `industry_members`(있음) — G의 커버리지 종목.
- **G를 건드리는 내러티브**: G의 멤버 종목을 **인과 노드 or 문서 공동언급**에 포함하는 내러티브. join: `narratives` → `entity_relations`(narrative_id) / `entity_links` → 멤버 종목 엔티티. **관련도 필터**(D-035 계승, co-mention/전체 ≥ 0.3)로 편재 대형주 편승 배제 — 멤버를 스치기만 한 내러티브가 뷰를 오염시키지 않게.
- **G의 섹터 RS·밸류체인**: `sector_rs`·value_chains(있음).
- **최신 섹터 리포트**: reports(anchor=G).

전부 결정적(LLM 0) 집약. 내러티브·리포트는 별도 생성물을 그대로 뷰로 모을 뿐, 중복 생성 없음.

## 섹터 리포트 (report 엔진 진화)

기존 `report`가 이미 "앵커 + related_narratives(공유노드 이웃) + 종목 다각도 + Top-pick + 유니버스 크로스체크(in_universe, D-036)"를 한다. 변경점:
- **앵커 = 유니버스 그룹 G** (topic 문자열 대신).
- **gather = G 소속 종목 + G를 건드리는 내러티브들**(위 집약 쿼리). 기존 related_narratives 취합 로직을 그룹 앵커로 대체.
- **Top-pick = G 소속 종목 중**에서 (커버리지 안에서 고른다 — 유니버스 = 담당).
- **핵심 질문**(D-049)은 G의 지배 내러티브에서 도출 — `_narrative_power`가 G의 내러티브들을 랭킹.
- 나머지(애널리스트 팀·debate·리드·섹션·캐시·append-only 히스토리)는 그대로.

→ 리포트가 `report/compute?group=G`로 섹터당 1개. 기업 리포트(bottom-up leaf)는 별도 유지(유니버스→기업 드릴다운).

## IA — 유니버스 페이지 증강 (신규 페이지 최소화)

기존 `/follow/universe`(UniversePage, D-037)가 이미 그룹×밸류체인 커버리지 표면. 여기에 **그룹마다**:
- (있음) 소속 종목 × 밸류체인 단계 + RS·밸류
- **(신규) 이 섹터를 건드리는 내러티브 목록** — 집약 뷰, 각 내러티브로 링크
- **(신규) 섹터 리포트** — 최신 리포트 링크 + 생성 버튼

**층위 주의**: 내러티브·리포트는 월드모델 소속인데 유니버스는 팔로우 소속 → 유니버스 페이지에선 **링크로 연결**(월드모델로 이동), 유니버스에 내러티브 본문을 복제하지 않는다. 섹터는 팔로우(커버리지)와 월드모델(생성물)을 잇는 **cross-cutting 앵커**.

## 경계 (안 하는 것)

- **섹터를 유일 조직축으로 강제 금지** — 매크로·지정학(전략·CAPEX·금융 topic)·event/spot(SK하이퍼)은 섹터 뷰에 안 담고 세계관/질문 축에 둔다.
- **topic→섹터 N:1 배정 금지** — 뷰(N:M)로만. 내러티브 테이블에 sector_id 컬럼 추가 안 함.
- **메가 내러티브와 병합 금지** — 역할 분리(수직 커버리지 vs 수평 슈퍼사이클).
- **미커버 섹터 자동 생성 금지** — 유니버스 그룹은 사람 큐레이션(D-037). 미커버 topic-내러티브는 loose로 남고, 그룹 만들면 편입.

## Phase 스코프

- **Phase 1 (집약 뷰, LLM 0·저위험)**: 그룹→건드리는 내러티브 집약 쿼리 + API(`GET /industries/{id}/narratives` 류) + 유니버스 페이지에 "이 섹터의 내러티브" 섹션. **파편화가 '조직된' 형태로 즉시 가시화** — 가장 값싼 첫 수확.
- **Phase 2 (섹터 리포트)**: report 엔진 앵커를 그룹으로 (gather·Top-pick·핵심질문을 그룹 스코프로). 유니버스 페이지에 섹터 리포트 링크·생성.
- **Phase 3 (편입 고리)**: 미커버 topic-내러티브가 자주 뜨면 "유니버스 그룹 만들기" 제안(신규 후보 → 그룹 생성, D-037 확장).

## 스필오버 배제 튜닝 (2026-07-27 실측 후 확정)

Phase 1 실측이 미해결 #1(관련도 임계)을 구체화 → **관련도 임계는 틀린 레버**임이 드러남:
- 임계를 0.3→0.35로 올리니 **AI(rel 0.33)가 죽음** — AI는 broad theme라 관련도가 낮지만 반도체의 최중요
  내러티브(co 623). 반대로 스필오버 바이오(0.4)·2차전지(0.54)는 관련도가 오히려 높음. **relevance는
  broad-legit와 spillover를 못 가른다.** → 임계 0.3 유지, 대신 **두 구조 필터**로 스필오버 배제:
  1. **카테고리 필터** — category에 산업/기술 렌즈(`industry`|`tech`) 없으면 배제. 금융·지정학·매크로 전용
     내러티브는 세계관 축으로(스펙 규율 실행).
  2. **다른 유니버스 그룹의 홈 배제** — topic이 다른 큐레이션 그룹(바이오·2차전지·방산…)이면 그 섹터 뷰로
     보내고 이 뷰에서 제외(이름 매칭, 그룹 6개라 견고). 자기 홈은 유지.
- **실측 결과**: 반도체 = 반도체·AI·CAPEX·HBM·반도체장비·소부장·파운드리(코어 정확). 바이오·2차전지·방산·
  금융·지정학 제거됨.

## 미해결 / 후속

- **잔여 약한 꼬리** — 아직 유니버스 그룹이 아닌 테마(레버리지·로봇·소비재·신재생)가 낮은 co로 남음.
  그룹 커버리지가 늘면(D-037 큐레이션) 이름-홈 배제가 더 잡음. 레버리지는 category 'tech' 오태깅으로 누수(vocab 과제).
- **cross-sector 내러티브 표시** — 한 내러티브가 여러 섹터 뷰에 뜰 때 "반도체·전력 공통" 배지로 드러낼지.
- **매크로 pseudo-view** — 전략·CAPEX류 cross-cutting을 담을 뷰가 필요한지(아니면 세계관에만). CAPEX는 현재
  'tech' 태그로 섹터 뷰에 남김(반도체 핵심 서사라 유지 판단).
