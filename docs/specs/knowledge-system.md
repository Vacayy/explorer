# 지식 체계 고도화 — 3축 로드맵 (승인: 2026-07-11)

> 순서: ③ 인물 축 → ① 지식 주입 → ② 지식 위계. ②는 깊은 설계 선행 (아래 게이트).

## ③ 인물 태깅·팔로우·도시에 (선행 — 기존 패턴 조립)

- **태깅**: enrich에 `people[]` — 실존 인물(기업가·투자자·정책결정자)을 통용 한국어 표기로
  정규화 (live vocab: 기존 person 엔티티 주입 → 표기 수렴). 종목 정규화와 동일 문법.
- **온톨로지**: entities(type='person'), entity_links(link_type='person', conf 0.8).
- **팔로우**: follows는 엔티티 기반 — type='person' 그대로 동작, 홈 업데이트 자동 편입.
- **도시에** `/person?name=`: 언급 흐름 + 연관 엔티티(종목·토픽 공출현) + 게으른 프로필
  (source_digests 테이블 재사용: kind='person', doc_ids_hash 가드 — 소스 도시에와 동일 규율).
- **X(트위터) 커넥터**: 게이트 — 공식 API 비용/스크랩 불안정. 핵심 발언은 구독 채널들이
  이미 인용·번역해 나르므로(간접 수집) v1은 기존 데이터로 출시.

## ① 지식 주입 (입구 UX — 파이프라인은 기존)

- vault 노트가 이미 지식 주입 통로 (NoteConnector → raw_documents(note) → 태깅·검색·RAG).
- 추가할 것: 인앱 입구 — 대화 "기억해: …" / 옴니바 커맨드 → note 문서 생성 (epistemic
  선택: 사실|가설). garbage 방어는 입구 검열이 아니라 **provenance** (출처=나, 배지 표시,
  RAG는 note를 사실과 구분 취급 — 기존 규칙).
- 수집 문서가 사용자 주장을 확인하면 corroboration → ②의 승격 대상.

## ② 지식 위계 (게이트 잠김 — 설계 선행 필수)

### 설계 게이트 (stakeholder 지시)
구현 전에 다음에 대한 관찰·통찰의 체계화가 선행되어야 한다:
1. **인간 지능의 구조** — 작업기억/장기기억, 기억 강화(반복·정서·연결), 망각의 기능,
   스키마와 사례의 관계
2. **집단 지성의 발현** — 독립 관측의 교차확인, 권위·평판의 가중, 소수 의견의 보존,
   합의의 형성과 뒤집힘
3. **세계의 축들이 상호작용하는 방식** — 구조적 사실(느린 변화) vs 사건(빠른 소멸),
   인과 사슬의 전파, 맥락이 오래된 지식을 되살리는 조건
→ 산출물: 별도 설계 문서 (knowledge-hierarchy-design.md) — 리서치 + 개념 체계 + 스키마 매핑.

### 기술 스케치 (설계 문서에서 검증할 가설)
- 3계층: 원문서(records) → 주장(claims, 현 entity_links 수준) → **통합 지식(knowledge)**
  = entity_relations/observations + epistemic 메타 (epistemic_type, confidence,
  corroboration 수, valid_from/to, 반감기 클래스: 구조적|사건적)
- **승격 배치** (주 1회 haiku): 반복·다소스 확인 주장 → 관계로 승격, 모순 발견 시
  valid_to 닫고 새 관계 + 홈 브리핑 '지식 충돌' 알림
- RAG: 승격된 지식 계층을 검색 컨텍스트에 포함, 신선도·위계 가중
- **데이터 게이트**: 문서 1,000+ (현 ~500 — 반복 확인이 잡히기 시작하는 규모)

### 경계 (과설계 방지)
분류 체계의 완성을 먼저 추구하지 않는다 — 승격 배치 1개 + RAG 통합 1개로 시작해
실데이터가 체계를 다듬게 한다.
