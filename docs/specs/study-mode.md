# 스터디 — 자료를 묶어 읽고 표시하며 대화하기

상태: **프로젝트 스터디 구현됨 (D-158, 2026-09-11)**. 상위: [SYSTEM](../SYSTEM.md). 기존 단일 문서 스터디는 유지한다. 이 문서가 기획과 구현의 단일 계약이며 초기 HTML은 탐색 이력이다.

## 학습 코파일럿과 후속 질문 (D-159, 2026-09-11)

스터디 답변은 주석을 다시 브리핑하는 대신 짧은 요약과 사용자 생각에 대한 설명·빠진 가정·반례·다음 확인 질문을 제공한다. 일반 개념/논리적 추론은 허용하되 새로운 시사 사실·기업 현황은 실제 근거와 구분한다. 기본 답변은 2~4문단이며 하이라이트 개수나 모든 표시를 순서대로 재서술하지 않는다.

- 완료된 답변 다음에는 기본 **이전 대화 이어가기**다. 선택을 자동 해제하고, 새로 고른 주석이나 명시적으로 다시 포함한 본문만 전송한다. 프로젝트도 자료 선택이 없으면 이전 대화를 이어간다.
- 서버는 `context_mode=auto|selection|continue`를 받는다. auto는 동일한 문서 hash/주석 ID·revision을 감지해 중복을 줄인다. continue는 소유 스터디/프로젝트 안의 완료된 턴 `context_ref`를 참조하며 annotations/evidence를 새로 복제하지 않는다. 새 선택은 immutable snapshot으로 저장한다. 이전 context는 수정하지 않는다.
- ‘관련해서 다룬 내용이 더 있나?’는 같은 문서의 추가 설명이 아니라 **다른 수집 자료 탐색**이다. `study_coach`가 현재 질문·최근 대화·원래 학습 초점을 바탕으로 최대 3개 검색어를 만들고 `chat_tools.search_docs`를 실행한다. 공부 중인 원문 doc_id는 추천에서 제외하고 중복 href를 합친다. 본문보다 제목·저장 자료 링크·읽을 이유 중심으로 답하며 실제 반환 자료를 별도 목록으로도 표시한다.
- 탐색 설정 `research=auto|off|library|web`: 자동으로 설명/자료 탐색/검증을 선택하거나 사용자가 제한한다. 하이라이트 요약은 검색 없이 수행한다. 코멘트의 개념 설명을 보완하기 위한 검색은 가능하지만, 자료 안의 명령이 도구 권한을 바꾸지는 않는다.
- 웹은 기존 격리 Claude CLI에서 **WebSearch/WebFetch만** 허용한다. 검색 1회 후 관련 원문 1~2개 확인, 100초 제한/6턴 상한. 실제 tool_use 입력·tool_result를 기록하고 검색 결과에 있는 URL을 실제 WebFetch로 확인한 경우만 개별 원문 근거로 쓴다. 모델이 답변에 써낸 URL은 근거로 채택하지 않는다. 검색 목록만 확보하면 하나의 묶음으로 표시하며 원문 확인/진위 검증 완료라고 하지 않는다. API 엔진에서 웹 도구가 지원되지 않으면 명시적으로 한계를 알린다.
- 단일/프로젝트 턴 context의 research에 검색 계획과 실제 결과가 남는다. 대화의 ‘찾은 자료’ 링크는 새 탭에서 열려 읽던 스터디를 유지한다. 검색 실패/빈 결과는 숨기지 않는다. 이 기능은 별도 URL 수집이나 프로젝트 자동 추가를 수행하지 않는다.
- 호출: `study.plan`(haiku·45초), 필요 시 `study.web`, 기존 `chat.answer`. 일반 대화 라우터 전체를 열지 않으며 도구 집합은 수집 자료 검색과 웹 읽기로 제한한다.
- 검증: 전체 백엔드 89개와 빌드 통과, 단일/프로젝트 후속 질문·모바일 자료 링크 확인. `test_study_coach.py`, `logs/study-coach/`. study/3을 격리 복사해 실제 재실행: 후속 주석 10→0, 실제 수집 자료 검색 3회. 웹 원문 2개를 실제 도구로 확인했다. 운영 스터디의 기존 대화는 수정하지 않았다.

## 제품 구분

- **저장됨**: 나중에 다시 읽을 북마크. 스터디의 입력함이나 대기함이 아니다.
- **스터디 프로젝트**: 지금 함께 공부할 자료의 묶음. 북마크 없이 바로 추가하며, 저장·저장 해제와 추가·제거는 서로 영향을 주지 않는다.
- **스터디로 읽기**: 기존 문서 한 편의 스터디로 바로 이동한다.
- **스터디에 추가**: 피드/문서에서 프로젝트를 선택하거나 새로 만든 뒤, 원래 화면에 머문다. 신규 생성 후 자료 추가 실패 시 생성된 빈 프로젝트는 목록에서 다시 사용할 수 있다.

## 통합 노트 (D-160, 2026-09-11)

문서 노트/프로젝트 노트 탭을 없애고 하나의 노트로 통합했다. 활성 문서에 관계없이 모든 포함 자료의 인용 카드를 문서 순서대로 표시하며, 출처는 카드마다 작은 태그로 구분한다. 태그와 인용문 모두 원문 위치로 연결된다. 기존 자유 메모·브라우저 초안·주석 ID·revision·대화 데이터는 보존한다. 노트/AI 전환이나 출처 이동으로 코멘트 초안을 지우지 않는다.

자료를 연속 세로 읽기로 바꾸는 것은 다음 화면 개편 범위이며, 현재 읽기 책상의 탭/비교 구조는 유지한다.

## 프로젝트 경험

1. Dock 또는 Omnibar의 **스터디**(`/study`)에서 프로젝트를 만든다. 이름은 나중에 바꿀 수 있다. 기존 단일 문서의 ‘이어서 공부하기’도 이 화면에 둔다. 저장됨에는 스터디 목록을 두지 않는다.
2. **자료 추가**에서 수집 자료의 제목/URL을 검색하고 여러 개를 선택한다(회당 30개, 검색 최신 50건). 미수집 자료는 제목·본문·선택적 출처 URL을 직접 붙여넣는다. URL만으로 새 외부 페이지를 자동 수집하지 않으며 UI에도 명시한다.
3. `/study/projects/:id?doc=:study_id`는 자료함 + 읽기 책상 + 학습 패널이다. 탭으로 자료를 펼치며 두 자료 비교도 제공한다. 비교 쪽은 읽기 전용이며 ‘표시하며 읽기’로 활성 문서를 바꾼다.
4. 같은 자료를 다른 프로젝트에 담으면 독립 스냅샷과 주석을 사용한다. 기존 단일 스터디의 주석을 자동 복제하지 않는다. 프로젝트 내부 탭 전환은 읽기 위치와 코멘트 초안을 유지하며, 미저장 코멘트가 있는 탭 닫기/제거 및 AI 요청을 막는다. 새로고침 전에는 문서 코멘트를 명시적으로 저장한다.
5. 학습 패널은 **노트 / AI 대화**다. 노트는 프로젝트 전체 자료의 하이라이트·코멘트와 자유 메모를 한 스크롤 영역에 모은다. 인용 카드의 작은 문서명 태그를 누르면 해당 문서/인용 위치로 이동한다. 현재 자료·펼친 자료·전체 자료 또는 개별 체크로 AI 범위를 고른다. 자료별 선택 주석이 있으면 인용·문맥·저장 코멘트를 보내고, 없으면 고정 본문(최대 앞 16,000자)을 보낸다. 하이라이트 요약/AI에 넘기기는 프로젝트 질문을 준비하며 보내기로 실행한다.
6. 질문마다 실제 사용한 자료·발행일·본문 hash·범위·당시 주석을 고정한다. 프로젝트 대화는 기존 일반 대화 이력에도 남으며 ‘프로젝트에서 계속 공부하기’로 복귀한다. 인용 링크는 해당 프로젝트의 문서/주석 위치로 돌아온다.
7. 통합 노트의 자유 메모는 사용자 작성 결과다. AI 답변의 ‘노트에 가져오기’는 초안에만 추가하고, 사용자가 수정·저장한다. 이름/노트는 revision 충돌을 검증하며 브라우저에 초안을 임시 보관한다. 충돌 시 서버 노트를 확인하고 직접 조정한다. 프로젝트 노트 자체는 AI에 자동 주입하지 않는다.
8. 자료 제거는 프로젝트 목록에서 숨길 뿐 스냅샷·주석·과거 대화는 유지한다. 같은 자료 재추가 시 이전 주석으로 이어진다. 과거 대화의 근거 링크로 제거된 문서도 읽을 수 있으며 새 AI 질문에는 다시 추가해야 한다.

## 프로젝트 화면·데이터 계약

- IBM 14px, 기존 PageLayout/Button/Dialog/SegmentTabs/Markdown/Checkbox와 단색 디자인 토큰을 사용한다. 데스크톱 자료함 220px·학습 패널 350px, 가운데는 가변 폭과 독립 스크롤. 비교 시작 시 자료함을 접어 읽을 폭을 확보한다.
- 모바일은 자료함 기본 접힘, 문서 위·학습 패널 아래. 자료 범위 상세를 접어 답변 영역을 확보한다. 문서 탭과 패널 탭은 가로로 유지하며 비교 자료는 세로 배치한다.
- `study_projects`: title/note/revision/conversation_id. `study_project_members`: project_id/study_id/removed_at. `study_project_turns`: 요청 멱등성·고정 context·상태·대화 연결.
- `study_sessions`의 문서당 UNIQUE를 `(document_id, project_id)` UNIQUE로 이관한다. project_id=0은 기존 단일 모드이며 기존 ID/본문/주석/대화는 유지한다. 붙여넣은 프로젝트 전용 자료는 document_id=NULL이며 수집 원본이나 북마크를 만들지 않는다.
- 이관은 구 스터디 테이블을 트랜잭션 안에서 교체하고 자식 외래키를 검사한다. 실제 운영 이관 전 스터디 데이터 백업은 `logs/study-projects/study-before-migration.json`; 기존 3문서·3주석·2턴 모두 유지했다.
- 프로젝트 AI는 최대 10자료·40근거·합계 80,000자다. 한 자료의 주석 제한은 기존 단일 스터디 규칙을 적용한다. 소속/제거/주석 revision을 서버 검증하고 초과 시 422로 거부한다. 클라이언트 임의 본문은 근거로 신뢰하지 않는다.
- 프로젝트당 pending 한 건, request_key 중복 접수 방지, 10분 이상 중단 요청 명시 복구. 일반 chat 합성/인용 검증·저장을 재사용하고 D-159의 제한된 자료 검색/웹 확인을 지원한다.

## 프로젝트 API

기본 경로 `/api/spine/study-projects`:

| 동작 | 계약 |
|---|---|
| GET / · POST / | 목록(최근 200) · `{title}` 생성 |
| GET /search?q= | 제목 또는 수집 URL 검색 |
| GET /:id · PATCH /:id | 프로젝트·자료·턴 조회 · `{title,note,revision}` 수정 |
| POST /:id/documents | `{document_ids}` 수집 자료를 프로젝트에 추가 |
| POST /:id/clips | `{title,text,url}` 직접 붙여넣은 자료 추가 |
| DELETE /:id/documents/:study_id | 해당 프로젝트 자료 목록에서 제거 |
| POST /:id/ask | `{question,sources:[{study_id,annotations:[{id,revision}]}],request_key}` 비동기 질문 |
| POST /:id/turns/:turn_id/recover | 10분 이상 중단 요청 정리 |

아래는 단일 문서 읽기와 프로젝트 내부에서 재사용하는 주석 계약이다.

## 사용자 흐름

1. Home 피드 또는 문서 상세의 **스터디로 읽기**로 진입한다. 같은 수집 문서는 기존 스터디를 이어 연다. 스터디 목록의 **이어서 공부하기**에서도 재진입한다.
2. 팔레트 **하이라이트**를 누른 뒤 드래그하면 선택한 텍스트가 바로 저장된다. **선택 영역 표시** 버튼으로 키보드 선택도 저장할 수 있다. Esc는 읽기 도구로 돌아간다.
3. **코멘트** 도구에서 본문을 클릭하면 그 위치의 문장을 가져와 노트 패널에서 생각·질문을 작성한다. 드래그한 범위에도 코멘트를 달 수 있다. 키보드는 본문 블록에 포커스 후 Enter를 사용한다.
4. 코멘트는 명시적 **코멘트 저장** 버튼으로 저장한다. 저장 실패 시 입력을 유지하고 오류를 표시한다. 저장하지 않은 초안이 있으면 AI 요청을 막고 먼저 저장하도록 안내한다.
5. 체크한 주석은 **AI에 넘기기**로 질문 입력란에 연결한다. 인용문·앞뒤 문맥·저장 코멘트를 포함하며 입력란의 **함께 보낼 내용**에서 확인/제외한다. 넘기기는 전송 전 준비이고 **보내기**가 실제 AI 실행이다.
6. **하이라이트 요약**은 선택한 하이라이트(선택이 없으면 전체 하이라이트)를 요약 요청한다. 같은 문서 옆 AI 패널에 답변한다. 코멘트를 원문 작성자의 주장과 구분한다.
7. 문서별 하나의 기존 `conversations` 웹 스레드를 사용한다. 일반 대화 목록에도 `스터디 · 제목`으로 남고, 대화 화면의 **문서에서 계속 공부하기**로 돌아올 수 있다. 스터디에서 최근 질문에 사용한 주석 선택도 재진입 시 복원한다.

## 화면 계약

- `/study/:id?annotation=:id`. PageLayout/PageHeader, Button/Textarea/Checkbox/SegmentTabs/TooltipProvider/Markdown 등 기존 컴포넌트 사용. 독립 Dock 스터디 항목, 상세 화면의 접힌 레일 상태 공유.
- 데스크톱은 본문 + 360px 노트/AI 패널. 각각 독립 스크롤. 팔레트는 두 영역 위에 남는다. 본문은 최대 720px, IBM 14px/1.85.
- 가용 폭 900px 미만은 **문서 / 노트 / AI 대화** 전환. 패널을 열어도 원문을 위쪽 최대 35dvh로 남기고 아래에 패널을 표시한다. 원문을 완전히 대화 화면으로 대체하지 않는다.
- 하이라이트는 연한 배경, 코멘트는 점선 밑줄. 읽기 도구에서 표시를 클릭하면 연결된 노트를 선택한다. 답변 인용은 해당 스터디/주석 위치로 이동한다. 삭제된 주석도 과거 context에 있으면 고정 원문 위에 당시 위치를 표시한다.
- 본문은 보관 텍스트를 그대로 렌더한다. Markdown 문법을 별도 변환하지 않으므로 문자 위치를 안정적으로 보존한다. 영상의 저장 Markdown이 AI 정리본일 수 있음을 표시하며 타임코드를 추정하지 않는다. 현재 이미지/PDF 영역 주석은 지원하지 않는다.
- 원문 위치는 탭 sessionStorage에 UI 상태로만 저장한다. 원문·코멘트의 진실 원천은 서버 DB다. 코멘트 초안의 새로고침 보존은 지원하지 않으며 저장 버튼을 사용한다.

## 영속 데이터

| 테이블 | 역할 |
|---|---|
| study_sessions | 수집 문서·프로젝트 범위당 1개. 원문 텍스트·제목·URL·종류·발행일·본문 종류·content_hash를 최초 진입 시 고정, conversation_id 연결 |
| study_annotations | kind, Unicode code-point start/end, exact, comment, revision, timestamps, deleted_at. 겹치는 범위는 별개로 저장 |
| study_turns | question, request_key, conversation/message ID, 고정 context_json, pending/complete/error, 생성/완료 시각 |

`database.init_db`에서 additive CREATE IF NOT EXISTS로 초기화한다. 기존 raw_documents·enrichments·saved_items·conversations는 보존한다. 최초 열기에서 본문을 요약/재수집하지 않는다. 원문이 이후 갱신되거나 사라져도 스터디의 고정 텍스트와 주석은 유지한다. 새 본문 버전으로 갱신하는 UI는 후속이다.

브라우저 DOM Range의 prefix 문자열을 Unicode code point 수로 변환해 서버와 같은 offset을 사용한다. 서버가 고정 본문의 `[start:end] == exact`를 확인한다. 원문 보존 렌더·같은 content_hash 안에서만 주석 위치를 해석하므로 재수집 후 자동 재앵커는 필요하지 않다. 같은 문장의 반복·이모지·겹치는 주석을 위치로 구분한다.

주석 수정/삭제는 revision 일치 시에만 적용하며 충돌은 409다. 삭제는 soft delete이고 과거 대화의 context는 수정하지 않는다. 북마크 해제로 스터디가 삭제되지 않는다. 스터디 전체 삭제/내보내기는 후속이다.

## AI 근거와 생성 계약

- 선택한 주석 ID/revision을 서버에서 해당 study 소속으로 검증하고 exact·comment·앞뒤 400자 문맥을 재구성한다. 클라이언트가 보낸 임의 인용문을 질문 근거로 신뢰하지 않는다.
- 선택 없음은 현재 고정 본문 전체(16,000자 초과 시 앞 16,000자, UI에 표시). 선택 시 인용문+코멘트 18,000자, 문맥 포함 28,000자, 최대 30개 주석. 초과 시 422이며 선택 내용을 조용히 자르지 않는다.
- 각 턴의 context에는 당시 주석 내용/revision, 본문 hash·종류·URL·사용 범위, 실제 근거 발췌를 고정한다. 질문 아래 **이 질문에 사용한 자료**에서 확인한다. 후속 편집/삭제로 과거 답변 근거가 바뀌지 않는다.
- `pipeline.chat.run_turn(study_context=...)`는 기존 종합·인용 검증을 재사용한다. 일반 라우터/시나리오 생성을 생략하고 D-159의 학습 계획과 제한된 읽기 도구를 사용한다. 종합 모델 자체의 도구는 비활성이다. 원문이나 코멘트의 명령이 검색 권한을 넓히지 않는다.
- `generate_answer`의 기존 대화 저장·스트림 처리를 재사용한다. 스터디 턴은 추가 메모 압축/별칭 제안을 실행하지 않는다. 패널은 기존 대화 GET으로 폴링하며 완료 상태 전환 시 최종 답변을 다시 조회한다.
- 코멘트는 사용자 생각·궁금증, 원문은 작성자의 주장, AI는 설명/추론으로 구분하도록 지시한다. 일반 `/chat`의 새 질문은 기존 일반 대화 정책을 사용하므로 문서에 집중한 후속 학습은 **문서에서 계속 공부하기**로 이어간다.
- 저장과 생성은 명시적 POST/PATCH만 수행한다. GET은 조회 전용. 동일 request_key 재시도는 동일 턴을 반환하고, study별 pending 한 건만 허용한다. 클라이언트는 실패한 같은 입력의 request_key를 유지한다.
- 생성 실패는 assistant 메시지와 turn.error에 남겨 재질문 가능하게 한다. 서버 중단 등으로 10분 이상 pending이면 **멈춘 요청 정리하고 다시 질문하기**를 제공한다(LLM 제한 300초 + 여유). 즉시 실행 취소는 지원하지 않는다.

## API

| 경로 | 역할 |
|---|---|
| POST /api/spine/studies | `{document_id}` → 스터디 생성 또는 기존 id |
| GET /api/spine/studies | 단일 문서 스터디 최근 100개, 스터디 목록에 최근 8개 노출 |
| GET /api/spine/studies/:id | 고정 원문, 활성 주석, 턴과 context |
| POST /:id/annotations | `{kind,start,end,exact,comment}` 저장 |
| PATCH /:id/annotations/:annotation_id | `{revision,comment,delete}` 수정/삭제 |
| POST /:id/ask | `{question,action,annotations:[{id,revision}],request_key}` → 기존 conversation_id, 비동기 생성 |
| POST /:id/turns/:turn_id/recover | 10분 이상 pending을 error로 마감, 다시 질문 가능 |

기존 GET /api/spine/conversations/:id에 선택적 study 메타를 추가해 문서로 복귀한다. 기존 일반 대화/봇 API 입력은 변경하지 않는다.

## 검증과 현 상태

- 격리 SQLite: 고정 본문, Unicode offset, 잘못된 인용, revision 충돌, 소속/삭제 주석 거부, 중복·동시 질문 방지, 당시 코멘트 고정, 미선택 주석 제외, 도구 라우팅 미호출, 멈춘 요청 복구.
- 브라우저 + 격리 API + 모델 대역: 드래그 하이라이트/재접속, 위치 클릭 코멘트, 선택 context 전달, 요약·같은 스레드 후속 대화, 기존 대화 이력/스터디 복귀, 모바일 문서 유지와 넘침 없음.
- 실제 모델 연결도 격리 저장소에서 1회 실행했다. 2026-09-10에는 Claude OAuth session expired 오류로 실패했다. 실패가 턴/대화에 정상 기록됨을 확인했다. 2026-09-11 프로젝트 CLI의 opus 짧은 실제 호출은 성공해 인증 정상화를 확인했다(9.8초, AUTH_OK). 스터디 전체 실응답을 다시 검증한 것은 아니다. 테스트 자료·대화는 운영 DB에 넣지 않았다.
- 프론트엔드 빌드와 백엔드 테스트 62개 통과. 추가로 미저장 코멘트의 AI 전송 차단, 겹치는 여러 문단 선택의 원문 보존, 다크 모드, 없는 스터디 오류 상태를 확인했다. 검증 산출물은 `logs/study-implementation/`, 실행 테스트는 `backend/tests/test_study.py`.

## 후속 범위

새 URL 자동 가져오기, 자막 시간 연결, 이미지/PDF 주석, 원문 새 버전 비교, 전체 삭제·내보내기. 자료 검색·웹 원문 확인은 D-159에서 구현했다. 기존 소스 구독과 혼동하지 않도록 각각 명시적 동작으로 확장한다. 단계별 별도 spec을 추가하지 않고 이 문서를 갱신한다.
