# 기술적 읽기 층 — 한눈에 보기 · 한 줄 읽기 · 상황 렌즈 (2026-09-22, D-198)

상태: **구현됨**(2026-09-22), **신뢰·조작 개선 묶음 A 적용**(2026-09-23). 상위 문서: [시장 전략 도구](market-strategies.md) §기술적 분석 스캔, [차트 구조 그리기](chart-structure.md). 결정 배경: DECISIONS D-198.

## 문제

기술적 분석 패널(D-190)과 구조 그리기(D-195)는 잘 쓰이지만, 둘 다 **사용자가 고르는 것**을 전제한다. 조건 이름(ADX·이격도·%B)을 읽고, 그릴 구조 종류를 고르고, 종목 발견에서는 빈 텍스트 상자에 조건을 적어야 한다. 지표 이름을 모르는 사용자는 여기서 멈춘다. 구조 그리기가 유독 잘 쓰이는 이유는 "아는 종목 하나에, 설정 없이, 그림으로, 바로" 나오기 때문이다. 이 층은 그 성질을 나머지에 옮긴다: **시스템이 고르고 그림과 평서문으로 번역하되, 판단은 남긴다.**

## 범위

| # | 기능 | 위치 | 계산 |
|---|---|---|---|
| 1 | **한눈에 보기(자동 캔버스)** | 기업 페이지 기술적 분석 패널 | 스캔 결과로 그릴 구조 종류·기간을 규칙으로 고르고 구조 그리기를 기본으로 펼친다 |
| 2 | **한 줄 읽기** | 같은 패널, 특이점 위 | 계열 5개 질문마다 상태·신호 값을 채운 평서문 1개. 모델 없음, 문장마다 근거 조건 id |
| 3 | **상황 렌즈** | 종목 발견 첫 화면 '목적에 맞는 검색으로 시작하기' + 저장 전략 탭 | 새 조건(박스권·스프링·이격·RSI·볼린저·모멘텀·ADX·매물대)을 조합한 추천 8개. 보는 것/못 보는 것 명시 |
| 4 | 후보 → 캔버스 연결 | 발견 결과 후보 카드 | `/analyze/{code}/summary?scan=1&source_run={runId}&scan_at=discovery`로 발견 당시 판정부터 진입 |

Out of scope: 종합 점수·신호등·"매수 관점" 요약(D-181 위반), 스캔 로드 시 모델 자동 해설(D-191 비용 원칙), 사용자별 렌즈 저장(저장 전략이 이미 담당).

## 1·2 계산 (`backend/pipeline/technical_reading.py`)

입력: `scan_rows()` 결과와 `technical_commentary.price_context()`. 순수 함수, 종목당 1ms 미만.

**한 줄 읽기 `readings(scan, price)`** — 계열 순서(가격 구조 → 시세동향 → 지표신호 → 추세·모멘텀 → 평균회귀)로 `{group, question, text, basis[]}` 5개. 규칙:

| 계열 | 문장에 넣는 것 (모두 스캔 값에서) | 아무것도 없을 때 |
|---|---|---|
| 가격 구조 | 박스권(상·하단 값) / 저점 높이기 / 고점 낮추기 상태, 최근 N거래일 구조 신호 최대 3개(라벨·날짜) | "박스권·저점 높이기·고점 낮추기 어느 상태도 아니고 최근 N거래일 구조 신호가 없습니다" |
| 시세동향 | 52주·연중 극값 → 20일·5일 극값 → 갭 순으로 최대 3개, 거래량/20일 평균 배수, 52주 고점 대비 % | "신고가·신저가·갭 신호가 없습니다" + 52주 고점·저점 대비 % |
| 지표신호 | 정배열/역배열/엉킴, 최근 교차(20·60 골든/데드 → 5·20 → MACD 0선 → 추세전환 확인) | "정·역배열 어느 쪽도 아니고 최근 교차 신호가 없습니다" |
| 추세·모멘텀 | 12-1 모멘텀 값·부호, 200일선 위/아래와 거리 %, ADX 값과 강도 말(20 미만 약함·25 이상 강함·사이 보통), +DI/−DI 우세 | 이력 부족 문구 |
| 평균회귀 | 20일선 대비 %, RSI 값과 구간 말(30 이하 과매도·70 이상 과매수·그 외 "과열도 과매도도 아님"), 볼린저 위치(%B: 안/상단 밖/하단 밖), 스퀴즈 | 이력 부족 문구 |

문장은 **판정 서술**만이다. 방향 예측·추천 어휘(매수·상승 전망·유망)는 템플릿에 없다. `basis`는 문장에 값을 준 조건 id 목록이며 화면은 이를 그대로 배지로 보인다. 값이 `unavailable`이면 그 계열 문장은 "시세 이력이 부족해 평가하지 못했습니다"로 대체한다.

**자동 캔버스 `canvas(scan)`** — 첫 규칙이 맞으면 채택, `{kind, window, swing, fit, reason}`:

1. 박스권 상태 → `levels` · 6m · "고점·저점이 수평인 박스권이라 지지·저항 레벨을 그립니다"
2. 최근 채널 상단 돌파/하단 이탈 → `channel` · 6m
3. 저점 높이기 상태 또는 상승 추세선 지지·이탈 신호 → `trendline_low` · 6m
4. 고점 낮추기 상태 또는 하락 추세선 돌파 신호 → `trendline_high` · 6m
5. 전고점 돌파·전저점 이탈·돌파 후 재돌파·거짓 돌파/이탈 신호 → `levels` · 1y
6. 매물대(60일) 돌파 신호 → `profile` · 6m
7. 그 외 → `levels` · 1y · "성립한 구조 상태가 없어 1년 지지·저항 레벨을 기본으로 그립니다"

스윙 폭 5·두 점 연결 고정. 사용자가 카드에서 종류·기간을 바꾸면 그 뒤로는 자동 선택을 덮어쓰지 않는다(범위 변경으로 스캔이 다시 와도).

API: `GET /api/spine/technical-scan/{code}` 응답에 `readings[]`·`canvas`를 추가한다. 다른 필드는 그대로.

## 3 상황 렌즈 (`discovery_service.recommendations`)

기존 목적별 추천 템플릿에 그룹 **"상황 렌즈"** 8개를 더한다. 템플릿은 조건별 매개변수 덮어쓰기와 항목별 "못 보는 것"을 받도록 확장했고, 모든 조건은 `normalize_condition`을 통과한다(테스트).

| id | 이름 | 조건 | 못 보는 것 |
|---|---|---|---|
| lens-range-break | 박스권 상단을 막 넘은 종목 | `trading_range`(1) + `resistance_break`(5) | 되돌아올지(거짓 돌파)는 며칠 뒤 판정 |
| lens-spring | 바닥을 깨는 듯하다 되돌아온 종목(스프링) | `false_breakdown`(5) | 매집인지 분산인지 |
| lens-pullback-20 | 장기 추세 위에서 20일선까지 되돌아온 종목 | `close_above_sma`(1) + `disparity_low`(1, 101.5) + `disparity_high`(1, 98.5) | 되돌림이 여기서 멈출지 |
| lens-squeeze | 변동성이 가장 좁아진 종목(볼린저 스퀴즈) | `bollinger_squeeze`(1) | 확대 방향 |
| lens-oversold-exit | 과매도에서 빠져나오며 저점을 높이는 종목 | `rsi_exit_oversold`(10) + `higher_lows`(1) | 반등의 이유 |
| lens-momentum-strong | 1년 모멘텀 양이고 추세가 강한 종목 | `momentum_up`(1) + `adx_strong_trend`(1) + `close_above_sma`(1) | 모멘텀 붕괴 시점 |
| lens-profile-above | 매물대 위로 올라선 종목 | `volume_profile_up_60d`(5) + `close_above_sma`(1) | 체결가별 실제 매물(일봉 근사) |
| lens-reenter-lower | 볼린저 하단 밖에서 안으로 복귀한 종목 | `bollinger_reenter_lower`(5) | 밴드 접촉 자체는 반전 신호가 아님 |

각 카드는 `purpose`(보는 것)·`misses`(못 보는 것)·`phrase`(질문에 덧붙일 문장)를 갖는다. 실행 경로·검증·저장은 기존 추천과 같다(D-181). 자연어 검색과 질문 다듬기(D-186)는 카탈로그를 자동으로 받으므로 새 조건은 이미 문장으로 쓸 수 있다.

## 화면

**기업 페이지 패널**(`company/TechnicalScan`, D-202): 시세 기준일 → 가격 차트 하나와 **핵심 관측 3개**(이동평균·평균 이격·거래량, 실제 서버 문장과 판정 근거) → 다음 확인. 한 줄 읽기 5개·특이점·잦은 신호는 ‘전체 지표·최근 신호와 계산 근거’에 둔다. **구조 그리기는 상단 탭**(D-203)으로 바로 열고, AI 해설은 기본 접힘이다. 활성 보기의 차트만 렌더하며 구조 종류·기간을 URL에 보존한다. 미평가 사유와 접힌 평가 범위를 유지한다.

| 상태 | 표시 |
|---|---|
| Empty | 시세 없음 404 → 기존 ErrorState 문구 |
| Loading | 기존 스켈레톤 3줄. 가격 차트는 가격 자료가 있으면 유지 |
| Partial | 일부 계열 unavailable → 그 줄만 "이력 부족" 문장; 캔버스는 422면 카드가 사유·스윙 줄이기·기간 늘리기를 보임(기존) |
| Error | 스캔 실패 → 기존 ErrorState 재시도 |
| Ideal | 위 순서 전부. 관측의 기준일을 명시하고 상세에서 기본 매개변수와 평가 범위를 확인 |

**종목 발견**(`analysis/DiscoveryLibrary.DiscoveryRecommendations`): 카드에 `misses`가 있으면 "못 보는 것: …" 한 줄을 조건 접힘 밖에 바로 보인다. 결과 후보 카드(`analysis/AnalysisResults`)의 '기업 개요' 옆에 **'기술적 분석 열기'** 링크(`?scan=1&source_run={runId}&scan_at=discovery`). 기업 개요 링크도 `source_run`을 유지하며 `scan_at=latest`로 연다.

## 실측 (2026-09-22)

- 한 줄 읽기·캔버스: 삼성전자 스캔 57ms(첫 호출)·이후 13ms, 읽기·캔버스 추가 비용 1ms 미만. 삼성전자 캔버스 = 매물대 6m(60일 매물대 상향돌파 신호), SK하이닉스 = 저점 추세선 6m(저점 높이기 + 하락 추세선 돌파), NVDA = 매물대 6m.
- 문장 예(삼성전자, 5거래일): "1년 수익률(최근 1개월 제외) +298.6%로 양(+). 200일선 위(+23.2%). 추세 강도 ADX 9은 약해 방향보다 횡보에 가깝습니다(방향 지표는 상승(+DI) 쪽이 우세)." / "20일선 대비 +4.9%. RSI 57로 과열도 과매도도 아닙니다. 볼린저 밴드 안(%B 0.94)."
- 렌즈 8개를 격리 루트의 실제 스냅샷(2026-09-18, 2,992종목, 평가 약 2,600)에 실행 — 매치 수: 박스권 상단 돌파 53 · 스프링 211 · 20일선 되돌림 150 · 스퀴즈 357 · 과매도 탈출+저점 높이기 7 · 모멘텀+강한 추세 172 · 매물대 위 134 · 볼린저 복귀 311. 실행 2~10초. 상태 조건만인 렌즈(스퀴즈·복귀·스프링)는 넓어 시총·거래량 하한을 기본값에 넣을지 후속 검토.
- 주의: 실행 중이던 백엔드(uvicorn, --reload 없음)는 옛 카탈로그를 메모리에 들고 있어 새 조건의 실행을 `unknown strategy_id`로 거절한다. 배포 시 재시작 필요.


## 신뢰·조작 개선 묶음 A (2026-09-23, D-201)

[승인한 HTML 기획안](../prototypes/discovery-technical-improvement-plan.html)의 첫 묶음. 계산·감시 엔진을 바꾸지 않고 저장된 결과와 현재 API의 의미를 정확히 연결한다.

- **관측과 판정:** `scanEvidence.readingEvidence`는 RSI·이동평균 배열·ADX·이격·볼린저 위치의 참조 조건을 중립 지표로 묶는다. RSI 60에 과매도 `fail`을 참조해도 ‘RSI · 중립’이다. 빠진 조건은 중립으로 추정하지 않는다. 나머지 조건에는 충족/불충족/미평가를 붙인다. `TechnicalEvidence`의 Dialog에서 개별 조건·원 판정·계산 값·비교 기준·날짜를 확인하고 닫으면 원 버튼으로 초점이 복귀한다. 정밀 값은 최대 소수 15자리로 보존한다. 충족 개수는 접힌 평가 범위로 옮긴다.
- **발견 당시 / 현재:** `DiscoveryTechnicalContext`는 `useAnalysisRun`으로 원 실행을 읽고 기존 `CandidateChart`를 재사용한다. 당시 보기는 그 실행의 고정된 차트와 조건만 표시한다. 현재 보기는 최신 보유 시세와 기본 스캔을 보여주고 원 질문·기준일·검색 범위를 보존한다. 현재 스캔의 매개변수가 당시 검색과 다를 수 있다고 명시한다. 동일 조건 버전의 변화 비교는 묶음 C에 남긴다.
- **URL:** `source_run`, `scan_at=discovery|latest`, `scan=1`, `scan_within`, `scan_chart=0|1`. 기업 탭의 허용 목록에도 추가한다. 원 후보 복귀는 `/discover?run={source_run}&candidate={code}`다. 검색 실행 시각은 `created_at`, 시세 기준은 `result.as_of`로 분리한다.
- **과거 날짜:** 임의 과거 날짜의 전체 스캔은 지원하지 않는다. `mode=research&date=...`가 최신일과 다르면 미지원 상태와 현재 분석 전환을 표시하며 최신 신호·보조 구조·AI 해설을 숨긴다. 가격과 스캔 기준일이 다르면 차트에 신호를 합성하지 않고 두 날짜를 표시한다.
- **선의 의미:** 원 판정의 `scan.lines`·스윙은 가격 차트에 사용한다. 별도 구조는 ‘큰 흐름의 보조 구조 · 6개월 채널’처럼 표기한다. 감시 행동은 ‘유사 조건 감시’이고, 묶음 선택 메뉴에도 최신 시세로 선을 재계산한다는 설명을 제공한다.
- **기초정보 없는 후보:** 기업 메타데이터 조회가 실패해도 원 실행의 차트·판정과 복귀 링크를 열 수 있다. 이 상태에서 현재 기업 분석 전환은 사유를 표시하고 비활성화한다.
- **조작:** 최초 후보는 보이는 시가총액 내림차순 첫 행과 맞춘다. URL에서 선택한 종목은 유지한다. 구조 선택 그룹은 줄바꿈하며 모든 선택지를 320px에서도 노출한다.

## 핵심 경험 개선 묶음 B (2026-09-23, D-202)

`feat/discovery-technical-ux`에서 같은 HTML 기획안의 다음 묶음을 구현했다. 계산 엔진·저장 모델은 그대로 사용한다.

- **시작과 편집:** `DiscoveryStart`의 네 목적 중 세 검색은 서버 추천 `lens-pullback-20`, `lens-range-break`, `lens-oversold-exit`의 spec를 사용한다. 마지막 목적은 기업 검색 → 현재 기술적 분석이다. 시장·최소 시총·기준일을 보이게 두고, 개별 조건은 요약 → ‘조건 수정’에서 매개변수와 기간을 편집한다. 조건 추가·제거·기본 복원이 가능하며 편집한 spec를 그대로 전송한다. 접힌 입력도 자료형·범위·필수값을 검사한다. 조건은 AND이며 기본값의 당일 상태와 최근 N일 사건을 임의로 같은 기간으로 바꾸지 않는다. 자연어·전체 추천·구조 그리기는 별도로 펼쳐 쓴다.
- **검색 대상:** 기존 서버 계약의 국내 전체/KOSPI/KOSDAQ와 시총 하한을 사용한다. 검증된 증권 유형 필터가 없어 ‘보통주만’이라고 표시하지 않으며 스팩·우선주 등이 포함될 수 있음을 설명한다.
- **후보 비교:** 선택 종목의 차트 열기와 비교 체크를 분리한다. 2~3개를 같은 검색 실행의 `as_of`, 시총, 후보 상태, 조건별 판정·계산 값·비교 기준·판정일·순위로 비교한다. 없는 값은 ‘—’, 미검증·미평가·추정 값은 해당 상태를 유지한다. 지표 값의 단위가 다르므로 공통 거리나 매수 점수는 만들지 않는다. 서버에 없는 거래대금·현재 변화는 추정하지 않는다.
- **이동과 복원:** `intent`, `candidate`, `compare`, `sort=cap_asc|cap_desc`는 URL에 둔다. 기업 링크의 `source_compare`·`source_sort`를 탭과 발견 복귀에서 보존한다. 정렬을 바꿔도 선택 종목을 유지하고, 첫 진입은 정렬의 첫 후보와 맞춘다. 모바일 후보 미리보기의 ‘후보 목록으로 돌아가기’는 원 선택 버튼으로 초점을 돌린다. 목록 재진입은 선택 행이 보이도록 목록 내부 위치를 맞춘다.
- **초안:** `useSessionDraft`는 자연어 질문·날짜·판정 범위, 목적별 조건, 실행별 후속 질문·범위·자료 시점을 탭의 sessionStorage에 보존한다. 수정할 때만 쓰며 손상된 저장값은 초기값으로 복구한다. 저장이 차단돼도 입력·실행을 유지하고 보존 실패를 알린다. 탭 종료 후의 영구 보존이나 창 사이의 동기화 계약은 아니다.

- **기업 분석:** `CompanyPriceResearch`의 가격 차트를 `TechnicalScan` 슬롯으로 전달해 첫 화면에서 차트와 핵심 관측 3개를 함께 보인다. 요약은 서버 문장을 재사용하며 거래량 문장이 없으면 다른 신호로 대체하지 않는다. ‘다음 확인’은 실제 최근 신호의 날짜와 계산 근거를 연결한다. 전체 읽기 5개·신호, 보조 구조, AI 해설은 펼쳐 확인한다. 원 판정선과 보조 구조의 구분, 임의 과거일 미지원, 가격/스캔 기준일 불일치 계약은 A와 같다.
- **조회 계약:** `useAnalysisStrategies`는 목적 편집기와 기존 전략 라이브러리가 전략 정의 envelope를 공유한다. 감시 화면의 items 배열 쿼리와 캐시 키를 분리해 응답 모양 충돌을 방지했다.

## 상승 후보 중심 탐색과 구조 그리기 우선순위 (2026-09-23, D-203)

사용자 피드백에 따라 시작 화면의 기본 목적은 **상승 후보 탐색**으로 바꾼다. 신고가·거래량 동반 돌파·횡보 돌파·강한 추세·되돌림·매물대 돌파 6개를 기본으로 노출하고, 반등·전환 및 전체 상황으로 확장한다. 각 시나리오는 기존 서버 추천 spec를 사용하며, 방향이 없는 변동성 축소나 거래량 증가만으로 상승 후보라 표시하지 않는다.

**아는 종목 분석**은 상황 검색과 분리한 상단 강조 카드다. 종목을 선택하면 기술적 분석으로 이동하거나, 구조 프리셋을 고르고 곧바로 그린다. 질문을 채워 재실행하는 중간 단계를 없애며 서버 쓰기나 자연어 해석 없이 기존 그리기 URL을 연다.

**아는 종목 검색 기록:** 검색 결과에서 실제로 선택한 국내 종목의 이름·코드를 최근 순으로 최대 8개 보존한다. 입력 중인 검색어는 저장하지 않는다. 같은 종목을 다시 선택하면 중복 없이 맨 앞으로 옮기며, 기록 선택은 분석 대상만 바꾸므로 기술적 분석·구조 그리기 중 원하는 동작을 이어갈 수 있다. 브라우저 localStorage(`explorer.recent-company-searches.v1`)에 저장하며 옴니바의 최근 본 종목과는 별도 기록이다. 전체 삭제는 현재 선택 종목을 유지하고 종목 검색으로 초점을 돌린다. 빈 기록은 안내, 손상된 값은 유효한 항목만 복구, 저장이 차단되면 현재 화면에서만 기록을 유지하고 이를 표시한다. 별도 서버 조회·로딩은 없으며 검색 API의 로딩·오류·빈 결과는 기존 검색기가 처리한다.

검색 기록 검증: 실제 로컬 종목 검색을 이용한 브라우저 검사 **27개** 통과. 입력만 할 때 미저장, 선택·중복 제거·최근 순 정렬·최대 8개, 새로고침·기업 왕복 보존, 기록에서 분석·그리기 연결, 전체 삭제·초점 복귀, 손상된 저장값·저장 차단, 320·390·768px 표시를 확인했다. 서버 쓰기는 없었으며 기존 Node 테스트 **31개**와 타입 검사·프로덕션 빌드도 통과했다.

기업 기술적 분석에서는 **차트 읽기 / 구조 그리기**를 동등한 상단 탭으로 제공한다. 읽기를 기본으로 유지하고 구조 그리기는 한 번에 진입한다. 활성 탭의 차트만 표시하며 구조 종류·기간·스윙 폭·적합은 URL에 보존한다. 신호 판정선과 독립적으로 계산한 구조임을 설명하며 당시/현재 구분과 과거일 미지원 계약은 유지한다.
