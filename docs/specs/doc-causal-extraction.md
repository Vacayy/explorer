# 기획서 — 문서 레벨 인과 추출 (제2 인과 공급원)

> 2026-07-18. 상태: **승인됨 (D-028 레버 3) — 같은 날 구현.**
> 배경: 인과 그래프의 공급원이 내러티브 종합 하나뿐이라, 양질의 단일 분석글(유튜브 정리본·
> 롱폼 블로그)이 품은 인과 통찰이 요약 한 줄로 압축된 뒤 버려진다. 60개 엣지 전부
> corroborated_by=1인 것도 공급원이 하나라서다 — 독립된 제2 공급원이 교차검증을 깨운다.

## 1. 원칙

- **내러티브(종합) 엣지와 문서(개별) 엣지는 서로 독립 출처** — 같은 (src,dst,rel)이 양쪽에서
  나오면 confidence 강화(기존 upsert 로직 그대로). 문서 엣지는 `source_doc_id`로 근거 추적,
  `narrative_id=NULL`로 구분.
- **노이즈 방어 3중**: ① 선별(LLM 태깅 완료 + 본문 1,200자+ — 짧은 시황 코멘트 배제)
  ② 프롬프트 규율("문서에 명시적으로 서술된 인과만, 암시·추측 금지, 없으면 빈 배열")
  ③ 낮은 초기 confidence 상한(0.5) — 반복 확인돼야 커진다.
- **노드 정규화**: 내러티브와 같은 `_node_vocab` 주입 — 문서 엣지가 내러티브 엣지와 같은
  노드를 밟아야 교차검증이 성립한다.
- **행위자·반사성·시간 규율**: 내러티브 프롬프트(D-027)와 동일 지침 — person/company 중간
  행위자, 피드백은 시점 다른 두 엣지, 수혜 종착=sector.

## 2. 모델 선택

**sonnet** — 인과 추출은 태깅(haiku)보다 어렵고(암시/명시 구분, 방향 판정), 내러티브 종합
(opus)보다 대량 반복이라 중간 티어가 균형점.

## 3. 구현

- `enrichments.causal_extracted_at` 컬럼 — 추출 시도 기록(인과 0건이어도 기록, 재시도 방지)
- `pipeline/doc_causal.py` — 선별 쿼리 + 문서당 sonnet 1콜 + narrative.py `_persist_causal`
  재사용(narrative_id=None 허용으로 파라미터화)
- `scripts/extract_doc_causal.py --limit N` — 수동 배치 (최신순)
- **cron 편입은 보류** — 30분 체인이 이미 30분을 초과(D-024 배경)라 당장 얹지 않는다.
  초기 백필은 수동 배치로, 이후 편입 여부는 체인 런타임 최적화(BACKLOG) 후 재논의.

## 4. Out of Scope
- 텔레그램 단문 추출 (1,200자 필터로 자연 배제 — 짧은 글의 인과는 내러티브 종합이 흡수)
- narrative_edge_evidence로의 문서 근거 통합 (corroborated_by는 당분간 내러티브 수만 집계 —
  문서 출처는 source_doc_id로 추적 가능, 통합 카운트는 후속)
