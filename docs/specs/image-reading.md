# 이미지 해석 — 본문 속 차트·표를 '무엇을 말하려는가'로 바꿔 넣는다 (2026-10-23)

> 상태: **구현됨**. 관련: [link-scrap](link-scrap.md)(스크랩도 같은 경로) · SYSTEM.md §5 수집

---

## 0. 한 문장

**수집 문서 속 이미지를 저장하지 않고, AI가 읽은 "이 이미지가 전달하려는 메시지"를 이미지가 있던 자리에 텍스트로 넣는다. 그 텍스트는 AI 해석임을 표시해 저자의 말과 섞이지 않게 한다.**

## 1. 문제

| 항목 | 실측 (2026-10-23, 최근 30일) |
|---|---|
| 블로그·스크랩 이미지 | 하루 약 100개 `<img>` — 정규화(`get_text`)에서 통째로 사라짐 |
| 텔레그램 이미지 | 하루 약 52장 — `media/`에 저장되지만 본문에는 들어가지 않음. 이미지-only 글은 본문이 빈 문서 |
| 기존 비전 단계(`extract_events`) | 증시일정표만 catalysts로 적재, 그 외 해석은 버림. D-116으로 OFF |

차트·표가 글의 핵심인 경우가 많은데, 검색·대화·태깅·청크가 전부 그 부분을 못 본다.

## 2. 원칙

- **정확한 수치 판독이 아니라 의도 해석.** 실험(합성 차트 4종)에서 haiku의 수치 판독 오차는 값 범위의 약 1%로 이미 충분했고, 가상 눈금선을 그어 픽셀 위치로 환산하는 방식은 오히려 악화(이중축에서 축 혼동)했다. 그래서 산출물은 "핵심 메시지 + 받치는 근거 1~3개"다.
- **함께 게시된 글을 맥락으로 준다.** 실제 텔레그램 이미지 24장 비교에서 글을 함께 준 쪽이 저자의 의도(게시글이 짚은 대상)를 맞히고, 상품명 오인(3배 한국 지수 ETF ↔ SK하이닉스)을 피했다. 대신 글의 주장을 평가·반박하는 경향이 있어 프롬프트로 금지한다.
- **글을 그대로 옮긴 이미지는 skip.** 실데이터에서 보고서 표지·글 캡처가 본문과 같은 내용을 반복했다.
- **이미지 파일은 저장하지 않는다.** 원본은 원문 링크에서 본다. 해석에 필요한 동안만 임시 파일로 두고 지운다. (기존 `media/telegram/` 파일은 실험·백로그용으로 그대로 둔다.)
- **AI 해석은 표시한다.** 저자의 말이 아니므로 원문 인용·인과 추출의 근거가 되면 안 된다.

## 3. 산출 형식

이미지가 있던 자리(블로그: 해당 `<img>` 위치, 텔레그램: 그 이미지가 붙은 메시지 뒤)에 한 줄:

```
[이미지 해석·AI · 차트] DRAM 수출 단가 — 2020~25년 박스권을 벗어나 2025년 하반기부터 급등, 구조적 전환으로 읽힌다. (근거: 5,000~15,000$/kg 횡보 → 2026.7 약 68,000)
```

- 접두 `[이미지 해석·AI` 가 계약이다. 하류는 이 접두로 AI 줄을 식별한다 (`pipeline.image_reading.strip_ai_notes`).
- 정보 가치 없는 이미지(로고·밈·인물 사진·광고·장식)는 skip — 아무것도 넣지 않는다.
- 증시일정표(`kind=calendar`)면 이벤트를 catalysts에 적재한다(기존 vision 경로와 같은 `_insert_events`). 호출은 한 번.

## 4. 동작

```
connector.fetch ─┬─ telegram: 메시지별 이미지 URL → read_image(맥락=묶음 글) → markdown에 삽입 (raw_content는 원문 그대로)
                 └─ blog/scrap(html): normalize에서 <img> 자리 → read_image(맥락=제목+앞뒤 본문) → 치환
read_image: 캐시(image_readings) 조회 → 없으면 필터 → 임시 다운로드 → haiku 1콜(Read) → 캐시 저장 → 임시 파일 삭제
```

| 게이트 | 값 | 이유 |
|---|---|---|
| 관리자 플래그 `image_reading` | 기본 on | 끄면 이미지 해석 없이 예전처럼 텍스트만 |
| 신규분만 | 게시 7일 이내 (`IMAGE_READ_MAX_AGE_DAYS`) | 백로그는 별도 결정. RSS 창의 옛 글이 예산을 먹지 않게 |
| 실행당 예산 | 30콜 (`IMAGE_READ_BUDGET`) | 30분 체인 1회 상한. 일 유입 ~110장은 여유 |
| 문서 단위 원자성 | 문서의 미해석 이미지 수 > 남은 예산이면 그 문서는 이번엔 해석 안 함 | 해석이 나뉘어 들어가면 문서 해시가 여러 번 바뀌어 재태깅이 반복된다 |
| 문서당 상한 | 12장 | 이미지 수십 장짜리 글 한 건이 예산을 독식하지 않게 |
| 사전 필터(LLM 0) | 링크 미리보기·스티커·이모지·200px 미만·5KB 미만 | 블로그 `<img>`의 상당수가 장식 |
| 실패 | 캐시에 failed+시도 횟수, 3회까지 재시도 | 깨진 이미지가 예산을 영구히 먹지 않게 |

캐시 키: 텔레그램 `telegram/{채널}_{메시지}_{순번}`, 블로그 이미지 URL. 해석 결과가 캐시에 있으면 재수집 때 LLM·다운로드 없이 같은 텍스트를 만든다 → 해시가 안정적이다.

비용 실측(2026-10-23, 격리 runner `llm.run(tools=Read)`, 21콜): 호출당 $0.002(API 환산)·약 6.4초. 일 유입 ~110장이면 하루 약 $0.2·12분.

## 5. 하류 영향

| 경로 | 처리 |
|---|---|
| enrich·청크·검색·대화 | 해석 줄을 그대로 본다 (목적) |
| doc_claims 원문 인용 | AI 줄은 인용 후보 문장에서 제외 |
| doc_causal 인과 추출 | AI 줄을 지운 본문으로 추출 (문서에 "명시된" 인과만) |
| 문서 상세 | 본문에 접두와 함께 보인다 |

## 6. 같이 고친 것 — 블로그 줄바꿈

`get_text("\n")`가 모든 텍스트 노드 사이에 줄바꿈을 넣어, 네이버 본문이 빈 줄 82%였고 굵게·링크 같은 인라인 요소에서 문장이 끊겼다("이로 인해 \n국내 전체 일자리의 27%가…"). 블록 요소(p·div·li·h·tr·br…) 경계에서만 줄을 바꾸고, 제로폭 공백을 지우고, 연속 빈 줄은 하나로 접는다. 새로 수집·갱신되는 문서부터 적용된다.

## 7. 5-state

FE 변경 없음(본문 텍스트에 섞여 표시). 해석 실패·예산 초과는 해당 이미지만 빠진 상태(Partial)이며 다음 회차에 채워진다. 실행 결과는 `llm_calls`(job=`image_reading`)에 남는다.

## 8. 기각한 대안

- **가상 눈금선·레이어 분할로 판독** — 실험에서 정확도 악화. 의도 해석이 목적이라 수치 정밀화의 가치도 낮다.
- **이미지 파일 저장** — 용량은 감당 가능(연 수 GB)하나 원문 링크로 충분하고, 해석 텍스트가 있으면 검색·대화에는 파일이 필요 없다.
- **해석을 본문 밖 별도 필드로** — 하류(청크·검색·대화)가 모두 markdown만 읽어 각 경로를 다 고쳐야 한다. 자리 치환 + 접두 표시가 더 적은 변경으로 같은 효과.
- **sonnet** — 깨끗한 차트에서 정확도 차이는 미미하고 호출당 약 15배 비싸다.

## 9. 후속

- 텔레그램 미해석 백로그(~6,000장, `media/telegram/`)와 블로그 과거분은 별도 결정(야간 창·예산 상한).
- 줄바꿈 수정의 과거 문서 소급은 미적용(소급 시 해시 변경 → 재태깅·스터디 주석 위치 영향 검토 필요).
