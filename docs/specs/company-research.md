# 기업 상세: 개요 · 실적·사업 · 자료

2026-09-13 사용자 승인안 구현. 시각 참고는 `docs/prototypes/company-research-proposal.html`이며 최종 정보 깊이는 아래 계약을 따른다.

- 국내 `/analyze/:code/summary`: 사업 분류·확보된 사업부 정보, 가격·거래량, 최근 분기 핵심 실적, 최근 자료 3건. 이전 자동 브리프·기간 요약 생성 컴포넌트는 이 화면에서 실행하지 않는다.
- `/financials`: 최근 4·8·12개 분기 매출/영업이익 막대, 영업이익률 선, 수치 설명과 표, 사업부 구성. 전체 손익/재무상태/현금흐름표는 `view=statements`에서 확인. 기존 사업 데이터 관리·밸류에이션 경로는 유지한다.
- `/mentions`: 기업과 연결된 수집 문서 및 DART 공시. 제목·본문 검색과 출처 필터, 페이지네이션, 원문 읽기. 기존 공시 URL도 유지한다.
- 주가의 모든 보유 거래일에서 탐색 가능. `mode=research&date=YYYY-MM-DD`로 진입하면 가용 폭 900px 이상·높이 740px 이상에서 좌측 차트 60%, 우측 자료 40%(최소 360px). 작은 화면은 위아래 배치. 탐색 중 사업·재무 요약은 숨긴다. 기본 팔로우 레일은 접는다.
- 날짜·조회 기간·시작일·공개 기준·후속 자료·검색·출처·페이지·차트 표시 개월은 URL에 보존한다. 차트 인스턴스는 날짜 선택마다 재생성하지 않는다. 원문은 Radix Dialog로 열고 닫을 때 기존 목록 위치와 버튼 포커스로 복귀한다. 페이지 새로고침 시 수동 차트 확대/이동 상태까지 복원하는 기능은 후속 범위다.
- 미국 `/us/:ticker`도 개요/실적·사업/자료와 공통 차트 탐색을 사용한다. 기존 렌즈·월드모델은 명시적 상세 진입에서 유지한다. 코드가 없는 `/company?name=`은 주가를 지어내지 않고 개요/사업/자료만 제공하며 저장 프로필만 읽는다.

## 읽기 API와 시점

`GET /api/spine/feed/company-evidence`: company, market=kr|us, start/end(포함), cutoff=end|close, after, source, q, page, size. 기업 엔티티의 명시적 연결과 공시의 corp_code를 사용한다. 검색은 전역 top-k 후 필터가 아니라 기업 후보 안의 제목·본문 부분문자열 검색이다. 원문 미리보기는 저장 본문 앞부분이며 LLM 요약이 아니다. 동일 문서의 여러 엔티티 연결은 중복 제거한다. 서로 다른 문서의 같은 사건 묶기는 아직 하지 않는다.

- `published_at`만 사용하고 `fetched_at`을 대체하지 않는다. 시각 있는 값은 UTC로 비교하고 한국/뉴욕 날짜로 표시한다. spine의 기존 시각 없는 datetime은 UTC 저장 규약을 따른다. 날짜만 있는 문서와 DART 공시는 해당 시장의 날짜로 취급하고 시각 미상을 표시한다.
- 장 마감 기준은 KR 15:30, US 16:00이다. 뉴욕 DST는 ZoneInfo로 처리한다. 미국 조기 폐장일은 별도 거래소 캘린더 연동 전이므로 화면에 고지한다.
- 종료일 시각 미상 문서는 장 마감 기본 결과에서 제외한다. 이후 자료 옵션을 켜면 미확인으로 구분하여 제공한다. 이후 7일 자료도 명시적으로 구분한다.
- 미래/잘못된 공개일은 제외. 날짜 미확보 건수 및 소스별 보유 기간을 제공하되 완전성으로 표시하지 않는다. 조회 실패와 0건을 구분한다. React Query는 조건별 키와 취소 signal을 사용하며 다른 날짜 결과를 placeholder로 유지하지 않는다.
- 이 회사 자료 화면은 과거 자료 조사 목적상 저장된 소스 전체를 조회한다. 홈 피드의 구독/뮤트 노출 필터를 적용하지 않는다.
- `GET /api/spine/feed/company-prices`: 국내/미국 저장 주가 최대 1,500거래일. 수집·LLM 호출 없음.
- 새 개요/실적 차트는 `GET /api/financials/:code?stored_only=true`를 사용한다. 조회만으로 연도별 DART 일괄 수집을 시작하지 않는다. 일반 재무제표 상세 조회는 기존 수집 동작을 유지하며, `discovery` 맥락에서 연 상세도 `stored_only=true`로 읽는다. 필요한 수집은 명시적 조사 POST에서 수행한다.

## 재무 정확성

DART `finstate_all`의 분·반기 IS/CIS `thstrm_amount`는 이미 3개월 값이다. Q1~Q3을 그대로 사용하고 Q4는 연간−Q1−Q2−Q3로 계산한다. 중간 분기 누락 시 Q4를 만들지 않는다. CF만 누적 차감, BS는 시점 값. 근거: [DART 전체 재무제표 필드 정의](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020).

금액 결측과 0을 구분하고 손실을 0으로 자르지 않는다. 누락된 달력 분기는 빈 값으로 유지한다. 영업이익률은 양의 매출을 분모로 계산하며 매출 미확보/0에서는 산출하지 않는다. YoY는 동일 분기를 찾는다. 연결 우선/별도 폴백을 실제 응답 기준으로 표시한다. 사업부 조회는 연간 보고서만 사용한다. 비중이 모두 확보되고 합이 100%인 경우에만 도넛을 표시하며 그렇지 않으면 금액·비중 표만 제공한다.

## 확보 데이터에 따른 제한

사업부 테이블은 확인 당시 0건이다. 사업의 제품·고객 설명, 사업부 연결조정·출처, 미국 분기 재무/회계기간, 수출입 통계의 기업 및 발표시점 연결은 미확보다. 실제 값 없이 차트·내러티브를 생성하지 않는다. 국내 실적 설명은 계산된 사실만 제공하고 회사 설명·외부 해석은 원문으로 연결한다. 공시 수정 전 버전은 보유하지 않으므로 과거의 재무 값을 완전 재현한다고 표현하지 않는다.

### 조사 방식

선별된 이유와 사용자의 질문을 토대로 조사 의제를 만든다. 기업명뿐 아니라 제품·고객·경쟁사·수요 산업을 검색하되, 연결의 근거와 불확실성을 남긴다. 보유 자료를 검색하고 실제 원문/수치를 읽어 가설을 비교한다. 부족한 자료의 추가 확보는 통제된 수집 경로에서 수행하며 CodeAct에 운영 DB·수집 권한을 부여하지 않는다.

| 질문 | 재사용할 기존 경로 | 연결에서 확인할 것 |
|---|---|---|
| 시장에서 무엇을 말했나 | 기업 자료·통합 피드·수집 본문 검색·기대 변화 관측 | 화자·발행일·원문, 기존 견해 대비 변화, 재전파/중복. 수집 소스의 담론을 시장 전체 합의로 표현하지 않음 |
| 전방 수요 산업은 어떻게 변하나 | 사업/제품 정보·섹터 내러티브·인과 그래프 | 고객·최종 수요→제품/주문→기업 실적의 각 연결 근거. 그래프·생성 내러티브는 원문으로 확인할 조사 단서 |
| 최근 실적은 무엇이 달라졌나 | 저장된 국내 분기 재무·DART 공시·사업부 자료 | 회계기간·연결/별도·기저효과, 수치와 회사 설명 구분. 사업부/전망/컨센서스가 없으면 공백 표시 |
| 컨퍼런스콜에서 무엇이 달라졌나 | transcript 저장·요약·프록시 추출·관련 기업 자료 | 경영진 발언과 질문자 가정 구분, 실제 콜 날짜·전문 확보 여부, 직전 콜과 비교 가능 범위 |
| 수출입 통계가 뒷받침하나 | 품목별 trade_stats·HS 팔로우·관련 종목 제안 | 제품↔HS 코드 적합성·기간·금액/중량/단위·공개 시점. 국가/품목 통계를 기업 자체 수출·매출로 간주하지 않음 |

기업 고유 요인·업종 공통 변화·일시 수급 등 복수 설명을 비교한다. 주가 상승이나 언급 증가를 실제 순매수 또는 매수 동기로 치환하지 않는다. 직접 확인한 사실, 원문 작성자의 주장, 에이전트의 추론, 사용자의 판단을 구분한다.

과거 검색 시점의 조사와 현재 시점의 후속 조사를 명시적으로 구분한다. 문서의 발행일뿐 아니라 원문 사건일·확보 시점·수정 여부를 기록한다. 수집 시각이 공개 시각을 대신하는 소스는 당시 알려진 정보로 취급하지 않는다. 날짜 필터만으로 과거 시점의 완전성을 보증하지 않는다.

### 남길 결과와 후속 관찰

- **발견 기록:** 검색 실행·종목·조건·시점·선별 근거와 자료 한계.
- **조사 기록:** 질문별 읽은 원문·수치·범위, 주요 변화, 근거가 있는 설명·반대 근거·미확인 항목. 제목/요약만 읽은 자료와 전문을 확인한 자료를 구분한다.
- **사용자 판단:** 관심 이유, 핵심 가정, 판단을 바꿀 조건. 시스템 제안과 사용자가 채택한 기록을 분리하고 사용자 메모를 자동 재작성하지 않는다.
- **팔로우업:** 다음 실적/콜·산업 지표·수출입 발표·기술적 조건 변화 중 채택한 관찰 항목을 연결한다. 새로운 독립 근거가 무엇이며 기존 가설을 어떻게 바꾸는지 보여주고 이전 판단을 보존한다.

기존 스터디 프로젝트·질문/프록시·팔로우·촉매 기록 중 실제 계약이 맞는 경로를 재사용한다. 발견된 종목 전체를 자동으로 심층 조사하거나 추적에 편입하지 않는다. 사용자의 조사·저장·추적 선택은 별도 재확인 없이 해당 동작을 수행할 의도로 취급한다.

### 연결 전 자료 검증과 완료 기준

코드/테이블의 존재와 필요한 종목·기간의 자료 확보를 구분한다. 첫 구현에서 대표 기업으로 시장 자료→고객/전방→실적/콜→관련 통계 중 실제 연결 가능한 범위를 확인한다. 국내 기업의 콜 전문, 사업부 데이터, 제품/HS 매핑, 통계 공개일은 우선 점검 항목이다. 원문 발행 시점과 데이터 신선도, 동일 사건 중복, 상충 근거, 자료 없음/검색 실패도 검사한다.

Empty는 조사 전/근거 없음, Loading은 검색·원문 확인·정리 진행, Partial은 확인된 내용과 공백, Error는 원문·사용자 기록을 유지한 재시도, Ideal은 근거를 바로 열 수 있는 조사와 다음 관찰 항목을 제공한다. 첫 통과 흐름은 검색 결과의 종목 선택→발견 이유 보존→근거 원문 열기→질문/가설 저장→새 근거와 이전 판단 비교다.

### 2026-09-19 읽기 전용 연결 준비 점검

아래는 당시 코드와 `mode=ro`·`query_only` SQLite 조회 결과이며 데이터 품질 통과를 뜻하지 않는다. 이 설계 작업에서 데이터·파이프라인을 변경하지 않았다.

- 기업 연결 자료는 11,192개, 국내 재무는 49,377행이지만 12개 회사에 한정되고 사업부는 0행이다. 기업별 사용 가능한 원문·회계기간을 먼저 확인해야 한다.
- 컨콜은 미국 티커 중심 20종목·38건이며 활성 팔로우 33개 중 13개는 미수집이다. 한국 전용 콜 수집 경로는 확인하지 못했다. `pipeline/transcript.py`의 분기 근사 `call_date`, 수집 시각으로 넣는 문서 `published_at`, 선택적 yfinance 보정 때문에 시점 검증이 필요하다. 실제 미래 날짜의 콜 1건이 프록시 관측 4개에 전파돼 있어, 이 경로를 후속 시점 판정에 바로 연결하지 않는다. 원문 외부 URL도 38건 모두 미확보다.
- 수출입은 179 HS·10,238행(2021-09~2026-08)을 보유한다. 국가별 축·공식 공개일·수정 vintage가 없고, HS 2/4/6/10단위를 섞어 상위–하위 43쌍이 겹친다. `trade_metrics.table()`의 합계는 중복을 제거하지 않으며 `trade._num()`은 결측/파싱 실패를 0으로 바꾼다. 조사에 쓰기 전에 품목 범위·결측·집계 기준을 검사해야 한다.
- `trade.compute_beneficiaries()`의 기업 연결은 4개 HS에 대한 23개 논리 제안이며 실제 제품·매출 노출의 검증된 매핑이 아니다. `sector.sector_narratives()` 역시 공동언급에 기반하므로 전방 고객 관계의 증거로 사용하지 않는다.
- 질문 추적은 17개가 tracking 상태지만 16개의 numeric 판정이 unknown이다. numeric proxy 132개 중 12개, stance proxy 58개 중 0개에 관측이 있다. 기존 `_decompose_and_track()`은 DART·수출입 시계열의 직접 관측까지 연결하지 않는다. 원천이 없는 질문을 자동으로 추적 가능하다고 표시하지 않는다.
- `questions._confirm_edges()`는 질문의 종합 확인을 내러티브 전체 엣지에 확산할 수 있고, `rollup()`은 관측 시효·출처 독립성을 반영하지 않는다. 새로운 팔로우업에서는 주장별로 실제 관련 근거와 시점을 확인해야 한다. 현재 확인된 자동 확증 엣지는 0개다.

연결 구현 전에는 위 날짜·단위·결측·주장 귀속 문제를 먼저 보완하거나 해당 자료를 명시적 미평가로 분리한다. 전체 소스 정비가 끝날 때까지 기다리는 대신 검증된 기업·기간·원문부터 작은 경로를 연결한다.

### D-181 구현과 사용 경로

`AnalysisResults`의 ‘이 종목 조사’ → `/analyze/:code/summary?discovery=:caseId`에서 기존 SummaryPage 안에 `DiscoveryResearch`를 연다. 공개된 API에 조건이나 근거를 직접 보내지 않으며 서버가 독립 검증된 원 결과의 실제 후보에서 복사한다. 원 질문·패턴/식·기준일·스냅샷·선별 근거·미지원/미평가 경고를 유지한다.

`discovery_research.build_packet`은 읽기 전용 원본 트랜잭션·15초 쿼리 제한·영역별 제한된 발췌로 자료 묶음을 만든다. 문서 범위와 실제 문자 발췌·해시·출처를 저장한다. 시장/산업 검색을 고객 관계 확정으로 바꾸지 않으며 실적은 회계기간과 연결/별도·단위를 표시한다. 콜은 시점 미검증, HS는 라벨/기업 연결 미확정과 상하위 합산 금지·저장0의 원천 결측 가능성을 표시한다. 과거 시점에는 공개/확보 시점을 입증할 수 없는 수치·콜을 제외한다. 모든 자료의 독립성이나 원문 진위를 자동 보증하지 않는다.

조사 결과는 요약·fact/source_claim/inference/unknown별 주장과 실제 자료 인용·다음 질문·한계다. 사용자 기록은 관심 이유/가정/생각을 바꿀 조건/확인 질문으로 직접 작성하고 새 버전으로 보존한다. 연구는 그 요청 당시의 판단 버전을 참고하며 자동 재작성하지 않는다. 후속 비교는 직전 읽은 자료의 추가/제외/내용 변경이다. 원문 삭제·전체 뉴스의 신규성·가설 자동 확증과 구분한다.

전략/발견/판단/조사는 별도 `logs/market-discovery/discovery.sqlite`에 트랜잭션과 요청 멱등키로 보존한다. 단일 worker가 명시적 조사 요청만 실행하고 취소·중단 복구를 제공한다. 직접 원문을 열어 확인하고 기존 기업 자료/저장 실적/콜/수출입 화면으로 이동할 수 있다. 자동 스케줄 알림·기존 question/proxy의 자동 갱신·스터디 자동 편입·전체 원천 품질 정비는 후속 범위다.

실제 자료 확인: HPSP는 시장/산업 문서와 수출입 단서는 있으나 저장 실적·콜 부문이 비어 있음을 유지했다. 삼성전자·NVIDIA 관련 읽기 점검에서는 시장6/산업6/실적·공시8/콜3/통계3개를 확보해 5개 어댑터가 실제 자료를 읽는 것을 확인했다. 문서상의 기업 연결·통계 라벨은 검증된 사실로 승격하지 않는다. 검증된 기술적 발견의 호스트 작성 근거를 별도로 제공하고 MA의 최근 기간과 사건 이후 전체 기간을 혼동하지 않게 한다. 검증·실행 기록은 [시장 분석 §11](market-codeact.md#11-승인-기획-구현-계획-2026-09-19-진행)과 `logs/discovery-implementation/`에 있다.


### D-182 UX 개편과 자료 준비

- 후보의 `기업 조사` 한 번으로 발견 기록과 첫 조사를 접수한다. 같은 검색/종목/질문의 재진입은 기존 기록을 열며, 실패/취소 후 재실행은 ‘후속 조사·이력’의 명시적 액션이다.
- 기존 summary에 발견이 있으면 compact 발견 이유와 기존 가격 차트를 먼저, 이어 조사 결과·원문·내 판단을 보여준다. 일반 summary의 사업/분기 실적/최근 자료 구성은 유지한다. 기업 탭의 개요는 발견 맥락에서 ‘기업 조사’로 표시한다.
- 질문/기준일/조사 이력, 계산 근거, 인용 원문은 Sheet로 제공한다. 출처는 저장 발췌이며 외부 링크는 http/https만 허용한다. 내 판단은 넓은 화면에서 결과 옆에, 작은 화면에서는 같은 초안을 유지하는 탭에 둔다.
- 조사 준비 상태는 실제 자료별 확인/수집/보유/실패/미제공/자동 수집 제외를 구분한다. 준비 완료 시 재무 조회 캐시를 갱신한다. 콜과 품목 연결의 공백은 성공으로 가장하지 않는다.
- 기본 조사는 요청 시점의 한국 날짜로 고정한다. 검색의 마지막 거래일과 구분한다. 과거 연구는 새 수집을 생략하고, 수집일을 공개일로 대체하지 않는다. 새 재무의 접수번호/접수일/수집 시각을 보존하며 기존 수치는 덮어쓰지 않는다.
- 국내 DART 수집기는 최대 30요청/90초로 선택 기업만 준비한다. 기존 일반 조회용 DART 함수의 광역/오류 캐시 경로를 사용하지 않고 검증된 성공과 공식 미제공 응답만 별도 캐시한다. 공시 전문·최신 정정 전수 확인·국내 콜 커넥터 신설은 이번 범위에 포함하지 않는다.

구현 계약·검증: [시장 발견 §12](market-codeact.md#12-발견조사-ux-개편과-필요한-자료-준비-2026-09-19).

## 웹 조사 레인과 기업 개요 보고서 (2026-09-20, D-188)

사용자 결정: 웹 검색은 기업 조사에 먼저 붙이고(대화는 후속), 저장은 **발췌**만, 조사 시 "웹도 확인"은 기본 켠 체크. 초기 기업 조사에서 사업보고서·IR 자료·뉴스·리포트를 웹으로 조사해 **구조화된 기업 개요 보고서**를 만들고, 기업 페이지 "기업 개요"에 연결한다.

### 격리 원칙과의 관계
- 종목 발견 CodeAct(D-176)는 그대로 망이 끊긴다. 웹은 **신뢰된 호스트 수집기**(D-182의 재무·공시와 같은 자리)가 수행한다.
- 수집기는 `pipeline/llm.run(tools=("WebSearch","WebFetch"))`(스터디 웹 확인 D-159와 같은 경로)로 모델 1콜을 돌리고, 마지막 JSON만 받아 호스트가 검증한다. 조사 종합 모델(도구 없음)에는 다른 레인과 같이 읽기 전용 발췌로만 전달된다.

### 기업 개요 보고서 (`pipeline/company_profile.py`)
- 입력: 종목코드·기업명·업종·(있으면) 발견 이유. 출력 `WebProfile`: `overview`(한 문단), `business_lines[{name, description, share_pct?, source_ids}]`, `products_customers[{text, source_ids}]`, `competitors[]`, `drivers[]`, `risks[]`, `recent_events[{date, title, source_ids}]`, `sources[{id, url, title, publisher, published_at, kind: filing|ir|news|report|other, excerpt}]`, `gaps[]`(확인 못 한 것).
- 호스트 검증: URL 스킴 http(s)만, 존재하지 않는 `source_ids` 제거, 출처 0건이면 `unpublished`. 모델이 실제 WebFetch로 연 URL은 `fetched=true`로 표시한다(검색 결과 요약만 본 출처와 구분).
- 저장: `company_profiles`(종목코드·버전·생성 시각·모델·비용·payload) append-only. 출처 발췌는 `raw_documents(source_type='web', source_id='{code}:{sha1(url)[:16]}')`에 제목·URL·발행일·발췌로 INSERT OR IGNORE(본문 수집·태깅 없음). 이후 조사 패킷·대화·스터디가 같은 문서를 읽는다.
- 비용: 사용자 클릭 또는 조사 1회당 웹 호출 1번, sonnet, 180초. 24시간 안의 보고서가 있으면 재사용한다(`force`로 재생성).

### 공식 본문: DART '사업의 내용' (`pipeline/dart_business.py`)
- 웹 도구는 DART 뷰어(JS)를 열지 못해 첫 실측에서 공식 매출 구성이 gaps로 남았다. OpenDART 목록 API로 최근 400일 안의 최신 정기보고서(사업·반기·분기)를 찾고, `sub_docs`의 하위 문서 URL에서 사업의 개요·주요 제품·원재료·매출 및 수주·주요 계약·기타 절의 HTML을 받아 텍스트로 만든다(절당 9,000자·총 30,000자, 모델 호출 0, 1초 미만).
- 저장: `raw_documents(source_type='dart_business', source_id='{code}:{rcept_no}:{절}')`, 발행일=접수일. 같은 보고서가 있으면 재사용. 조사 패킷 `web` 레인이 web 문서와 함께 읽는다.
- 개요 보고서에서는 **출처 id 1로 고정**해 프롬프트에 `[공식 자료]`로 넣고(개요 전체 → 주요 제품 → 매출 순 12,000자), 모델에게 사업 구성·제품·고객·비중은 이것을 1차 근거로 인용하고 웹 검색은 IR·뉴스·리포트에 집중하라고 지시한다. 호스트는 모델 출력의 id 1을 공식 출처로 교체하고 `official_report`(접수번호·보고서명·접수일·뷰어 URL)를 payload에 남긴다. 확보 실패는 gaps 첫 줄에 사유로 남긴다.

### 미국 종목 (`market=us`)
- 같은 수집기를 `/us/:ticker` 도시에의 "기업 개요" 카드에 붙인다(`CompanyOverview market="us"`). API는 `?market=us`, 이름은 `resolve_us`(transcript_follow·entities)로, 없으면 티커 그대로.
- DART 단계는 없다. 조사 순서는 SEC EDGAR 10-K 'Item 1. Business'·10-Q → IR·실적 발표 → 최근 뉴스(영문 포함) → 애널리스트 의견 기사. 보고서는 한국어, 고유명사는 원문 표기, 금액은 USD 명시. EDGAR 본문을 호스트가 직접 받아 출처 1로 고정하는 것은 후속(DART 본문과 같은 방식).

### 조사 레인 `web`
- `pending_preparation`에 `web`(웹 조사 · 사업보고서·IR·뉴스·리포트) 항목 추가. 상태: pending → collected(새 조사)/available(24시간 내 보고서 재사용)/unpublished(출처 0)/failed/skipped(체크 해제)/unsupported(과거 기준일).
- 실행 위치: DART 수집(90초 예산) 뒤, `discovery_service._execute`가 별도 단계로 호출한다. 취소를 존중하고 실패는 레인 상태로만 남긴다(조용한 폴백 금지).
- 패킷: `build_packet` LANES에 `web`(웹 조사)을 추가하고 `raw_documents`의 web 문서를 발행일 기준으로 읽는다. 과거 기준일 조사에서는 공개일 미확인 발췌를 제외한다(D-182 공개일·수집일 구분).
