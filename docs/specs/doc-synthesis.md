# 문서 교차 종합 (Doc Synthesis) — 고른 문서들을 엮어 읽기

> 2026-08-13 기획. 사용자 요청: "저장한 문서들 중 원하는 것들을 골라, 여러 개를 엮어서 이게 의미하는 바 = 인사이트를 추출."
> 배경: 기존 종합은 전부 **앵커가 자동 선정**됨 — 질문 종합(D-093)은 질문 앵커, 다이제스트는 기간 앵커, 내러티브는 토픽 앵커.
> **"사람이 손으로 고른 문서 묶음"을 앵커로 하는 종합 층이 비어 있었다.**

## 관통 원칙

1. **사람이 앵커** — 무엇을 엮을지는 기계가 고르지 않는다. 저장됨(D-078)이 이미 사람의 큐레이션이므로 그 위에 선택만 얹는다.
2. **프레임이지 판정이 아니다** — 산출물 전체가 가설(PHILOSOPHY §1). 재료에 없는 것을 지어내지 않고, 미판정은 미판정으로. 인과 그래프·질문 트래커를 건드리지 않는다(read-only 격리 — 논지 감사 D-078의 규율 계승).
3. **일회성 + append-only** — 묶음을 관리하는 객체를 만들지 않는다. 선택 → 생성 → **결과만** 저장. 같은 조합 재생성은 새 행(히스토리).
4. **새 탭 0개** (D-013) — 진입은 기존 `/follow/saved`, 산출물은 아티팩트 디테일 라우트(`/question/:id` 선례).
5. **버튼 트리거** (D-093 ④) — 진입 시 자동 생성 없음. 사람이 누를 때만 LLM이 돈다.

## 데이터 모델

`doc_syntheses` (신규):

| 컬럼 | 타입 | 설명 |
|---|---|---|
| id | INTEGER PK | |
| doc_ids | TEXT | json 배열(정렬된 `raw_documents.id`) — 무엇을 엮었나 **스냅샷** |
| title | TEXT | LLM이 붙인 한 줄 제목 |
| body | TEXT | 마크다운 산출물 |
| model | TEXT | `claude-code/sonnet` |
| created_at | TEXT | |

UNIQUE 없음 — 같은 조합 재생성 = **새 행**(원칙 3). `question_reports`(body 마크다운 + model) 패턴 미러.

> doc_ids는 `saved_items.id`가 아니라 **문서 id 스냅샷** — 나중에 저장 해제해도 종합은 자기가 무엇을 읽었는지 안다.

## 산출물 구조 (body 마크다운)

> **층위 = 업황·판세** (D-105, 사용자 피드백). 개별 종목 투자 판단(밸류에이션·목표주가·그 회사만의 리스크)으로
> 좁히지 않는다. 자료가 특정 기업의 것이어도 그 기업은 **산업을 읽는 표본** — 이 사실이 산업의
> 수요·공급·가격·자본조달·경쟁구조 중 무엇을 어디로 움직이는 증거인가로 옮긴다.
> 단, 한 기업 이야기뿐이라 넓힐 근거가 없으면 **억지 일반화 대신 무엇이 부족한지** 말한다(정직 우선).

| 섹션 | 내용 | 규율 |
|---|---|---|
| (첫 문단) | **업황 한 줄 종합** 2~3문장 — 판이 어디로 가고 있는가 | BLUF (D-049) |
| `### 판의 구조` | 3~4개 — 각 항목이 산업의 수요·공급·가격·자본·경쟁 중 무엇을 어디로 움직이는지 | 근거 없는 축 금지 |
| `### 상충·긴장` | 자료 간 어긋나는 지점 + **주장 주체의 성격 차이**(자사 이해관계 1인칭 vs 제3자 관찰) | 없으면 "없음"이라고 정직히 |
| `### 업황이 던지는 질문` | 질문 2~4개 + **각 질문에 잠정 추론**. **산업 층위** — "이 회사 주가가 오를까"가 아니라 "이 구조가 지속되는가·무엇이 판을 뒤집는가" | 사용자 요청의 핵심 — 질문만 던지고 끝내지 않는다 |
| `### 감시 지표` | 무엇이 관측되면 확인되고 무엇이면 무효화되나 | 조건부 (PHILOSOPHY §3) |

**인용 = 자연어, 번호 참조 금지** (D-105). `[문서 1]`·"문서 2에 따르면"처럼 독자가 원문을 찾아가야 아는 표기는
쓰지 않는다 — 본문은 **그 자체로 완결된 콘텐츠**여야 한다. 출처는 자료의 성격(경영진 컨콜 발언·제3자 분석·
현직자 글·기자 보도) + 채널·작성자명 + 시점을 문장 안에 녹인다: "네비우스 2분기 컨콜에서 경영진은 …",
"AWS 2분기를 분석한 블로그는 …". 재료는 `resolve_channels()`(spine_feed 재사용)로 채널명을 프롬프트에 주입.

**모델 = sonnet.** 재료는 원문 문서(비구조화)지만 과제는 *제공된 텍스트 위의 종합·프레이밍*으로 D-093 결산과 같은 결. opus는 4단계 모델링(업사이드·시나리오·리포트 엔진)용으로 남긴다.

**출력 계약 = 마크다운**(JSON 아님, D-105). 첫 줄 `# 제목` + 이후 본문. 산문 + 따옴표 인용을 JSON 문자열로 받으면
이스케이프가 깨진다(실측: 개행·따옴표 각각 실패). 마크다운은 이스케이프가 없어 실패 유형이 사라진다.
※ 구조화 출력이 필요한 파이프라인(태깅·판정)은 JSON 유지 — **산문 산출물에만** 해당.

**입력 예산**: 문서 최대 12건 · 문서당 8,000자(초과 시 앞 6,000 + `…(중략)…` + 뒤 2,000 — 컨콜 Q&A·결론부 보존) · `markdown` 우선, 없으면 `raw_content`.

## API (`/api/spine/synthesis`, `routers/spine_synthesis.py`)

| 엔드포인트 | 기능 |
|---|---|
| `POST ""` | `{doc_ids: int[]}` → 종합 생성(sonnet, ~수십초) → 저장 → 단건 반환. 2~12건 검증 |
| `GET ""` | 목록 최신순(id·title·doc_count·created_at) — 재열람 경로, LLM 0 |
| `GET "/{id}"` | 단건 + 엮은 문서 메타(제목·유형·발행일) — LLM 0 |

## 화면

### 진입 — `/follow/saved` (SavedPage)
문서 행에 Checkbox(선택 모드). 2건 이상 선택 시 액션 바에 **"N건 엮어 종합"** → 생성 중 로딩 → 완료 시 `/synthesis/:id` 이동.
`kind='doc'`만 선택 가능(다른 kind는 체크박스 없음). 헤더 Sheet(compact)에는 선택 UI 없음.
페이지 하단 **"최근 종합"** 목록(최대 5건) — 일회성 산출물의 재열람 경로.

### 열람 — `/synthesis/:id` (SynthesisPage)
제목 · 생성시각 · **엮은 문서 칩**(→ `/doc/:id`, **번호 라벨 없음** — 본문이 번호를 안 쓰므로 가리킬 대상이 없다) ·
Markdown body · `SaveButton`(kind=`synthesis`) · 뒤로(저장됨).

### 5-state
| 상태 | SynthesisPage | SavedPage 선택 |
|---|---|---|
| Empty | 없는 id → ErrorState "종합을 찾을 수 없습니다" | 저장된 문서 0건이면 선택 UI 미표시 |
| Loading | Skeleton(제목+본문) | 생성 중 버튼 스피너·비활성 |
| Partial | 원문 삭제된 문서는 메타 없이 id만 표시 | 1건만 선택 시 버튼 비활성(안내) |
| Error | ErrorState + 재시도 | 실패 토스트 "종합 생성 실패 — 다시 시도" |
| Ideal | 문서 칩 + 5섹션 본문 | 카운트 + 활성 버튼 |

## 저장됨 확장 (D-078 후속)
`saved_items.kind`에 `synthesis` 추가 — 생성된 종합 자체를 다시 북마크(사용자 선택). BE 화이트리스트 + FE `SavedKind`·KIND_META 아이콘·필터 항목.

## Out of Scope
- 명명된 묶음·문서 추가·재종합(stale 가드) — 일회성 선택(사용자 결정)
- 질문 트래커 승격 · 인과 엣지 추출·승인 큐 — read-only 격리(사용자 결정)
- doc 외 kind(기업·내러티브·리포트) 혼합 종합 — 재료 수집 경로가 다름
- 종합 삭제·검색·정렬
