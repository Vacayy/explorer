# 리포트 엔진 v2 — 다중 에이전트 리서치 (analyst 팀 → bull/bear debate → 리드 판정 → 섹션 작성)

> 2026-07-21. 상태: 착수(풀 B~F). 배경: v1 리포트가 단선 종합이라 빈약하고, 레이팅이 기계적
> RS→Sell 오버라이드(맥락맹)였다(사용자 2026-07-21). 착안: TradingAgents(analyst팀·bull/bear
> debate·research manager·risk). 우리 규율에 맞춰 자동매매 대신 **리서치 리포트**로 앉힌다.

## 관통 원칙 (사용자 2026-07-21)
1. **기술지표는 맥락에서만 의미** — RS/MA/볼린저는 임계값이 아니라 **국면**(신고가 돌파·과열·건강한 조정·
   바닥)으로 해석. 하이닉스式: 펀더 견고 + 쏠림 해소로 RS 급락 = Sell 아니라 재진입 여지일 수 있다.
   → **레이팅은 결정적 임계가 아니라 종합 판단의 산물**(리드 애널리스트가 부여).
2. **상상은 살리되 확률론+리스크와 한 몸** — 좋은 투자자 = 확률론적 사고 + 리스크 관리 + 타율 높은
   상상력. 업계 리더의 의지(방향성)를 근거로 미래를 당겨오되 **강세 상상은 약세 반론과 함께**(debate).
3. **상상엔 틀이 필요** — 미래 시나리오를 모델링 수준으로(TAM→침투율 곡선→ASP→미래이익→해자→멀티플).
   현재 매출 없는 산업(로봇 등)도 프레임으로 call 가능. v1은 프롬프트로 허용(별도 TAM 에이전트는 후속).

## 파이프라인 (`pipeline/report.py` v2, 연쇄 LLM, 캐시)
A. **자료 수집(기존)** — 앵커 + 공유 이웃 내러티브 + scenario(±보강) + 종목 다각도 집계 + 정량.
B. **애널리스트 팀**(각 1콜, sonnet — 전 종목·산업 커버):
   - 펀더멘털: 재무 앵커·리레이팅·업사이드
   - 기술: RS·이동평균(20/60/120)·볼린저 → **종목별 국면 판정**(맥락 해석, 원칙1)
   - 수급·심리: 언급 모멘텀·쏠림
   (뉴스=내러티브가 담당, 별도 콜 없음)
C. **리서처 debate**(각 1콜, sonnet):
   - Bull: 강세 목차 + 근거 태깅 + 틀있는 미래 상상(원칙2·3)
   - Bear: 상충 약세 목차 + 근거 (Bull과 충돌 논리 우선)
D. **리드 애널리스트**(1콜, opus, research manager): 애널리스트+debate 종합 → 최종 판정 —
   overall thesis · **종목별 레이팅**(맥락 판단, 임계는 어휘 가이드) · **섹션 목차**(제목+브리프+근거태그).
E. (후속) 미래 모델링 전용 에이전트 — v1은 D/Bull 프롬프트의 프레임 허용으로 대체.
F. **섹션 작성**(목차 파트마다 1콜, sonnet): 각 섹션을 근거에 기반해 서술 → 조립(A4 2~3p).
G. **적재** — `reports`(body=조립 리포트) + **`debate_json`**(analyst 요약·bull·bear·레이팅 — 검증
   산출물 보존·열람, 사용자 요건). members_hash 멱등 캐시.

## 레이팅 (원칙1 반영)
어휘: **상승여력 ≥50 Strong Buy · ≥15 Buy · 이하 Hold · 위험/추세훼손 Sell** (사용자 정의).
그러나 **부여 주체는 리드 애널리스트**(펀더+기술 국면+수급을 확률론적으로 종합) — v1의 기계적
warning→Sell 오버라이드(`_rating`) **폐기**. 하이닉스 반례를 통과해야 한다(건강한 조정=Sell 아님).

## 프론트 (검증 산출물 열람)
ReportView: 본문(2~3p) + 종목 레이팅 배지 + 구성 내러티브. + **논쟁·분석 디스클로저**(접이식):
Bull 논지 / Bear 논지 / 애널리스트 요약 — 리포트가 어떻게 벼려졌는지 보이게(debate_json).

## 비용·검증
콜 ~11개(analyst3+debate2+리드1+섹션~5) → 리포트당 10분+. opus는 리드 1콜만, 나머지 sonnet로 비용·
시간 절감. 대상 종목 M≈4. **검증은 백그라운드 실행 → 완료 시 DB 적재**(중간 타임아웃 방지, 산출물 보존).
