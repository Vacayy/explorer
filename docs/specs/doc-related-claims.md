# 문서 상세 관련 자료 — 논점별 관련 자료 + 유사도 기반

상태: 구현(2026-10-14, D-233). 유사도 기반 목록은 D-221.

## 목표

자료를 읽은 뒤 "이 주제로 더 넓혀 보고 싶다"는 흥미로 다음 자료를 누르게 한다. 평평한 유사 문서 목록은 '왜 관련 있는지'가 보이지 않아 약한 연결(같은 장르의 긴 대담끼리 0.8 이상)이 엉뚱해 보였다. 같은 자료라도 **"이 자료의 어떤 논점을 이어 가는가"** 한 줄 아래 놓이면 확장으로 읽힌다.

## 화면 (문서 상세 `/doc/:id` 본문 아래)

```
이 자료의 논점별 관련 자료
‘AI 투자의 병목은 GPU에서 전력·인허가로 옮겨 갔다’는 논점
  · [텔레그램] 제목 ……………………… 채널 · 날짜
    “찾은 대목의 원문 문장”
  · …
‘…’는 논점
  · …
유사도 기반 관련 자료
  · [블로그] 제목  [겹치는 종목·인물·산업]   채널 · 날짜
```

- 논점 = LLM이 뽑은 해석(“~는 논점”으로 표시). 관련 자료 아래 인용 = **찾은 대목의 원문 문장**(LLM 작성 아님) — 자료가 말한 것과 해석의 구분(PHILOSOPHY §1).
- 논점에 나온 자료는 유사도 목록에서 뺀다. 유사도 목록은 최대 3개.
- 맞는 자료가 없는 논점은 숨긴다. 논점이 하나도 남지 않으면 "충분히 맞닿은 다른 자료를 아직 찾지 못했습니다".

### 5-state

| 상태 | 표시 |
|---|---|
| Empty | 논점·유사도 모두 없음 → 카드 자체를 숨긴다. 짧은 자료(600자 미만)는 논점 없이 유사도 목록만(`skipped`) |
| Loading | 처음 열 때 자동 생성(`status=none` → POST). 만드는 동안 스켈레톤 + "논점을 정리하고 관련 자료를 찾는 중", 3초 폴링. 유사도 목록은 먼저 보인다 |
| Partial | 논점 생성 실패 + 유사도 목록 있음 → 실패 문구·다시 시도 버튼과 유사도 목록 함께 |
| Error | `failed` — 사유(리랭커 미가용·LLM 실패)와 다시 시도 |
| Ideal | 논점 1~3개 × 자료 최대 2개 + 유사도 목록 |

## 생성 (`backend/pipeline/doc_claims.py`)

1. **논점 추출** — haiku 1회, 본문 앞 12,000자. 논점 1~3개: `claim`(40자 이하 평서문, 다른 회사·산업으로 이어지는 주장 — 이 자료의 사실 요약·일반론 금지), `query_ko`, `query_en`(영어 자막·컨콜도 찾기 위해).
2. **논점별 검색** — `rag.retrieve_docs(query_ko, variants=[query_en, claim])`(대화 검색과 같은 청크 하이브리드 + 리랭커). 리랭커 점수 **−1.0 미만 제외**(2026-10-14 문서 5개×2회 실측: −1.0~−1.2는 엉뚱한 자료가 더 많음). 제외: 자기 자신, **같은 실적 발표**(같은 티커의 컨콜↔보도자료 ±3일 — 수집 때 기록한 티커·발표일로 판정), 앞 논점에 이미 나온 자료, 앞에서 나온 것과 같은 인용 문장(재게시·A/S 글). 미검증 스크랩은 `retrieve_docs` 기본 규칙대로 제외. 논점당 최대 2개.
3. **인용 고르기** — 찾은 청크의 문장 중 리랭커로 논점과 가장 맞닿은 문장. 저자 소개·구독 안내·저작권 문구와 표 행(`|`·`●` 2개 이상)은 문장 후보에서 뺀다.
4. 리랭커가 없으면 기준을 적용할 수 없어 `failed`로 남긴다(조용한 degrade 금지 — 리랭커 캐시 사고 D-232).

저장 `doc_claims(doc_id PK, content_hash, status, token, payload, error, model, updated_at)`. 원문 해시가 바뀌면 `none`으로 보고 다시 만든다. `running`이 10분 넘으면 `failed`. 관련 자료의 제목·채널·날짜는 조회 시 붙인다.

## API

- `GET /api/spine/doc/{id}/claims` → `{status: none|running|ok|failed|skipped, error, claims:[{claim, related:[{id, source_type, title, published_at, channel, quote, score}]}]}` — 저장분만, LLM 0.
- `POST /api/spine/doc/{id}/claims` → 202 `{status}` — 없거나 실패·원문 변경이면 백그라운드 생성, 진행 중·완료면 그대로.

## 비용·지연

문서를 처음 열 때만 haiku 1회(이후 저장분). 생성은 논점 추출 10~20초 + 논점별 검색·리랭크 수 초. 피드 목록·홈은 만들지 않는다(열람 이벤트 기반 — 비용 의식 설계).

## 알려진 한계

- 리랭커가 완벽하지 않다 — 기준 위에도 엉뚱한 자료가 가끔 남고(실측: 배달 플랫폼 논점에 은행 대출 기사 −0.89), 기준 아래로 관련 자료가 빠지기도 한다.
- 논점은 LLM 결과라 같은 자료도 생성마다 조금 다르다. 저장 후에는 고정.
- 긴 컨콜·영상은 앞 12,000자에서 논점을 뽑는다.
- 코퍼스에 이어 읽을 자료가 없으면 논점이 숨는다(2008년 피터 틸 인터뷰처럼).

## 후속 (P1)

관계 표시(같은 주장 보강 / 반대 관점 / 한국 사례 / 최신 업데이트 — 논점별 후보를 haiku 1회로 분류), 오래된 저장분의 재검색(새 자료 반영).
