# Peer 그룹 탐색

상태: 5차 구현 — 그룹 프리셋·전체 종목 비교·자동 기준·세부 사업군 비교. 98기업·61분류·정기 수집 연결, 원전·조선 각16기업, 자동 신호는 검증 대기.

## 목적과 범위

`/discover/peers`에서 조사된 기업을 제품·공정 및 밸류체인 그룹으로 탐색한다. 그룹은 연구자의 분류 판단이며 회사 전체의 직접 경쟁 관계를 의미하지 않는다. 제품, 사업 중첩의 한계, 공식 근거 링크, 조사 기준일을 함께 제공한다.

첫 단계는 버전 고정된 공개 사업근거 카탈로그를 앱에 포함한다. 개인의 내부 언급·관심·거래 기록과 우선순위는 카탈로그에 포함하지 않는다. 조회 시 외부 수집·DB 변경·AI 호출이 없다. 데이터를 새로 반영하려면 검증 후 카탈로그 파일을 갱신한다. 실시간 데이터처럼 표현하지 않는다.

## 화면 계약

- URL: `group`은 그룹 ID, `q`는 기업명·코드·제품 검색어. 검색어와 그룹을 동시에 적용한다.
- 그룹 목록은 검색에 따라 사라지지 않는다. 그룹별 숫자는 전체 편입 수, 결과 숫자는 필터 통과 수다.
- 유효하지 않은 그룹 URL은 전체 그룹으로 조용히 바꾸지 않고 찾을 수 없음을 표시한다.
- 구성 종목에서 기업 분석으로 이동하며 원래 URL은 브라우저 뒤로 가기로 복원 가능하다.
- 그룹별 비교 목적과 주의점, 종목별 제품·그룹·원문 주장·출처·기준일을 표시한다.
- 소속 그룹을 여러 개 허용하고 목록 결과에서는 기업을 중복 계산하지 않는다.
- 세션이 확인된 가격의 탐색 비교만 제공하며, 기업행사 조정 검증 전 자동 신호는 제공하지 않는다. 알려진 기준가 불연속을 횡단하는 수익률은 미평가한다. 그룹 규모만으로 신호 준비 완료를 표현하지 않는다.

## 상태

- Loading: 카탈로그 로딩 상태와 skeleton.
- Empty: 조사 데이터 없음, 검색 0건, 존재하지 않는 그룹을 구별하고 초기화 제공.
- Partial: 조사된 사업 소속은 보여주되, 매출비중·직접 경쟁 여부와 가격 신호의 미확정 상태를 표시.
- Error: 스키마 검증 실패 또는 청크 로드 오류를 보여주고 재시도 제공.
- Ideal: 검색·그룹 선택·근거 열람·기업 분석 이동. 항상 스냅샷 기준일과 현재 지원범위를 표시.

## 데이터와 검증

`frontend/src/data/peer-catalog.json`은 공개 근거만 포함한 배포 스냅샷이다. `frontend/src/lib/peerCatalog.ts`가 Zod 구조 검증과 코드/그룹 ID 유일성, 참조 무결성, 근거 URL 프로토콜을 검사한다. 종목별 `groupIds`가 단일 소속 원본이며 그룹별 숫자는 이 값에서 파생한다. 타입은 `frontend/src/types/peer.ts`, 읽기 훅은 `frontend/src/hooks/usePeerCatalog.ts`에 둔다.

공개일이 미확인된 사업페이지는 조회 기준 근거로만 사용한다. 과거 편입 여부나 시점별 백테스트 근거로 사용하지 않는다. 자료 출처와 연구자의 그룹 판단을 분리한다.

## 후속 범위

기업행사·조정가격·공식 거래일 검증 → 주기적 스냅샷 수집 → 앞으로 누적한 관측으로 상향 전환·훼손 사건. 이 단계에서는 API·DB·외부 알림·거래 기능을 만들지 않는다.

## 2차 구현 계약 — 정규장 종가 탐색 비교

Naver 공식 서비스 일별 응답의 `regularMarketClosingPrice`와 시간외 포함 `closingPrice`가 다름을 확인했다. 전자는 41개×61일에서 Yahoo close와 일치했다. 세션 필드 확인과 기업행사 조정 검증은 별개의 상태다.

이제 명시적 정규장 종가 필드를 고정한 스냅샷에 한해 **탐색용 가격변동률**과 비교 차트를 제공한다. 기업행사 조정은 미검증이므로 배당 포함 총수익·전략 성과·자동 신호로 표시하지 않는다. 최신 원천 재조회로 수정될 수 있는 값의 수집 시각·내용 지문·출처를 저장한다. 기존 운영 시세 DB는 덮어쓰지 않는다.

- `view=performance|research`, `days=5|20|60`, `group`, `benchmark`, `stock`을 URL에 보존. 기본 화면은 성과 비교. 검색 `q`는 사업근거 화면에서만 적용되며 가격 비교 모집단을 바꾸지 않는다.
- 그룹 간 표는 기간 시작 동일가중 바스켓의 기간 수익률, 중앙값, 상승 종목 수와 선택 기준 그룹 대비 차이를 제공한다. 시장 지수가 없는 상태에서 기준 그룹을 시장으로 부르지 않는다.
- 그룹을 선택하면 종목별 절대·자기 제외 Peer 초과수익률과 기간 내 순위를 보여준다. 결측 구성원을 빼서 기준선을 다시 만들지 않는다. 그룹 중 한 종목이라도 필수 관측이 없으면 그룹 수익률·Peer 기준선은 미평가한다.
- 비교 차트는 시작값100, 그룹·선택 기준 그룹·선택 종목 최대3선. 동일 가격 스냅샷과 기간을 사용한다. 표의 수익률과 마지막 차트값이 일치해야 한다.
- 1개 기업 그룹은 개별 가격변동만 표시하고 Peer 대비는 미평가. 소규모 그룹에서도 순위는 실제 분모를 표시한다. 중복 기업은 각 그룹 내1회, 두 그룹의 중복 수를 별도로 표시한다.
- 현재 그룹으로 과거 구간을 다시 본 탐색이며 과거 당시 존재한 분류/실행 가능한 전략으로 표현하지 않는다. 자동 알림은 항상 비활성. 기업행사·거래정지·그룹 독립성 검증과 앞으로 누적한 관측이 후속 조건이다.
- `frontend/src/data/peer-prices.json`의 정규장 필드 스냅샷을 엄격 검증해 읽는다. 일자는 정렬·유일, 시계열 길이는 날짜 수와 일치, 가격은 양의 유한수 또는 null. 결측은0으로 치환하지 않는다. 기업별 미수집·오류는 null/부재로 유지한다.
- 상태: 스냅샷 로딩 skeleton, 청크/스키마 오류 재시도, 유효기간 부족/미수집/존재하지 않는 그룹 각각 설명, 가격비교 정상일 때도 기업행사 미검증과 날짜 한계는 표시.

- `overview=groups|candidates`, `scope=all|product|value_chain`, `relative=over|under`도 URL에 보존한다. 상대 강약 후보는 유효한 가격 관측을 가진 3개 이상 구성의 제품·공정 그룹에서만 조회한다. 종목–그룹 관계별로 표시하되 고유기업 수를 따로 보여준다. 이는 기간 단면 조건이며 발생 사건·알림과 구분한다.
- 61기업의 3,721개 정규장 관측에서 에코프로비엠 2026-09-03 기준가 불연속을 발견했고 공식 공시로 유상증자 권리락임을 확인했다. 이 날짜를 횡단하는 60일 종목·소속그룹 성과는 미평가한다. 임의 조정계수를 만들지 않는다. 가격 파일의 `qualityIssues`에 근거와 사건일을 보존한다.
- 갱신: 검토된 연구 산출물에서 `scripts/research/build_peer_price_snapshot.py --input <regular_prices.json> --audit <continuity_audit.json> --event <공식행사근거.json>`로 정규장 가격만 내보낸다. 코드명·일자·관측길이·기준가/등락식 검사를 통과해야 하며, 화면 조회에서 수집하지 않는다.

## 3차 구현 계약 — 정기 수집과 전진 관측 저장

- `scripts/refresh_peer_monitor.py`는 카탈로그의 전체 기업을 Naver 명시적 정규장 일별 필드로 수집한다. 외부 호출은 기존 cache_service의 TTL 확인→검증된 payload 로컬 저장→TTL 기록 순서. 캐시 키는 KST 날짜별이며 TTL 15분이다. 기존 시세 테이블은 쓰지 않고 캐시 메타와 운영 job_runs만 갱신한다.
- `scripts/research/peer_monitor.py`는 순수 검증·계산·원자적 게시를 담당한다. 전체 종목의 최근61일 날짜가 일치해야 게시한다. 정규장 종가-기준가격=등락가격 및 등락률 허용오차0.011%p를 검사한다. KST16:30 이전 당일 자료를 제외하고, 최신 관측이7달력일보다 오래되면 실패 처리한다. 이는 공식 거래일 검증을 대신하지 않는다.
- 전일 정규장 종가와 당일 기준가격 불일치, 거래량0은 품질 이슈로 남긴다. 알려진 공식 기업행사 근거는 보존하며 자동 조정하지 않는다. 관측20일 구간에 품질 이슈가 있는 기업이 하나라도 있으면 그룹 전체 상대성과는 미평가한다.
- 저장은 `logs/peer-monitor/`: `raw/<hash>.json` 원응답, `snapshots/<key>.json` 변경 불가 묶음, `current.json` 마지막 정상 게시본, `attempts/` 시도 이력과 `last-attempt.json` 최신 수집 상태. 전체 수집·게시를 flock으로 직렬화한다. 파일 fsync·원자적 replace로 가격·카탈로그·관측 상태를 함께 게시한다. 실패 시 정상본은 유지한다.
- 내용 멱등 키는 전체 카탈로그 내용 지문·가격/품질 버전·계산정책 버전이다. 게시 이력 키에는 부모 게시 키도 포함해 A→B→A 정정을 보존한다. 동일 키는 skip. 같은 날짜의 가격 정정·과거 겹친 가격의 수정·카탈로그/정책 변경은 유지일 수를 초기화한다. 원천 관측일 기준 중간 수집 공백도 연속으로 세지 않는다. 과거 가격일로 역행하지 않는다.
- 최초 실제 실행 KST일을 baseline으로 고정하고 그 이후 관측만 누적한다. 최초 이력으로 과거 사건을 생성하지 않는다. 제품 그룹3기업 이상에서 자기 제외20일 초과수익률 ±3%p 조건과 관측 유지일 수만 저장한다. **이 숫자는 신호가 아니다.** 기업행사 조정·공식 거래일·그룹 독립성 검증 전 `signalStatus=held`, `events=[]`를 유지한다.
- launchd의 `peer`는 로컬시간 평일20:30이다. KST 운영환경을 전제로 하며 `install_launchd.py --only peer`로 다른 잡을 재등록하지 않고 설치/제거한다. 기존 catchup을 통해 예정 시각 이후6시간 안에서 재시도하고 peer_refresh 운영 이력에 결과를 기록한다. 파일에도 실패 이력을 보존한다. 브랜치 전환으로 스크립트가 사라지는 체크아웃에서는 잡을 제거해야 한다.
- 런타임 수집 결과의 읽기 API와 화면은 아래4차 계약으로 연결했다. GET이 수집이나 관측 누적을 유발해서는 안 된다.

## 4차 구현 계약 — 읽기 API와 화면 연결

`GET /api/peers/runtime`은 Pydantic PeerRuntime 계약으로 저장된 카탈로그·가격·수집 상태를 한 번에 반환한다. current.json이 없는 설치만 배포 JSON으로 초기화 표시하며, 손상 파일은503으로 실패한다. GET은 수집·가격 DB 쓰기·관측 누적을 하지 않는다. 앱은 하나의 query에서 가격과 카탈로그를 함께 렌더한다. 초기본/수집본, 가격일·게시시각·달력일 경과·마지막 시도 실패를 표시한다. API 갱신 실패는 QueryState로 이전 결과를 유지한다. 조정 검증 전 자동 신호 held 정책을 유지한다.

카탈로그는71기업·46분류로 확대한다. 은행 금융지주4사·증권3사·플랜트 EPC3사. 지주회사 비은행 노출·증권 해외/IB 구성·건설 주택/토목 겸업을 명시하고, 과거 공시는 최신 사업비중 근거로 사용하지 않는다.

## 5차 화면 계약 — 그룹 프리셋 우선

- 기본 진입은 전력 인프라 프리셋. 주요 산업/그룹 버튼 클릭 시 전체 구성 종목 정규화 차트·5/20/60일 가격변동률 표·기간 선택에 따른 자기 제외 Peer 대비·세부 사업군 비교를 즉시 제공한다. `overview=groups|candidates`로 전체 비교/후보 화면을 유지한다.
- 자동 기준: 구성 기업 전부가 포함되는 명시적 상위 밸류체인을 우선한다. 상위 그룹 또는 상위 분류가 없는 그룹은 자기 그룹 동일가중 기준선. 시장 지수 미연결 상태를 명시하며 자동 기준을 시장 성과로 표현하지 않는다. 사용자 benchmark override는 비교 설정 안에서만 조작한다.
- 그룹을 바꾸면 benchmark·stock·settings를 초기화해 새 프리셋을 적용한다. 기간은 유지하고 브라우저 뒤로 가기로 이전 설정 복원. 직접 URL의 잘못된 그룹/기준/종목은 명시 오류 안내를 유지한다.
- 전체 종목 선은 기본 모두 표시. 가격 결측/기업행사 차단 종목은 미평가로 남기고 표에서 삭제하지 않는다. 종목 이름 버튼 또는 표의 강조 버튼으로 선을 강조하며 선택은 stock URL. 색상과 선 굵기·점선을 함께 사용한다. 수십 종목 범례는 차트 바깥에서 스크롤한다.
- 비교 설정은 shadcn Collapsible, 열림은 settings=1. 기존 기준 그룹 선택·개별 종목 강조와 전체 그룹 선택 유지. 자동으로 돌아가기 제공.
- Empty/Loading/Error는 기존 QueryState, Partial은 차단 구성원/그룹 기준선 미평가와 자동 기준 한계를 표시. Ideal은 설정 없이 그룹 클릭만으로 전체 비교가 보인다. 조사된 구성 종목 수를 명시하며 관련주 전수 수집으로 표현하지 않는다.


## 원전·조선 커버리지 확장 계약

- 외부 테마 목록은 조사 후보이며 자동 편입 근거가 아니다. 공식 제품·사업·공시에서 연관 사업을 확인한 기업만 추가한다. 제외·보류와 그 근거도 조사 기록에 남긴다.
- 원전은 별도 밸류체인 프리셋으로 제공하며 설계·시공, 주기기·부품, 계측·제어, 정비 등 역할을 구분한다. 조선은 기존 그룹을 유지하면서 조선소, 엔진, 보냉재, 기자재·서비스로 확장한다. 세부 제품군의 부분 사업 중첩을 전체 기업 직접 경쟁으로 표현하지 않는다.
- 상장 지주회사·자회사 중복 노출 및 여러 산업에 공급하는 기자재의 매출 노출 한계를 종목별로 명시한다. ETF는 기업군 동일가중 산식에 편입하지 않는다. ETF 기준선 추가는 구성·비중·추적지수 검증 후 별도 계약으로 다룬다.
- 공개 검토 추가본을 `scripts/research/build_peer_catalog.py --extension`으로 병합한다. 기존 기업의 그룹·사업근거를 유지하며 같은 코드를 중복 생성하지 않는다. 카탈로그와 전체 구성원의61일 가격 검증을 통과한 묶음을 함께 게시한다. 분류 변경 시 유지일 수는 기존 정책대로 초기화하며 자동 신호는 계속 보류한다.

검증된 확장: 원전16기업(신규14, 기존 건설2), 조선16기업(신규13, 기존 조선3). 전체98기업·61분류. 원전4후보 및 조선4후보 보류, 아스테라시스 조선 제외, ETF3개는 참고 후보로만 기록한다. 원전 기자재·구조물은 이질적인 역할 관찰군이며 직접 제품 Peer로 해석하지 않는다. 우진엔텍의2026-10월 거래량0 기록을 횡단하는20/60일 원전·정비 그룹은 미평가한다.
