# 포트폴리오 인텔리전스 — 공통 변수·논지 감시·자료 흐름·다가오는 이벤트

상태: P0 구현(2026-10-08, D-216) — 공통 변수·다가오는 이벤트·자료 흐름·논지 감시. §5 운용 원칙·§6 관심 이유 감시 추가(2026-10-14, D-227). 테스트 `tests/test_portfolio_{exposure,events,flow,thesis,alerts}.py`. 원장·수익률·알림 계약은 [포트폴리오 거래 원장](portfolio-ledger.md)(D-212·D-214)을 따른다. 이 문서는 그 위의 네 기능만 다룬다. 프라이버시 계약(금액·수량 비노출, AI 입력도 비율·가격만)은 그대로 적용한다.

## 왜

수익률 표는 "얼마나 벌었나"만 말한다. 투자자에게 필요한 건 ① 내가 실제로 무엇에 베팅하고 있나 ② 산 이유가 아직 유효한가 ③ 시장이 내 종목을 어떻게 이야기하나 ④ 앞으로 무슨 일이 예정돼 있나다.

## 1. 공통 변수(노출)

보유 종목들이 함께 기대는 변수와 그 변수에 걸린 비중을 보인다. **결정적 계산, LLM 0.**

출처 세 가지를 합치고 화면에 출처를 배지로 표시한다(조사 결과 인과 그래프 커버리지가 종목마다 크게 달라 단일 출처로는 빈다).

| 출처 | 방법 | 신뢰 |
|---|---|---|
| 인과 그래프 | 회사 노드와 이름이 `{회사명}`으로 시작하는 사건 노드로 들어오는 CAUSES(+역방향 BENEFITS_FROM), 2단계까지. `source_status`가 document·verified인 간선만, 경로 신뢰도 곱 ≥ 0.2 | 방향(+/−)은 테마·사건·매크로·정책만 표시 |
| 문서 동시 언급 | 최근 180일 보유 종목과 같은 문서에 붙은 topic/industry 엔티티. 문서당 1/(그 문서의 종목 수) 가중(시황 나열 글 억제), 점유 ≥5%·향상도 ≥2.5·문서 ≥3, 글 성격 태그(산업동향·수급·실적분석 등) 제외 | 방향 없음 |
| 밸류체인 | 동시 언급 주제가 겹치는 체인 그룹. 단계는 업종 분류(`industry_members`)가 있을 때만 — 주제로 단계를 추측하면 후공정 기업이 '제조'로 잡힌다 | 구조 |

노출도 = 그 변수에 연결된 보유 종목들의 비중 합. 정렬: 걸린 종목 수 → 노출도 → 출처 수 → 단계(1단계 우선) → 신뢰도. 화면: '공통 변수' 카드 — 변수 이름 · 노출도 막대 · 연결 종목 · 출처 배지 · 수혜/부담 요인. 상위 8개(15개까지 펼침). 인과 그래프 연결이 없는 종목은 카드에 그 사실을 적는다.

API: `GET /api/portfolio/exposure` → drivers[name·entity_id·type·exposure_pct·holdings[code]·sources[graph|comention|chain]·direction?].

## 2. 논지·반증 감시

보유 종목마다 "왜 샀나 / 무엇이면 틀린가"를 적으면 기존 **핵심질문 추적기**(D-067)로 넘겨 매일 판정하고, 판정이 나빠지면 텔레그램으로 알린다.

- 데이터: `questions.stock_code` 칼럼 추가(ALTER). 생성은 기존 `decompose_question`(sonnet 1회, 사용자가 '감시 시작'을 누를 때만) — `created_by='portfolio'`.
- 판정: 기존 07:40 `refresh_all`의 결정적 롤업. 국내 종목은 숫자 관측 경로가 없어(전사록=미국 기업만) **문서 논조 지표 + 미국 관련 기업(마이크론·램리서치 등) 전사록 지표**로 판정한다. 분해 프롬프트에 "보유 종목이 한국 기업이면 관측 가능한 미국 상장 관련 기업 티커를 지표에 쓰라"를 덧붙인다. 국내 시세·DART·수출입 지표 어댑터는 P1.
- 알림: 07:40 롤업 뒤, 보유 종목 질문의 판정(선행·확정·괴리)이 바뀌어 `leaning_no`가 생기거나 반증 조건이 붙은 하위 질문이 `leaning_no`가 되면 텔레그램 1회(`portfolio_alerts_sent` 키 `q:{id}:{판정 3종}`).
- 화면: 종목 탭에 '논지' 카드 — 없으면 입력 폼, 있으면 종합 판정·하위 질문(반증 조건·판정)·질문 상세 링크.

## 3. 내 종목 자료 흐름

16:50 일일 요약 메시지에 종목별 한 줄을 붙인다(조건 충족 종목만).

- 언급 급증: 오늘 언급 문서 수 ≥ 3 이고 최근 7일 평균의 2배 이상(기존 `mention_surge`와 같은 기준). 소형주는 하루 0~1건이라 대개 조용하다 — 정상.
- 논조 변화: 오늘 연결 문서의 부정 비율이 최근 7일보다 30%p 이상 높을 때(문서 `enrichments.sentiment`).
- 요약: 오늘 날짜 1D 다이제스트의 `insights` 첫 줄. 보유 종목은 상위 5개 밖이어도 `digests.compute_daily(day, stock_code=)`로 그날 1D만 만든다(`catch_up`은 월·주 소급까지 해 비용이 커 쓰지 않음) — 오늘 새 문서가 있을 때만, 1회/종목/일(문서 집합이 같으면 재생성 안 함). 미리보기(--dry-run)에서는 생성하지 않는다.
- 화면: 종목 탭 '자료 흐름' — 14일 언급 막대 + 최신 요약.

## 4. 다가오는 이벤트

기존 일정 데이터는 모두 지났거나 비어 있다(조사 2026-10-08). 새로 모은다.

| 종류 | 출처 | 날짜 |
|---|---|---|
| 보유 종목 예고 공시 | DART 결산실적공시예고·기업설명회(IR)개최·주주총회소집결의 — 매일 16:50 최근 120일을 30일 창으로 조회(긴 기간은 목록이 잘린다), 본문의 '일시'·'예정일' 날짜를 `catalysts`에 저장. 읽은 접수번호는 다시 열지 않음 | 공시 본문의 예정일 |
| 보유 종목 실적 예상 | 확정 일정이 없을 때만: 작년 같은 분기 잠정실적 공시일 + 364일(같은 요일). 잠정실적 공시 이력이 없으면 정기보고서 법정 제출 기한. `portfolio_event_estimates`에 근거와 함께 | '예상' 표시 |
| 관련 해외 기업 실적 | `transcript_calendar`(yfinance) — 보유 종목이 속한 밸류체인의 대표 미국 기업(`CHAIN_TICKERS`, 반도체: MU·LRCX·AMAT·KLAC·ASML·TSM·NVDA·TER), 7일 지난 캐시만 갱신 | 발표 예정일 |
| 수동 | 기존 `catalysts` 입력 | 입력값 |

화면: 포트폴리오 '다가오는 이벤트' 카드(45일, 확정·예상·해외 구분, 확정은 DART 원문 링크). 알림: 16:50 일일 요약에 '3일 이내 일정'.

## 5. 운용 원칙 감시 (D-227)

계좌 운용 원칙을 문장으로 적으면 저장 전에 모델이 한 번 수치 규칙으로 풀고(haiku, 원칙 문장만 보냄 — 원장은 보내지 않음), 사용자가 확인한 규칙만 저장한다. 이후는 모델 없이 계좌 상태와 대조해 **어긴 순간 텔레그램으로 한 번** 알린다. 풀렸다가 다시 어기면 다시 알린다. 화면 배지·거래 입력 경고는 없다(사용자 선택: 알림만).

- 규칙 유형(`pipeline/portfolio_principles.RULES`): 보유 비중 상한(보유 중 내내) · 신규 진입 비중 상한(포지션을 처음 연 매수 한 번만 — 그 시점 계좌 대비, 이후 나눠 사서 커지는 건 허용, `portfolio.entry_weights`) · 현금 비중 하한/상한 · 평단 대비 손실 한도/이익 실현 점검 · 하루 하락 한도 · 보유 종목 수 상한 · 공통 변수(§1) 노출 상한 · 보유 기간 점검 · 계좌 누적 손실 한도. 매개변수 범위는 서버가 검증한다. 허용 유형으로 옮길 수 없는 문장(예: "실적이 꺾이면 판다")은 `unparsed`로 돌려주고 감시하지 않는다 — 종목별 '보유 논지'(§2)로 안내.
- 데이터(로컬 DB만, git 제외): `portfolio_principles`(원문·규칙 JSON), `portfolio_principle_state`(지금 어기고 있는 키 = 원칙id:규칙번호:대상). 키 대상은 종목(비중)·편입 단위(손익·보유 기간)·날짜(하루 하락)·cash·account·driver.
- 점검 시점: 장중 30분(`pfintraday`)은 장중 규칙(비중·현금 하한·손익·하루 하락)만, 16:50(`pfclose`)은 전체. 공통 변수 노출은 노출 규칙이 있을 때만 계산한다. 장중 점검은 장중 규칙의 상태만 갱신한다.
- 발송 실패면 상태를 기록하지 않아 다음 점검에서 다시 보낸다. 원칙 점검 실패는 다른 포트폴리오 알림을 막지 않고 실행 결과의 errors로 남는다.
- **해석 결과 저장**: 확인 화면의 두 목록 — ① 기계 점검 규칙 ② 대화에서 참고하는 원칙(`notes_json`, 모델이 원문에서 원칙만 한 줄씩 정리, 사용자가 뺄 수 있음) — 을 확인한 그대로 저장한다. 규칙 없이 참고 원칙만 있어도 저장된다.
- API: `GET /api/portfolio/principles`(text·rules·notes) · `POST /principles/parse`(미리보기, 저장 안 함) · `POST /principles`(text·rules·notes) · `PUT /principles/{id}`(다시 풀기 — 원문·규칙·참고 목록 교체, 그 원칙의 위반 상태 초기화) · `PATCH /principles/{id}`(원문만 수정, 모델 0) · `DELETE /principles/{id}`. 원문은 최대 20,000자. 화면: 포트폴리오 하단 '운용 원칙' 카드 — 입력 → 규칙으로 풀기 → '시스템이 이렇게 이해했습니다'(규칙·참고 원칙, 항목별 빼기) → 이대로 저장. 저장된 원칙은 이해한 내용을 먼저 보이고 원문은 '원문 보기'로 접는다(줄바꿈 그대로, 8줄 넘으면 '전체 보기'). 다시 풀기 · 원문 수정('저장하고 다시 풀기'/'원문만 저장') · 삭제.
- 메시지는 비율·가격만(원문 앞 80자 인용 포함 — 텔레그램은 사용자 개인 채널).
- **대화 맥락(D-228)**: 원문 전체(기계가 못 푸는 문장 포함)를 저장하고, 대화 도구 `get_portfolio`가 원문·기계 점검 규칙·지금 어긴 규칙을 포트폴리오 비율 요약과 함께 돌려준다. '내 원칙대로라면 더 사도 돼?'류 질문의 판단 기준이 된다. 화면 확인 단계는 '기계가 이렇게 점검합니다'와 '대화에서 참고하는 문장'을 구분해 보인다.

## 6. 관심 이유 감시 (D-227)

관심 묶음 종목마다 "왜 보고 있나 / 무엇이 오면 움직이나"를 적으면 §2와 같은 핵심질문 추적기로 분해하고(sonnet 1회, 누를 때만) 매일 07:40 판정한다.

- 질문은 `created_by='watch'`, 보유 논지는 `'portfolio'` — 같은 종목이 양쪽에 있어도 섞이지 않는다(`portfolio_thesis.theses(created_by=)`).
- 알림: 보유 논지와 달리 **양쪽**으로 기울 때 — 선행·확정이 지지(🟢, 매수 검토 신호) 또는 약화(🟠), 반증 조건 하위 질문 약화. 같은 판정 상태는 한 번(`portfolio_alerts_sent` 키 `w:{id}:{판정}`). 대상은 모든 관심 묶음 종목(중복 제거). `refresh_questions` 07:40 직후, 결과는 `job_runs('watch_reason')`.
- API: `GET /api/spine/groups/{id}/reasons` · `POST /groups/{id}/reasons`(관심 묶음만, 보유 묶음은 409로 §2 안내). 화면: 관심 묶음 상세의 '관심 이유' 카드 — 종목마다 '이유 적기'(기존 멤버 메모가 있으면 미리 채움) → 감시 시작, 감시 중이면 선행·확정 판정·기운 신호·질문 상세 링크.

## 5-state

각 카드 Empty(근거 없음을 그대로: "인과 그래프에 연결이 없습니다" 등) · Loading · Partial(출처 일부만) · Error(재시도) · Ideal.

## 비용·실행

- LLM: 논지 생성 sonnet 1회(버튼) · 매일 롤업은 기존 haiku 추출 범위 안 · 자료 흐름 요약 haiku ≤ 보유 종목 수/일. 나머지 결정적.
- 스케줄: 기존 `questions` 07:40(직후 논지 알림) · `pfclose` 16:50(일정 수집·자료 흐름·요약) · `pfintraday` 30분에 얹는다. 새 launchd 없음. 일정·흐름 단계가 실패해도 요약은 보내고 실패는 `job_runs`에 error로 남긴다.

## 범위 밖 (P1)

- 운용 원칙: 화면 위반 배지·거래 입력 시 경고(사용자가 알림만 선택), 정성 원칙 자동 분해.

국내 숫자 지표 어댑터(시세·DART·수출입·컨센서스), 공통 변수 뉴스 알림, 그래프 노드 중복 정리, 시나리오(파급) 자동 실행.
