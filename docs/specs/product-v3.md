# Product v3 — Phase 2 UI/UX 대개편 스펙 (초안)

> 기초자료: docs/specs/ia-map.md (현행 스냅샷) · 전제: 비전 "혼자서도 리서치센터 — 노동은 기계가, 판단은 사람이"
> 상태: **초안 — stakeholder 리뷰 대기.** 승인 후 단계별 스펙으로 분해.

## 0. 본질과 중심 축

본질: 투자 의사결정 · 포트폴리오(논지) 관리 · 인사이트. 중심 축은 페이지가 아니라 **판단 루프**:

```
⓪ 유입 (새로 볼 것)  →  ① 델타 (뭐가 달라졌나)  →  ② 맥락 (이건 어떤 것인가)
     탐색·신호                 홈/스트림                   도시에(종목·소스·테마)
                                                              ↓
              ①로 복귀  ←  ③ 판단 (그래서 내 생각은) — 대화 · 논지 · 가설
```

모든 화면은 루프의 한 단계다. 화면을 늘리는 게 아니라 **루프를 닫는 것**이 Phase 2다.
현행 진단(ia-map §4): ①②는 구축됨, ③이 보관함에 유배(투자메모), 최대 허브(종목 요약 탭)가 루프 밖.

## 1. 프리미티브 3개 (기존 2 + 대화 승격)

| 프리미티브 | 방향 | 화면 | 역할 |
|---|---|---|---|
| 스트림 | delta push | 홈 | 기계가 먼저 말한다 |
| 도시에 | context pull | 종목·소스·(테마) | 축적된 맥락을 꺼내 본다 |
| **대화** | **judgment interface** | 대화 스레드 + 도시에 내 질문 + 텔레그램 | **판단이 만들어지고 기록되는 곳** |

옴니바(⌘K)는 프리미티브가 아니라 셋을 잇는 배선. 앤티-분산 정책 유지: 신규 기능은 스트림 항목 / 도시에 섹션 / 대화 커맨드로만 착지.

## 2. 대화 프리미티브 설계

### 2-1. 왜 대화가 일급인가 — 질문 히스토리는 유일한 "사용자 의도" 데이터
수집 파이프라인은 세상의 데이터를 쌓지만, **무엇을 물었고 어떻게 후속질문했는가**는 사용자의 관심·불안·판단 과정 그 자체다. 팔로우보다 강한 시그널이고, 지금은 전부 버려진다(/ask 일회성, 봇 stateless).

### 2-2. 데이터 모델
```
conversations: id, title(자동 생성), anchor_entity_id(NULL 가능), channel(web|telegram), created_at
chat_messages: id, conversation_id, role(user|assistant), content,
               citations_json, gaps_json, model, created_at
질문 메시지 → 엔티티 링크 (기존 enrich 재사용, 종목/토픽 추출)
```

**불변 원칙 — 에코챔버 방지**: AI 답변은 RAG 검색 인덱스에 절대 넣지 않는다.
사용자 질문 = 시그널 데이터(엔티티 링크·패턴 분석 대상), AI 답변 = 파생물(표시·회고용).

### 2-3. 표면 (어디서 대화하나)
- **대화 L1**: /ask를 스레드 리스트+이어가기로 확장 (기존 1회성 Q&A 대체)
- **도시에 안**: "이 종목/소스에 대해 질문" (앵커 프리필) + **"내가 물어본 것들"** 섹션 (스레드 회고)
- **옴니바**: 문장형 입력 → 새 스레드 생성 (현행 라우팅 유지)
- **텔레그램**: 같은 스레드 풀의 모바일 표면. 봇 문답을 conversations에 적재, 웹에서 이어보기.
  스레딩 휴리스틱: 30분 무응답 → 새 스레드, 종목 브리프 질의는 해당 엔티티 앵커.

### 2-4. 히스토리 활용 3단 (점진 — 각 단계가 독립 가치)
- **L0 저장**: 웹·봇 전 대화 영속화 + 질문 엔티티 링크 (UI 무변화, 자산 축적 시작)
- **L1 회고**: 도시에 "내가 물어본 것들", 옴니바에서 과거 대화 검색, 스레드 이어가기
- **L2 패턴**: 반복 질문 감지(주 1회 haiku 배치) → "이 질문, 브리핑에 상시 편입할까요?" 제안
  = 질문의 cron화. **3단계(자율 에이전트)로 가는 다리**: 에이전트가 할 일을 사용자 질문 패턴이 정의해 준다.

### 2-5. 메모리 규약 (토큰 안정성)
- 스레드 컨텍스트 = 최근 N턴 + 앵커 엔티티의 최신 다이제스트만. 전체 히스토리를 매 턴 프롬프트에 넣지 않는다.
- **판단 승격**: 대화 중 사용자의 판단 발언 → 버튼 한 번으로 vault 가설 노트 저장 (③과 vault 연결).

## 3. 화면·플로우 재편

### L1 네비 (4→4, 구성 교체)
```
오늘(스트림, /home) · 탐색(유입, /explore·신호·기업활동) · 피드(원천, /feed) · 대화(판단, /chat)
```
- '분석' 모드필 제거 — 도시에는 네비가 아니라 목적지 (진입 13+ 엣지로 충분, ia-map §2-3)
- '리서치' 고아 서브탭 해체 — 논지는 도시에 안으로(§3-2), 나머지 보관함
- catch-all `*` → /home

### 종목 도시에 재편 (최대 허브를 루프에 연결)
1. **AI 브리프** (신규 첫 화면): 언급 다이제스트 + 신호 + 재무 변곡 + 일정 + **내 논지 현황** — 소스 도시에와 동일한 게으른 생성(hash 가드, 새 데이터 시만)
2. **내 논지** (투자메모 4분면을 보관함에서 이관): Bull/Bear/Catalyst/Risk + AI가 "새 증거 vs 내 논지" 충돌 감지(기존 '새로운 시각' 패턴 확장)
3. **내가 물어본 것들**: 이 종목 앵커 스레드 목록
4. 원천 데이터 탭(재무·밸류·사업·공시): 유지하되 **dead-end 제거 규칙** — 모든 탭 하단 "다음 질문" 섹션(관련 문서/소스 링크, LLM 0토큰)

### 토큰 규약 (AI Native ≠ 매 클릭 LLM)
ⓐ 수집 시 1회 태깅·요약(haiku 배치) ⓑ 열람 시 게으른 종합(캐시+hash, 변경 시만)
ⓒ 질문 시 온디맨드(RAG sonnet — 유일한 사용자 트리거 고비용) ⓓ 탐색·네비 UI는 LLM 0
ⓔ 패턴 분석은 저빈도 배치(주 1회 haiku)

## 4. 다각 검토

### 관점별 (product trio + 운용역)
- **PM**: 질문 히스토리는 이 제품이 쌓는 유일한 사용자 의도 자산 — 방어력(개인화)의 원천. 위험: 대화가 좋아질수록 화면 열람이 줄 수 있음 → OMTM(주간 열람일수)에 텔레그램 문답 포함하도록 재정의 필요.
- **디자이너**: 채팅은 앵커 없으면 산만해지는 인터페이스 — 엔티티 앵커·스레드·"물어본 것들"의 제자리 노출이 정돈성 담당. "채팅창 하나 추가"가 아니라 "질문이 어디서나 가능하고 답이 제자리에 쌓인다".
- **엔지니어**: conversations 2테이블 + /ask 확장 = 저비용. 봇은 이미 있어 conv 매핑만. 주의: 스레드 컨텍스트로 프롬프트 길이 증가 — §2-5 규약 필수. 텔레그램 스레딩은 휴리스틱(불완전 허용).
- **운용역(사용자)**: 실전 가치는 "아침 브리핑에 답장으로 후속질문 → 퇴근 후 데스크톱에서 그 스레드에 근거 문서까지" — 모바일-데스크 연속성이 킬러.

### 리스크 가정 (Value/Usability/Viability/Feasibility)
| # | 가정 | 영역 | 확신 | 검증 방법 (싼 순서) |
|---|---|---|---|---|
| A1 | 질문 히스토리를 실제로 다시 본다 | Value | 중 | L0+도시에 섹션만 먼저 → 2주 클릭 관찰 |
| A2 | 반복 질문 패턴이 존재한다 (n=1 사용자) | Value | **하** | 질문 20+ 축적 후 배치 1회 돌려 눈으로 확인 |
| A3 | 대화가 화면보다 나은 순간이 충분히 많다 | Value | 중 | 봇/웹 질문 빈도 로그 (L0가 곧 측정기) |
| A4 | 앵커·스레드로 정돈성 유지 가능 (잡담성 질문 처리) | Usability | 중 | 앵커 없는 스레드 비율 관찰 |
| A5 | 텔레그램↔웹 문맥 전환이 자연스럽다 | Usability | 중 | 스레딩 휴리스틱 오분류율 |
| A6 | 토큰 비용 통제 가능 | Viability | 상 | §3 규약 — 사용자 트리거 sonnet만 변수 |
| A7 | 친구 초대 시 대화 프라이버시 분리 | Viability | 상 | chat_id별 conversation 격리 (멀티챗과 교차 확인) |
| A8 | 문서 807건에서 스레드 RAG 품질 유지 | Feasibility | 중 | H3 게이트(1,000+) 전 — 대화 UI(P2-2)를 데이터 축적 뒤로 |
| A9 | 텔레그램 스레드 구분 휴리스틱이 충분 | Feasibility | 중하 | 30분 윈도우부터, 오분류 시 /new 커맨드 |
| A10 | 에코챔버 방지 원칙 유지 | Feasibility | 상 | 답변 비색인 — 코드 리뷰 체크항목화 |

**킬 기준**: A1·A2·A3이 전부 부정되면(질문 빈도 자체가 낮음) 대화 L1 승격을 중단하고 봇+옴니바 수준으로 롤백 — L0 저장 비용은 매몰돼도 무시 가능.

## 5. 마이그레이션 (안정성 — 각 단계 독립 배포·롤백)

| 단계 | 내용 | 성격 | 게이트 |
|---|---|---|---|
| P2-0 | **대화 영속화** (/ask·봇 저장 + 질문 엔티티 링크) | 데이터만, UI 무변화 | 없음 — 즉시 |
| P2-1 | 종목 도시에 개편 (AI 브리프 + 내 논지 이관 + 물어본 것들) | 최대 허브 개선 | 없음 |
| P2-2 | 대화 스레드 UI + L1 재편 (오늘·탐색·피드·대화) | 네비 대개편 | P2-0 데이터 2주 관찰 (A1~A3) |
| P2-3 | dead-end 제거 + 텔레그램 스레드 통합 | 마감 | P2-2 |
| P2-4 | 반복 질문 → 브리핑 승격 (L2 패턴) | 에이전트 다리 | 질문 20+ 축적 (A2) |

원칙: **데이터부터, UI는 증거 뒤에.** P2-0은 위험 0으로 지금 시작 가능 — 대화 UI를 만들지 여부와 무관하게 질문 데이터는 오늘부터 쌓여야 나중이 있다.
