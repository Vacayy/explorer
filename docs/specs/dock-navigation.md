## 현행 개편 — Home 중심 탐색 (2026-09-10)

사용자 승인: Dock은 Home / 관심목록 / 월드모델 / 대화의 4개 모드. 피드 읽기는 Home으로 통합하고, `/feed` 기본 진입은 Home 피드로 이동한다. 문서 검색과 기존 검색·필터 URL은 유지하며 검색·더보기에서 접근한다. 기존 `feed_*` 타임라인 필터 링크는 호환 화면으로 유지한다.

`/follow`는 기업·인물·산업/테마 관심목록. 소스 등록·활성화 관리는 `/sources`로 분리하고 Home 피드의 소스 관리·옴니바·더보기에 연결한다. 컨콜·수출입·미국·유니버스·산업맵·저장·기업활동 경로는 관심목록 하위에 유지한다. 모바일은 4개 모드+더보기 5칸, 모드 단축키는 ⌥1–4. 문서/소스/검색의 기본 Dock 활성은 Home.

아래 D-136의 5모드·파이프라인 순서 설명은 이력이며 위 계약을 우선한다.

## 0. 검토 결론 — 조건부 찬성

**찬성.** 단, "공간 회수"가 아니라 **"상단 정적(靜寂) + 위계 축소"**가 명분이어야 하고, 아래 세 가지 설계 보정이 붙어야 한다.

### 0-1. 왜 되는가

| 근거 | 설명 |
|---|---|
| 1인 데스크톱 도구 | 로고·브랜딩·계정 메뉴가 필요 없다. 헤더가 지금 담는 것은 옴니바 트리거 1 + 아이콘 6(저장·승인·관리자·보관함·테마·레일). 전부 "아이템"이라 도크로 1:1 이식된다 |
| 도크 관용구 3개가 IA 요구와 일치 | **배지**(승인 대기 N — D-056 "어느 화면에서든") · **활성 점**(현재 모드) · **실행 중 임시 항목**(macOS는 도크에 없는 앱도 실행 중이면 나타남 → "열린 종목 도시에"가 정확히 이것. D-056/057의 "도시에는 네비가 아니라 목적지" 원칙과 충돌 없이 컨텍스트 pill을 대체) |
| L1 흐름 보존 | `Home ┃ 팔로우 → 피드 → 월드모델 ┃ 대화` 순서와 구분선(D-057)을 도크 안에서 그대로 유지 가능 |
| 모바일 축퇴가 자연스럽다 | 하단 도크 → 하단 탭바(iOS 관용구). 지금 상단 2단 네비는 390px에서 "팔로\n우" 줄바꿈이 난다(D-135 검증 스크린샷) |
| 매일 여는 도구의 시선 | 콘텍스트가 뷰포트 최상단에서 시작한다. 헤더+네비 132px이 매 화면 위에 있는 것과, 아무것도 없는 것의 차이는 수치보다 체감이 크다 |

### 0-2. 정직한 경고 — 수직 공간은 거의 안 늘어난다

```
현재 상단 크롬     = 헤더 56 + L1 행 40 + L2 행 36(L2 있는 모드만) = 96 ~ 132px
도크(플로팅, 상시) = 하단 예약 ≈ 도크 56 + 여백 16 + 콘텐츠 간격 12 = 84px (+ 인페이지 L2 36)
```
L2가 있는 페이지는 **12px**, 없는 페이지(Home·대화)는 **12px** 차이. 도크가 콘텐츠 위에 떠 있어 "읽기 영역"은 사실상 같다. **자동 숨김**을 켜면 84px을 회수하지만 wayfinding을 잃는다(§5). 그러니 이 개편의 성공 기준은 "화면이 넓어졌다"가 아니라 **"위가 조용하다 · 한 번에 보이는 크롬 요소가 13개 → 6개"**다.

### 0-3. 위험과 보정

| 위험 | 보정 |
|---|---|
| **도크는 런처, 위계가 없다.** 서브탭(팔로우 9·피드 9·월드모델 3·도시에 6)을 호버 팝오버에만 두면, 같은 모드 안에서 탭을 바꿀 때마다 화면 하단으로 내려가 호버해야 한다(Fitts 비용·피드 소스 전환은 분 단위로 일어남) | **분업**: 도크 팝오버 = *모드 간 직접 점프*("팔로우 → 컨콜"로 한 번에), 같은 모드 안 전환 = *페이지 첫 줄의 인페이지 탭 스트립*. macOS 자체가 그렇다 — 도크 메뉴는 창 목록, 탭은 창 안에 |
| **아이콘만으론 못 알아본다.** 5개 모드는 라벨 없이 학습 부담. 도크 라벨은 호버 툴팁 | 라벨 **상시** 노출(iOS 탭바). 크기 11px, 아이콘 아래. 아이콘 확대 애니메이션은 절제(1.06배·120ms), macOS식 파도 확대는 안 함 |
| **하단 자리 경쟁**: 대화 컴포저·'최신으로' 버튼·sonner 토스트(우하단) | 컴포저는 도크 위 12px에 정착(`--dock-reserve` 토큰), 토스트는 우상단으로 이동, '최신으로'는 컴포저 위(변경 없음) |
| **호버는 터치에 없다** | <768: 탭바로 축퇴, 활성 탭 재탭 → L2 Sheet(iOS "탭 다시 누르면 상단/하위" 관용구) |
| **참신함 ≠유용함** | §9-A에 안전한 대안(초슬림 상단 헤더)을 같이 놓고 선택한다 |

### 0-4. 기각한 대안

- **좌측 아이콘 레일(Linear·Slack)** — 웹 관용구라 안전하고 수직 공간 0. 하지만 우측에 팔로우 레일(256px)이 상시라 양쪽 레일 = 1440 셸에서 콘텐츠 1,136px. 좌우 대칭 크롬은 "도구 안의 도구" 느낌으로 요청 취지(거슬림 제거)와 반대.
- **초슬림 상단 단일 행(36px: L1 pill + 유틸 아이콘, L2는 인페이지)** — 위험 0, 수직 공간은 오히려 도크보다 유리(36 vs 84). 요청의 절반(최소화)만 충족하고 "없앤다"는 못 한다. **§9-A의 B안**으로 남긴다.
- **도크 자동 숨김 기본 on** — 현재 모드·배지가 안 보이면 "어디 있는지"와 "결정할 게 있는지"를 둘 다 잃는다. P2 옵션으로만.

## 2. L2 — 인페이지 탭 스트립 (`layout/SubNav.tsx`)

모드 안의 형제 탭은 콘텍스트 **첫 줄**에 sticky 36px로 산다. 지금 `SubTab`(밑줄형) 스타일 그대로, 위치만 콘텐츠 안으로. `FOLLOW_TABS`·`FEED_TABS`·`WORLDMODEL_TABS`·`ANALYZE_TABS` 정의는 `layout/navConfig.ts`로 이관해 도크 팝오버와 **한 소스**를 공유(D-057 원칙 유지: 탭 목록은 한 곳).

- Home·대화·문서(/doc)·소스(/source): L2 없음 → 0px. 콘텍스트가 뷰포트 최상단에서 시작.
- 도시에(/analyze/:code): SubNav 좌측에 회사명·종목코드(지금 컨텍스트 pill 역할) + 탭 6.
- URL = 상태 단일 소스(PHILOSOPHY §6) 그대로 — SubNav는 Link만.

## 3. 도크 호버 팝오버 — 모드 간 직접 점프

L2가 있는 도크 항목(팔로우·피드·월드모델·열린 도시에)에 **250ms 호버** 또는 **클릭 후 홀드**(mousedown 300ms) → 위로 여는 팝오버(`side="top"`).

```
        ┌──────────────────────────────┐
        │ 팔로우                        │
        │ 팔로우  유니버스  컨콜  미국   │   ← Link 그리드, 현재 탭 강조
        │ 수출입  저장됨  산업 맵  인물  │
        │ 기업활동                      │
        └──────────────┬───────────────┘
                     ☆ 팔로우
```
- 단순 클릭 = 모드 랜딩(빠른 길 유지). 팝오버는 "한 번에 하위로" 가고 싶을 때만.
- 대화 항목 팝오버(선택): 최근 스레드 3 + 새 대화 — macOS 도크 우클릭의 "최근 항목". P1에서 판단.
- 구현: shadcn **HoverCard**(Radix, 호버 지연 내장) — 미설치, `npx shadcn@latest add hover-card` 필요. 키보드: 항목 포커스 후 `↑`로 열기, `Esc` 닫기.

## 4. 열린 도시에 — 실행 중 임시 항목

`/analyze/:code/*` 또는 `/us/:ticker`에 진입하면 도크 L1 오른쪽 구분선 뒤에 **회사명 칩**이 나타난다(`useCompany`로 이름, 로딩 중엔 코드). 활성 점 항상 on(여기 있으니까). 호버 팝오버 = 도시에 탭 6(요약·재무·밸류·사업·공시·렌즈). 도시에를 떠나면 사라진다(애니메이션 150ms).

- 여러 도시에 동시 유지("최근 열어본 종목 3개")는 안 한다 — 팔로우 레일·`⌘K` 최근 항목이 그 역할. 도크가 탭바가 되는 순간 브라우저 탭과 경쟁한다.
- /doc·/narrative?topic·/question/:id는 v1 제외(진입 경로가 다양하고 "열린 문서"까지 도크에 올리면 잡음).

## 5. 위치·동작 규칙

- 위치: 하단 중앙 플로팅. 콘텍스트는 도크 아래로 스크롤되어 사라짐(반투명+블러로 "떠 있음"을 표시). 마지막 콘텍스트가 가려지지 않게 `main`에 `pb-[var(--dock-reserve)]`.
- **자동 숨김 없음**(기본). P2에서 옵션("스크롤 다운 시 축소 → 위로 스크롤·하단 근접 시 복귀")만 검토.
- 토큰: `--dock-height: 56px` · `--dock-reserve: 84px`(56+16+12) · `--shell-offset`은 "상단 크롬"이 사라지므로 **폐기 → 풀하이트 페이지는 `h-[calc(100dvh-var(--dock-reserve)-3rem)]`**(3rem = main p-6 상하). DESIGN_SYSTEM §1 갱신.
- 대화: 컴포저가 도크 위 12px에 앉는다. '최신으로' 버튼은 컴포저 위(변경 없음).
- 토스트(sonner): `position="top-right"`로 이동 — 하단 도크·컴포저와 겹치지 않게.
- 팔로우 레일(우측 Sidebar): 그대로. 도크는 `SidebarInset` 폭 중앙이 아니라 **뷰포트 중앙**(레일 열림/닫힘에 흔들리지 않게).

## 6. 반응형

| 폭 | 형태 |
|---|---|
| ≥1024 | 플로팅 도크(라벨 on), 호버 팝오버 |
| 768~1023 | 동일. 유틸B에서 '레일'은 그대로(Sidebar가 이 폭에서 토글형) |
| <768 | **전폭 하단 탭바** 5모드 + ⋯(검색·승인·저장·레일·테마·관리자·보관함). 라벨 on. **활성 탭 재탭 → L2 Sheet**(하단). 열린 도시에는 탭바 위 얇은 컨텍스트 바(회사명 + 탭 가로 스크롤)로 대체. `pb-[env(safe-area-inset-bottom)]` |

## 7. 키보드·접근성

- `⌘K` 검색 · `⌘1~5` 모드(Home·팔로우·피드·월드모델·대화) · `⌘B` 레일(기존) · `/` 검색(기존)
- 도크 = `<nav aria-label="주 메뉴">`, 항목 `aria-current="page"`, 배지는 `aria-label="승인 대기 3건"`. Tab 순회 · Enter 이동 · `↑` 팝오버 · `Esc` 닫기.
- `prefers-reduced-motion`: 확대·등장 애니메이션 off.

## 8. 상태

도크는 보조 UI라 전면 5-state 대신: 배지 로딩=숫자 없음 · 배지 실패=조용히 숨김(레일과 같은 정책, follow-rail.md) · 열린 도시에 로딩=종목코드 → 이름 치환 · 팝오버 데이터 없음(대화 최근 스레드 0)=항목 숨김.

## D-158 스터디 진입점 (2026-09-11)

Dock에 독립 스터디 `/study`를 추가한다. 현재 순서는 Home·관심목록·월드모델·스터디·대화이며 Alt+1–5가 같은 순서다. 모바일은 더보기까지 6칸이다. 저장됨 기본 순서는 유지하며 스터디 목록은 저장됨에서 분리한다. 피드/상세의 ‘스터디에 추가’는 프로젝트를 고른 뒤 현재 읽던 화면에 머문다. 상세 계약은 `study-mode.md`를 따른다.
