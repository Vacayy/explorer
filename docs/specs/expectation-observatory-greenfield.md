# 기대 변화 관측 시스템 — 공통 설계와 실험 계약

> 2026-09-09. 상태: **수집 자료 읽기 → 기존 챗봇 대화 연결 구현. 기대 원장은 보조 검토 도구**.
> 사용자 요구: 투자자 발언을 핵심 관측으로 취급하고, 펀더멘털의 수준·변화율·가속도,
> 이에 대한 기대, 심리·해석, 포지셔닝·수급을 시간축에서 대조한다.
> 이 문서는 현행 SYSTEM/DECISIONS를 대체하거나 기존 파이프라인 폐기를 확정하지 않는다.
> 첫 커버리지: **메모리반도체(사용자 확정, 2026-09-09)**.
> 기업·제품·쟁점 범위: [메모리반도체 커버리지](memory-semiconductor-coverage.md).
> 운영 수량은 초기 실험 설계값이며 실측 결과가 아니다.

## 진행 상태와 문서 소유권

- **단일 진입점:** [spec 목록과 수명주기](README.md). 이 파일은 공통 제품·데이터·판정 규칙의 기준 문서다.
- 산업별 범위와 코퍼스 준비 상태는 [메모리 커버리지](memory-semiconductor-coverage.md)에만 둔다.
- 현재 단계: 메모리 수집 자료의 저장 요약·발췌를 읽고, 최근 자료 묶음/단일 자료/과거 자료를 기존 챗봇에 직접 첨부하여 질문. 기존 발언 검토 원장은 보조 경로로 보존.
- 다음 단계: 초기 사례에서 화자·층위·기간·변화의 누락/오탐을 채점하고 20~30개로 확대. 아래 전체 제품 설계 중 구현 범위는 §8이며, 시장 가격·펀더멘털·수급 자동 연결은 미구현.
- 공통 규칙 변경은 이 문서 수정, 산업 설정 변경은 커버리지 문서 수정. 회의·작업일·실험마다 새 spec을 만들지 않는다.
- 입력 발췌·후보 명단·평가 결과는 로컬 `logs/memory-coverage/`; 재현 로직은 `scripts/audit_memory_coverage.py`.
- 구현 완료 시 현행 구조는 SYSTEM에 반영하고 이 문서는 유지할 계약만 남긴다. 폐기 시 대체 문서를 명시해 archive로 이동한다.

## 1. 제품과 커버리지 결정

**내가 중요하게 보는 투자자들이 무엇에 대한 기대를 바꿨고, 무엇을 계기로 바꿨으며,
그 변화가 사업·가격·수급 관측과 어떻게 맞물리는지 원문으로 확인하는 개인 도구.**

추천: 공통 기록·비교 구조 + 산업별 관측 설정. 전시장 정밀 분석도, 기업별 별도 앱도 먼저 만들지 않는다.
범용성은 새로운 커버리지를 추가할 때 출처·발언·시간·수정 이력을 다시 구현하지 않는다는 의미다.
새 산업을 완전히 이해하는 범용 온톨로지나 자동 판정기는 초기 목표가 아니다.

| 선택지 | 장점 | 초기 비용/위험 | 판단 |
|---|---|---|---|
| 전시장 범용 분석 | 넓은 탐색 | 도메인별 비교 기준·검증 표본 부족, 처리량 증가 | 보류 |
| 기업별 전용 구현 | 첫 기업에서 빠른 정밀화 | 파이프라인 복제, 산업 간 비교 단절 | 보류 |
| 공통 코어 + 작은 산업 커버리지 | 비교 품질과 재사용을 함께 검증 | 관측 변수·대상 선정 필요 | 추천 |

### 커버리지의 단위

단순 종목 목록이 아니라 **기업/산업 + 핵심 쟁점 + 관찰할 투자자 + 관측 변수 + 시간 범위**다.
한 투자자의 발언은 여러 커버리지에 연결될 수 있고, 원문/추출은 공유한다.
사용자의 보유종목, 관찰 대상, 비교 기업은 별개다. 커버리지 편입은 매수 의사를 의미하지 않는다.

### 넓은 수집, 좁은 정밀 분석

- **핵심:** 선택한 기업·쟁점·투자자. 발언 이력과 기대 변화를 계속 비교.
- **인접:** 고객·경쟁사·공급사·관련 정책/거시 변수. 핵심 쟁점에 관련될 때 심층 처리.
- **탐색:** 기존 선택 소스의 전체 원문을 보존하고 검색 가능하게 유지. 새로운 쟁점/기업은 후보로 제시.

키워드 미일치 자료를 버리지 않는다. 초기 관련성 판정이 틀려도 소급 검색할 수 있어야 한다.
명시적 이름 매칭과 의미 검색을 함께 사용하고, 탈락 문서도 표본 검토한다.
탐색에는 작은 별도 예산을 두되 비율은 실제 유입량·비용을 측정한 뒤 정한다.
후보의 자동 편입/전량 심층 재처리는 하지 않는다. 사용자 선택 후 필요한 과거 창부터 처리한다.

## 2. 초기 파일럿

**메모리반도체: HBM·일반 DRAM·NAND/SSD**를 첫 커버리지로 한다.
삼성전자·SK하이닉스·Micron·Kioxia·Sandisk를 핵심 비교 대상으로 두고,
경쟁 공급·고객 수요·생산 제약 관련 기업은 연결 범위로 관찰한다.
제품·역할·쟁점은 기업 하나에 독점 배정하지 않는다. 상세 범위와 집계 규칙은
[커버리지 설계](memory-semiconductor-coverage.md)를 따른다.
투자자/작성자 5~10명은 초기 운영 목표이며 실제 코퍼스 점검 후 선정한다.

쟁점 예시:
1. 투자 확대가 언제까지 지속될 것으로 보는가?
2. 수요 증가가 공급 증가보다 빠르다는 기대가 유지되는가?
3. 성장률보다 투자 회수·마진·현금흐름을 더 중요하게 보기 시작했는가?

파일럿 선택 기준: 사용자가 직접 오류를 판별할 수 있음, 동일 작성자의 반복 발언이 있음,
의견 차이가 존재함, 실제 관측과 비교할 자료가 있음. 문서량 자체가 기준은 아니다.
고객사의 발언은 투자자 의견과 다른 actor_role로 저장한다.

### 두 번째 커버리지가 범용성 시험

첫 파일럿만으로 공통 프레임워크를 완성하지 않는다. 이후 사용자 관심이 있는 다른 산업
(예: 소비재)을 작은 범위로 추가해 실제 공통점을 추출한다.
새 산업에서 관측 지표/동의어/원천 연결을 바꾸는 것은 정상이다.
발언 원장·시간 비교·출처 UI를 복제하거나 산업 이름별 분기가 코어에 늘어나면 설계를 수정한다.
통화·단위·회계 기간이 다른 지표에 동일 비교식을 강제하지 않는다.

## 3. 공통 코어와 산업별 설정의 경계

| 공통 코어 | 산업/커버리지별 설정 |
|---|---|
| 원문 버전·출처·인용 구간·수집 상태 | 소스, 작성자, 기업 별칭 |
| 작성자와 발행 채널의 분리 | 관찰할 경쟁사·고객·공급사 |
| 발언 시점·전망 대상 기간·시스템 인지 시점 | 핵심 쟁점, 업계 용어, 해석 사례 |
| 기대·수정·재전파 기록 | 지표 정의·단위·주기·비교 방식 |
| 동일 주체의 전후 비교와 원문 대조 | 자료 제공원, 갱신 일정, 신선도 기준 |
| 비교 불가·미확인·오류·정정 처리 | 관련 시장의 수급 관측 가능 범위 |
| 처리 예산·재시도·평가·사용자 교정 이력 | 사용자 중요도, 알림 조건 |

초기 설정은 단순한 버전 관리 파일/테이블로 충분하다. 플러그인 시스템·새 설정 언어는 만들지 않는다.
설정 변경에 따른 재분석은 영향받는 기록만 대상으로 하며 기존 결과를 덮어쓰지 않는다.

## 4. 의미 모델: 수준·변화·기대·해석·수급

### 펀더멘털과 기대

- 수준, 변화율, 변화율의 변화는 별도 값이다. 기울기는 1차 도함수, 가속도는 2차 도함수다.
- 실제 재무 자료는 이산·주기 자료이므로 무조건 미분하지 않는다. YoY 성장률의 전기 대비 차이 등
  사용한 계산 정의와 비교 기간을 명시한다. 계절성·기저효과·지표 변경을 무시한 가속 판단은 금지한다.
- 기대 대상은 `level / growth_rate / acceleration / timing / condition / other`로 구분한다.
- 가속 기대의 수정과 실제 가속도 변화는 다르다. 투자자 A의 상향 기대가 시장 전체 기대도 아니다.
- 정성 전망은 원문 표현을 유지한다. 불명확한 기간은 unknown이며 임의로 분기나 숫자를 채우지 않는다.
- 기대와 실제 수치 비교는 같은 지표·단위·대상 기간·정의일 때만 가능하다.
- 기대 수정도 같은 대상 기간을 비교한다. 2026년 전망과 2027년 전망의 차이는 그대로 상향 수정이 아니다.
- 컨센서스 수치, 관찰 집단 발언, 가격에서 역산한 기대는 구분한다. 역산에는 가정과 모델 버전이 필요하다.

### 심리와 수급

- 감성 하나로 압축하지 않는다. 주목 대상, 우려 사유, 표현된 확신, 명시적 행동 언급을 분리한다.
- 관찰하는 것은 표현된 입장이다. 속마음·실제 보유량·실행 거래로 승격하지 않는다.
- 알고리즘/파생상품 수급은 하나의 세력 태그가 아니다. 확인된 거래·자료, 대용 지표,
  발언자의 설명, 시스템 가설을 구분한다.
- 옵션 관련 데이터만으로 딜러 포지션이나 헤지 방향을 확정하지 않는다. 추정에는 필요한 가정과 한계를 붙인다.
- 수급 데이터가 없더라도 제품은 동작한다. 해당 층은 '관측 자료 없음'이며 심리로 대체하지 않는다.
- 가격 움직임을 설명하기 위해 그럴듯한 원인을 강제 생성하지 않는다. 촉발 계기 후보와 반대 근거를 함께 둔다.

## 5. 논리 데이터 모델 (물리 테이블 확정 전)

| 객체 | 필수 정보/역할 |
|---|---|
| Source / Actor | 채널과 실제 발언자, 역할, 동일인 연결 근거, 식별 불확실성 |
| DocumentVersion | 원문/첨부, 기존 ID, URL, 해시, 발표·수집 시각, 수정 관계 |
| EvidenceSpan | 문서 버전, 원문 구간/영상 타임코드, 언어, 인용/전언 여부 |
| CoverageSpec | 기업·쟁점·작성자·지표·인접 대상·처리 범위, 설정 버전 |
| ExpectationStatement | 발언자, 대상, 지표/쟁점, 관점, 전망 기간, 조건, 원문 근거 |
| StatementAssessment | 추출·해석 버전, 모델/프롬프트, 검토 상태, 불확실성, 사용자 교정 |
| ChangeEvent | 이전/현재 statement, 비교 축, 변화 유형, 비교 가능 여부와 이유 |
| PropagationLink | 원천 발언과 재전달/동의/반박/중립 인용 관계, 근거, 연결 확실성 |
| Observation | 펀더멘털·가격·수급 값, 단위·대상 기간·발표/이용 가능 시각·개정 버전 |
| ResearchQuestion / Judgment | 사용자 질문·판단, 근거 연결, 변경 조건과 이력 |
| Run / CoverageHealth | 입력 ID·버전, cutoff, 처리 버전, 실행 상태, 비용, 관측 공백 |

모든 주장은 원문으로 돌아갈 수 있어야 한다. 수집 시각을 발언 시각으로 사용하지 않는다.
발표 시각이 불명확하면 정밀도를 저장한다. 영상 게시 시각과 촬영/발언 시각도 다를 수 있다.
원문 증거와 그에 대한 해석을 분리하여 추출 오류를 고쳐도 원자료가 보존되게 한다.

### 시간의 세 축

1. **발언/공개 시점:** 언제 표현·공개됐는가?
2. **전망 대상 기간:** 언제의 사업/시장을 예상했는가?
3. **시스템 인지 시점:** 언제 수집하고 분석했는가?

역사 재생에서 뒤늦게 수집한 자료를 그날 시스템이 알고 있었던 것처럼 사용하지 않는다.
공개 자료 기준 재구성과 당시 시스템 이용 가능 자료 기준 재현은 다른 평가 모드로 표시한다.
수정 공시·수정 문서도 당시 버전을 사용해야 한다. 현재 모델로 재생한 결과는 당시 실제 운영 결과가 아니다.

## 6. 기대 변화 판정 흐름

1. 원문과 수정 버전 보존 → 기존 원천 ID 연결 → 검색 가능 상태로 적재.
2. 커버리지 관련성 후보 판정. 탐색 자료는 낮은 비용으로 유지하며 탈락 표본을 검사.
3. 발언자·전망 대상·기간·근거 구간 추출. 전언을 채널 운영자의 입장으로 오인하지 않음.
4. 동일 주체·쟁점·기간의 이전 발언 후보 검색. 하나의 사람에게 여러 조건부 시나리오가 공존할 수 있음.
5. 코드로 지표/기간/단위 호환성 확인, 모델로 의미 변화 제안.
6. 기대 상향/하향, 가속/감속 전망 변경, 예상 시점 이동, 조건 변경, 주목 이동,
   확신 표현 변경, 명시적 철회, 유지, 비교 불가를 구분.
7. 원문 전후 대조와 근거를 저장. 이전 자료가 없으면 '첫 관측'; 침묵은 유지/철회가 아님.
8. 다른 작성자에게 확산되는 경로와 의견 차이를 별도 기록.
9. 펀더멘털·가격·수급 타임라인을 붙이고 촉발 계기를 탐색. 앞뒤 순서만으로 인과를 확정하지 않음.
10. 읽기 전용 일일 변화 화면에 제시. 사용자의 오류 수정은 평가 사례와 해석 버전으로 축적.

초기에는 bounded 추출/비교 워크플로우를 쓰고, '왜 바뀌었나' 심층 질문에만 예산 제한 조사 루프를 시험한다.
모델·에이전트 형태는 대표 질문 평가로 선택하며 현재 파이프라인을 기본값으로 승계하지 않는다.

### 반복의 두 의미

- 원천 주장 1개가 채널 10개에 인용되어도 독립된 사실 근거는 1개다.
- 동시에 재전파 10건은 관심·확산의 관측이다. 삭제하지 않고 계보로 묶는다.
- 비슷한 주장이라는 이유만으로 전파를 확정하지 않는다. 명시 인용/링크와 추정 연결을 구분한다.
- 한 사람의 여러 채널 활동도 관찰자 수를 부풀리지 않도록 한다.

### 표본과 집계

기본은 개별 작성자의 전후 비교. 집계는 같은 관찰 집단의 비교 가능한 발언을 대상으로 한다.
관찰자 편입/이탈, 침묵, 수집 장애, 자료 지연과 분모를 표시한다.
'발언한 5명 중 3명 수정'과 '관찰 대상 10명 중 3명 수정'은 다르다.
소스 선정 이유/분야를 기록하고 똑똑함을 하나의 권위 점수로 만들지 않는다.
언급 빈도를 확신이나 정답 가능성으로 취급하지 않는다. 반대 관점 소스도 관찰한다.

## 7. 핵심 화면 제안

### 오늘의 변화

커버리지 선택 → 마지막 정상 수집 시각/관찰 범위 → 중요한 변화 카드.
카드: 누가·무엇을 바꿨는가 / 이전→현재 발언 / 대상 기간 / 직접 언급한 계기 /
사업·가격·수급 대조 / 독립 근거와 재전파 / 미확인 사항 / 원문 이동.
후속 행동: 원문 비교, 관련 발언 열기, 내 판단 기록, 오류 수정, 추적 질문 저장.

예시(가상): '성장 지속 전망은 유지하지만, A와 B가 투자 회수기간을 새로 우려했다.'
새 근거가 없다는 판정은 '검토한 자료 범위에서 확인되지 않음'으로 제한한다.

### 쟁점 상세

시간축 위에 사업 관측 / 작성자별 기대 / 가격·수급을 정렬한다.
장기 전망과 단기 가격은 각자의 해상도를 유지하며, 억지로 일별 점수로 채우지 않는다.
작성자별 소형 타임라인과 전후 원문을 우선하고 거대 네트워크 화면은 초기 필수가 아니다.

### 투자자 상세

분야별 최근 주장, 기대 변경, 아직 유지 중인지 확인할 수 없는 오래된 발언,
명시적 조건/철회, 재전파 원천을 열람한다. 성과 순위표는 초기 범위 밖이다.

### 5-state

| 상태 | 동작 |
|---|---|
| Empty | 커버리지 미설정/이전 발언 부족을 구분하고 설정 또는 첫 관측 표시 |
| Loading | 수집/추출/비교 진행과 마지막 완료 결과를 함께 표시 |
| Partial | 누락 소스·불명확한 주체/기간·미확보 수급을 명시, 확인된 변화만 표시 |
| Error | 오류 단계와 재시도, 이전 결과의 기준 시각 보존 |
| Ideal | 원문으로 검증 가능한 변화; 변화가 없으면 정상 수집 범위와 함께 '변화 미검출' |

## 8. 구현 경계와 기존 자산

### 구현됨: 수집 자료를 읽고 이어서 대화 (2026-09-09, D-150)

사용자 피드백: 분류·승인 원장은 사용자 가치를 먼저 주지 못한다. 첫 화면은 수집된 텔레그램·블로그·유튜브를 읽는 곳으로 바꾼다.
최근 24시간/7일/30일의 메모리 자료를 제품·소스별로 읽고, 저장 요약·본문 발췌·출처·시각을 바로 표시한다.
동일 본문 재전파는 묶되 다른 의견으로 세지 않는다. 선택한 자료와 같은 채널의 과거 관련 자료를 찾아 기존 챗봇으로 직접 전달한다.
‘최근 자료 정리’, ‘과거와 비교’, 자유 질문을 버튼/입력 한 번으로 시작하며 승인·라벨링을 요구하지 않는다.
명시한 첨부 문서는 검색 모델의 판단과 무관하게 답변 근거에 들어가며, 후속 대화에서도 유지한다.
과거 후보 연결은 변화 확정이 아니다. AI 정리본은 요약의 재료로 쓸 수 있지만 직접 발언 인용으로 쓰지 않는다.
자료의 실제 기간·최근 수집 시각·목록/첨부 상한을 표시한다. 문서가 없으면 기간 확장, 오류면 재시도, 질문 중에는 입력 보존/중복 전송 방지.
기존 실험 원장은 보조 검토 경로로 유지한다. 수집 코퍼스는 읽기 전용, 대화 기록은 기존 대화 저장소를 사용한다.

### 구현된 실험 API: 근거 준비 v1

- `GET /api/experiments/expectations/documents?product=hbm|dram|nand&source_type=blog|telegram|youtube&limit=20&before_id=...`
  : 명시 제품 어휘 후보. limit 1~50, 요청당 최대 500행을 검사하고 다음 행으로 계속할 커서를 반환.
  빈 items라도 has_more=true이면 미검사 자료가 남은 것이므로 '변화 없음'이 아니다.
  최신 저장 ID 순서이며 발언 시각 순서가 아니다. 세 제품 태그는 중복 가능.
- `GET /api/experiments/expectations/documents/{id}`: 지원 소스의 저장 텍스트와 해시·발표/수집 시각·검토 단서.
  사용자 note/canon 등 지원 밖 소스는 404. 상세는 제품 어휘가 없어도 지원 소스의 문서를 읽을 수 있다.
- `text_kind`: derived_summary / stored_transcript / stored_text / empty.
  유튜브 digest_status=ok 또는 알려진 정리본 표시는 derived_summary. 표시가 없다고 원저작/직접 발언이 검증된 것은 아니다.
- `source_text_available`: 저장 원문 후보 텍스트 존재 여부일 뿐 신뢰도나 정확성 보증이 아니다.
- `speaker=null`, `speaker_status=unresolved` 유지. 자기소개·서명·전언 패턴은 unverified 단서와
  반환 text 기준 문자 offset(start/end), SHA-256으로 제공. 파생 정리본에서는 화자 단서를 추출하지 않는다.
- 정규식 서명/전언 후보는 목록 항목이나 일반 괄호도 잡을 수 있다. 화자 귀속은 승인 단계에서 사람이 확인하며 실제 인용의 부분 문자열 검증은 추출/승인 단계에서 수행한다.
- 422: 잘못된 필터/범위, 404: 미존재/지원 밖 문서, 503: DB 읽기 실패. 부족한 자료는 warnings로 명시.
- DB mode=ro + query_only + 요청별 읽기 트랜잭션. 기존 lazy 문서 생성 API 우회. 모델·네트워크 호출·DB 쓰기 없음.
- 파일: backend/models/expectations.py · pipeline/expectation_evidence.py · routers/experiment_expectations.py.
- 검증: 임시 DB API 테스트 8개(정리본·자막·전언·비공개 소스 제외·페이지 연속성·스캔 상한·오류·쓰기 차단),
  실제 저장 문서 5개와 NAND 목록 smoke test. 생산 main은 import 확인만, 테스트에서 startup/봇을 실행하지 않음.

### 구현된 쓰기·비교·UI 계약

API 접두어는 모두 `/api/experiments/expectations`다.

| 경로 | 역할 |
|---|---|
| `POST /extractions` | `{doc_id}` → 202 작업 ID. 원문 버전+추출 버전으로 완료/진행 중 작업 재사용 |
| `GET /jobs?doc_id=...`, `GET /jobs/{id}` | 최근 20개 작업, queued/running/done/failed/cancelled 및 결과·사용량 |
| `POST /jobs/{id}/cancel` | 대기/실행 취소. 모델 반환 후에도 취소된 결과는 저장하지 않음 |
| `GET /statements?doc_id=...&status=...`, `POST /statements` | 최근 500개 기록 / 원문 해시·인용을 검증한 수동 초안 |
| `POST /statements/{id}/review` | expected_revision으로 동시 편집 충돌 검출, 승인/제외와 당시 필드·검토 이유 보존 |
| `GET /statements/{id}/comparison` | 승인 발언 중 같은 비교 키의 더 이른 발표와 대조 |
| `GET /statements/{id}/evidence` | 원문이 변경/삭제되어도 추출 당시 보존본 열람 |
| `GET /statements/{id}/history`, `POST /statements/{id}/notes` | 검토 이력·판단 메모 조회 / 메모 추가 |

- 별도 SQLite: `snapshots`, `jobs`, `statements`, `reviews`, `notes`. `expectation_store.py`만 관리하며 운영 DB와 경로가 같으면 차단한다.
  원문 스냅샷(문서 ID+해시)은 불변. 초기 실험 스키마 갱신도 이 DB에만 적용한다.
- `expectation_workflow.py`: 단일 프로세스 워커 1개, 진행/대기 최대 4개. 입력 앞 24,000자, 최대 8개 초안.
  길이 잘림·검증 제외 수를 결과에 표시. 취소 시 subprocess 그룹 종료, 모델 응답 150초 제한.
  프로세스 중단 후 남은 pending 작업은 10분이 지나면 실패 처리하여 재시도 가능하다. 자동 재실행은 하지 않는다.
- 설치된 Claude CLI의 sonnet/low를 기존 격리 실행 인자로 호출한다. 설정·MCP·도구를 비우고 문서를 데이터로만 제공한다.
  운영 `llm.run()`/`llm_calls`는 쓰지 않으며 모델·버전·usage·비용·시간은 실험 작업에 남긴다.
  CLI 로그인/사용량 문제가 있으면 작업 실패를 표시하고 수동 초안 경로를 유지한다.
- AI는 초안만 저장한다. 인용·발언자 근거는 원문의 연속 문자열이어야 하며 숫자는 단위가 필요하다.
  승인에는 실제 화자·직접/전언 관계 및 화자 근거 인용 또는 출처 확인을 설명하는 검토 이유가 필요하다.
  문자열 일치가 의미·화자·수치·층위의 정확성을 보증하지 않으므로 사람이 확인한다.
- 비교 키: 화자/제품/대상/층위/지표/축/전망 기간/비교 기준/단위/조건. 공백·대소문자만 정규화하며 별칭 추정은 하지 않는다.
  발표 시각은 시간대가 있어야 하고 전망 기간은 유효한 YYYY, YYYYQn, YYYYHn, YYYY-MM, YYYY-MM-DD만 허용한다.
  본인이 현재 표명한 투자 태도(lens/metric/axis=position)에 한해 horizon=current로 발표 시점 사이를 비교한다.
  이는 전망 기간을 임의로 만든 것이 아니며 실제 체결/시장 전체 수급을 뜻하지 않는다. 다른 층위에서 current는 비교 보류다.
  `unknown` 비교 기준과 상대 기간은 비교 보류. 최근 500개 승인 기록 중 발표가 더 이른 가장 가까운 발언을 찾는다.
  같은 인용은 반복 후보, 둘 다 명시 수치이면 산술 차이, 방향이 달라지면 후보, 나머지는 원문 대조 필요로 반환한다.
  `unclear`의 변화나 같은 방향을 확정적인 기대 변화/유지로 처리하지 않는다. 범위·조건의 의미 대조는 사람의 검토다.
- UI: `/experiments/expectations`, 하단 더보기 → 기대 관측 실험실(모바일: 기대 실험실).
  제품/탭/선택 문서/기록/목록 커서는 URL에 보존한다. 원문은 HTML 실행 없이 평문으로 표시한다.
  문장 선택 또는 직접 입력 → 초안 저장, 접을 수 있는 발언별 검토, 전후 비교/당시 원문/판단 메모/이력.
- 검증: 임시 코퍼스+실험 DB API 테스트 23개. 승인 경계·비교 키·시간·재전파·동시 편집·취소·중단 복구·멱등 버전·운영 DB 불변 검증.
  실제 코퍼스에서 모델 추출 smoke 수행. 이는 추출 품질/전체 변화 검출기 평가가 아니다.
  프런트엔드 타입 검사·프로덕션 빌드, 격리 fixture API에 연결한 브라우저 흐름 검증. 로컬 산출물은 `logs/memory-coverage/`.


단일 앱 + 관계형 저장 + 원문/첨부 저장 + 검색 + 복구 가능한 작업 원장으로 시작할 수 있다.
큐 서비스/그래프 DB/멀티 에이전트는 선행 요구사항이 아니다.
멱등 키는 문서 버전·추출 버전·커버리지 설정의 영향 범위를 반영한다. 처리 실패와 비교 결과 '변화 없음'은 다른 상태다.
요청 시 원문 읽기와 조사만 수행하며 외부 글의 지시를 실행하지 않는다.

기존 원문·첨부·수집 시간·사용자 노트/판단은 보존한다. 원 DB를 읽는 어댑터와 안정 ID 매핑으로 파일럿을 시작한다.
새 관측 원장은 분리해 기존 데이터 덮어쓰기 없이 재생/비교한다.
요약·태그·인과 엣지는 legacy 파생 자료로 보존하되 새로운 관측 사실로 자동 승격하지 않는다.
원문이 없는 과거 요약은 검증 제한 자료로 표시한다. 전량 재태깅은 첫 사용자 가치의 전제가 아니다.

## 9. 검증·확장 기준

### 초기 비교 평가

같은 자료·기간에서 A='오늘 자료 요약', B='작성자별 과거와 비교'를 대조한다.
사용자가 중요한 전환으로 표시한 실제 사례와 변화 없는 대조 사례를 함께 구성한다.
초기 20~30개 사례는 시작용 제안이며 통계적 보장이나 최종 품질 기준이 아니다.

필수 사례: 동일 기간 기대 수정 / 전망 기간만 바뀜 / 우려만 추가되고 전망은 유지 /
조건부 발언 / 제3자 인용 / 여러 채널의 동일 원천 / 반어·질문형 표현 / 동일인 별칭 /
발언 없음 / 수집 장애 / 뒤늦게 수집된 문서 / 사업 지표 둔화지만 기대보다는 양호 /
가격 하락 뒤 등장한 설명 / 수급 자료 없는 수급 주장 / 시간 단위 불일치.

측정: 변화 판정 precision·누락 recall, 원문 지지 여부, 주체/기간 정확성,
전파 관계 오탐, 중요 변화 확인 시간, 사용자 유용 판정, 커버리지당 처리·교정 비용.
기간을 나눈 평가와 사용자 검토로 과거 사례에만 맞춘 규칙을 방지한다.
손익·시장 예측 적중률은 초기 제품 성공 지표로 사용하지 않는다.

### 확장 게이트

1. 사용자가 실제 변화를 더 빨리 확인한 사례가 반복적으로 나온다.
2. 주체/기간 오인과 반복 인용을 독립 의견으로 세는 심각한 오류가 회귀 사례에서 해결된다.
3. 변화 없는 날·수집 장애를 구분한다.
4. 실행 비용과 사용자 교정 부담이 추가 커버리지에서도 감당 가능한지 실측한다.
5. 두 번째 산업을 공통 코어 복제 없이 추가할 수 있다.

수치 목표는 첫 기준선 확보 후 정한다. 기준 없이 종목 수나 소스 수를 먼저 늘리지 않는다.

## 10. 다음 설계 입력

- 첫 산업은 메모리반도체로 확정. 특히 주목하는 투자자·채널은 기존 코퍼스 점검 후 선정.
- 사용자가 기억하는 '생각이 바뀐 순간'의 실제 사례.
- 일일 변화 확인과 장기 기대 추적 중 우선하는 사용 빈도.
- 현재 확보된 펀더멘털·수급 데이터 범위와 필요한 시간 해상도.

입력 전에도 원문 계보·주체/시간 모델·비교 불가 규칙은 설계할 수 있다.
운영 소스 추가·수집 재개·유료 데이터 도입·기존 시스템 폐기는 별도 실행 결정이며 이 제안의 결과가 아니다.
