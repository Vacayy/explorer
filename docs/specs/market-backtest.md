# 시장 전략 비교 백테스트

상태: **첫 버전 구현·실제 비교 검증 완료** (2026-09-19). 사용자 요청: 조사에서 얻은 교훈에 따라 계획을 세우고 순서대로 구현·실행한다.

상위 문서: [SYSTEM](../SYSTEM.md), [시장 분석 계약](market-codeact.md). 진입: 시장 분석 → **전략 비교** (`/analysis/backtests`).

## 목표와 실행 순서

1. **데이터 점검**: 기존 불변 스냅샷의 가격·달력·종목·시총 범위를 읽기 전용으로 확인한다.
2. **실험 계약 고정**: 결과를 보기 전에 아래 전략, 매매, 비용, 기간을 저장한다.
3. **계산기 구현**: 미래 참조 방지, 다음 봉 체결, 현금·비용·보유 평가를 합성 데이터로 검증한다.
4. **실행·조회 연결**: 모델 호출 없는 고정 계산을 격리 환경에서 실행하고 실행 이력·실험 조건·곡선·CSV를 제공한다.
5. **실제 비교**: 동일 스냅샷으로 기준 전략과 복합 조건의 추가 효과를 계산한다. 개발/평가 구간을 모두 보고하며 결과를 보고 기본값을 최적화하지 않는다.

원본 DB·수집 DB·기존 분석 실행은 수정하지 않는다. 스냅샷을 만드는 작업은 기존 고정 exporter만 수행한다. 모델 생성 코드, 임의 SQL, 파일 경로를 백테스트 API에서 받지 않는다. 자동매매·주문·외부 라이브러리 실행·데이터 추가 수집은 포함하지 않는다.

## 사전 고정 실험 v1

국내 주식의 **매수 전용·동일 비중·20거래일마다 목표 재구성** 실험이다. 최초 자금은 1억원, 최대 편입 수 20종목, 매수/매도 각각 거래 금액의 25bp를 차감한다. 비용은 수수료·세금·슬리피지를 포괄한 **예시 시나리오**이며 실제 거래소 세율이나 증권사 요율을 뜻하지 않는다. 현금 이자·차입·공매도는 없다.

초기 비교 구간은 개발 `2026-02-03 ~ 2026-06-30`, 평가 `2026-07-01 ~ 2026-09-18`이다. 실제 다수 종목의 자료 시작(2024-09-19)과 365일+90거래일 준비 구간을 기준으로 시작일을 정했다. 평가 구간은 별도 초기 자금으로 시작한다. 표본이 짧으므로 전체 기간 수익률·최대 낙폭·거래 비용·노출·편입 수를 우선 표시한다. 현재 데이터에서의 잠정 비교이며 장기 수익성 입증으로 표현하지 않는다. UI에서 날짜·비용·편입 수를 바꾼 재실행은 새 실험으로 남긴다.

### 비교 전략 7개

| ID | 조건 |
|---|---|
| `buy_hold` | 시작일 당시 평가 가능한 고정 유니버스를 동일 비중 매수한 뒤 유지하는 참고 기준 |
| `sma_cross` | 최근 20거래일 내 SMA5가 SMA20을 상향 교차한 종목 |
| `breakout_20d` | 최근 20거래일 내 종가가 직전 20봉 고가 최댓값을 새로 돌파한 종목 |
| `momentum_20d` | 20거래일 수익률 순위 상위 종목 |
| `high52` | 최근 90거래일 내 종가가 직전 365달력일 고가 최댓값을 새로 돌파한 종목 |
| `high52_ihs` | `high52` + 같은 90거래일 구간의 역헤드앤숄더 넥라인 돌파가 해당 52주 돌파보다 앞선 경우 |
| `high52_ihs_ma` | `high52_ihs` + 최근 14거래일 종가가 각 날짜의 SMA20 이상 유지 |

패턴은 기존 `consecutive-pivots-v1` 정의(피벗 폭 3, 어깨 허용 오차 15%, breakout 기준 탐색)를 재사용한다. 패턴 발생일과 확인 가능일을 구분하고 `known_at <= 판단일`을 강제한다. 같은 날의 넥라인/52주 돌파는 선후 조건을 충족하지 않는다.

편입 한도가 있는 전략의 후보 우선순위는 모두 20거래일 수익률 내림차순, 동률이면 종목코드 오름차순이다. 따라서 이평/돌파 비교는 공통 순위 위에 해당 필터를 추가한 결과다. 후보가 20개보다 적으면 남은 몫은 현금이다(후보 수만큼 비중을 확대하지 않음). 단순 보유 기준은 전체 고정 유니버스를 사용하며 실제 지수와 동일한 벤치마크가 아니다.

### 시점과 체결

- 판단에는 해당 날짜의 종가까지 공개된 입력만 사용한다. 판단일의 신호로 당일 종가에 체결하지 않는다.
- 판단일 NAV·종가로 목표 비중에 해당하는 수량을 고정하고 다음 공통 관측 거래일의 시가에 그 차이만 거래한다. 매도 후 매수하며 비용·시가 갭으로 현금이 부족하면 체결 가능한 매수 주문 전체를 같은 비율로 축소한다. 다음 날 시가로 과거 신호나 목표 수량을 다시 선택하지 않는다. 실제 체결 후 비중은 목표와 다를 수 있다.
- 동일 비중 비교를 위해 분수 수량을 허용하는 연구 모형이다. 실제 주문 단위·호가·체결 우선순위를 재현한다고 표현하지 않는다.
- 시가/가격이 없거나 거래량이 0이면 체결하지 않는다. 이월 주문을 임의 체결하지 않으며 실패 주문 수와 이유를 남긴다.
- 종가가 없는 기존 보유분은 마지막 유효 종가로 잠정 평가하고 누락·지연 평가를 표시한다. 이후 정보를 보고 사전에 그 종목을 제외하지 않는다.
- 종료일에는 종가로 평가하며 강제 청산하지 않는다. 미실현 보유와 잔여 현금을 보고한다.

### 데이터와 유니버스

- 미래의 가격 완전성을 보고 종목을 고르지 않는다. 각 구간 시작일에 존재하고 공통 준비 구간이 확보된 종목으로 유니버스를 고정한다.
- 공통 준비 구간은 첫 판단일의 90거래일 이벤트 탐색 시작보다 365일 앞까지다. 계산에 필요한 관측일 누락·잘못된 OHLCV는 시점별 미평가로 집계한다.
- 과거 시총 필터를 켜면 각 판단일의 시총만 사용한다. 없는 값을 최신 시총으로 채우지 않는다. 첫 비교의 시총 하한은 0이다.
- 수집 유니버스가 현재 종목 중심이고 공식 상장·상폐 이력이 없어 생존 편향 가능성을 제거하지 못한다. NAVER 수정주가는 배당 포함 총수익률이나 과거 시점별 기업행동 처리를 보증하지 않는다.
- 관측 날짜 합집합은 공식 거래소 달력이 아니다. 거래정지·가격 제한·실제 유동성 제약의 완전한 모형도 없다. 결과는 항상 연구용 잠정 상태로 제공한다.

## 실행·결과 계약

입력 `BacktestSpec`: `start_date`, `split_date`, `end_date`, `initial_cash`, `max_positions`, `rebalance_every`, `buy_cost_bps`, `sell_cost_bps`, `min_market_cap`, `markets`. 전략 구조와 기본 기간은 버전으로 고정한다. 날짜는 `start < split <= end`, 각 구간은 최소 2거래일이어야 한다. 최대 기간·자금·편입 수·비용·동시 작업을 제한한다.

출력에는 입력 원문, 정규화 조건, 코드/스냅샷 해시, 사전 고정 시각, 단계별 상태, 오류와 실패 이력, 개발/평가 구간의 7개 결과를 남긴다. 전략별 일별 NAV·현금·노출·낙폭, 편입 수·후보 수·미평가·체결 실패, 거래 원장과 비용, 최종 보유분을 제공한다. 단순 보유 기준 대비 수익률 차이는 같은 구간끼리만 계산한다.

API는 `GET /api/analysis/backtests/config`, `POST /api/analysis/backtests`, `GET /api/analysis/backtests`, `GET /api/analysis/backtests/{id}`, `POST /api/analysis/backtests/{id}/cancel`, `GET /api/analysis/backtests/{id}/artifacts/{name}`를 사용한다. 결과 파일은 호스트가 검증·등록한 JSON/CSV만 제공한다. UI는 시장 분석 화면에서 별도의 '전략 비교' 화면으로 진입하고 기존 종목 검색 실행 상태와 분리한다.

`logs/market-backtests/`에 실행 이력·제어 파일·작업 공간·결과를 저장한다. 계산 전에 `experiment.json`으로 조건과 입력/코드 해시를 고정한다. 같은 입력을 서로 다른 macOS 샌드박스에서 두 번 계산하고, 종료 후 입력 파일·manifest 해시를 다시 대조한다. 호스트의 별도 검증기는 입력 시가/종가/거래량으로 체결·수량·비용·현금·일별 평가·최종 보유를 재검산한다. 재실행 일치만으로 정확성을 판정하지 않는다.

성공 계산도 데이터 한계 때문에 `partial`·완료 상태로 제공한다. 같은 요청 키는 기존 실행을 반환하고 동시에 한 실행만 허용한다. 취소·실패·서버 중단 이력을 보존하며, 결과 재조회나 화면 새로고침은 계산을 시작하지 않는다. 다운로드는 해시로 등록된 `experiment.json`, `result.json`, `equity.csv`, `trades.csv`, `summary.csv`에 한정한다.

## 완료 기준

- 합성 가격으로 다음 날 시가 체결, 비용/현금 수지, 거래를 줄이는 순재조정, 마지막 날 미체결, 결측/거래량 0, 피벗 확인 시점, 미래 데이터 추가에 대한 과거 신호 불변성을 검사한다.
- 개발/평가 구간은 독립 초기화하며 모든 비교 전략이 같은 스냅샷·기간·비용을 사용한다.
- 실제 스냅샷 비교 결과와 사용한 사전 고정 명세를 보존한다. 후보 0·거래 0도 숨기지 않는다.
- 백엔드·프론트 검사와 브라우저 실행→결과→재조회→CSV 경로를 확인한다.
- 원본 업무 데이터·스키마가 변경되지 않았음을 확인하고 한계와 함께 결과를 전달한다.

## 첫 실행 검증 기록

2026-09-19 사전 고정 기본값으로 실행 `321e50b8654a44b5b45d4e9add08f509`를 완료했다. 기존 스냅샷 `4062ca0a88b94be99f9a62a40eb2ace8`의 2,992종목·1,374,352행을 사용했고, 구간 시작 시점 준비 조건을 만족한 유니버스는 개발 2,322종목·평가 2,369종목이었다. 과거 시총의 결측이 많아 첫 실험의 시총 하한은 0이며, 원래 예시의 **시총 5,000억원 조건까지 검증한 결과는 아니다**.

격리 재실행 일치와 별도 원장 검산을 통과했다. 관련 백엔드 테스트 123개, 프론트 프로토콜·근거 테스트 7개, TypeScript/프로덕션 빌드 및 실제 브라우저의 실행→개발/평가 조회→CSV→새로고침을 확인했다. 데스크톱·모바일 화면 검증과 실행 전후 원본 자료 대조 기록은 `logs/market-backtest-verification/`에 보존한다.

실험의 수치·해석은 [첫 비교 기록](../../logs/market-backtest-verification/first-comparison.md), 원장은 `logs/market-backtests/runs/321e50b8654a44b5b45d4e9add08f509/`의 산출물에 있다. 평가 기간이 짧고, 복합 조건의 후보 감소는 현금 비중도 바꾸므로 수익률 차이만으로 개별 조건의 독립적인 효과를 입증하지 않는다. 이번 평가 구간은 이미 관측한 구간으로 기록하며 이후 최적화에 사용하면 새로운 미관측 검증 구간이 필요하다.
