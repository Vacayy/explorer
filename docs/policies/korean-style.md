# 한국어 문체 룰 (SSOT)

AI가 쓰는 한국어 글(내러티브·시장 요약·브리핑 등)의 자연스러움을 올리기 위한 압축 룰북. `im-not-strange-ai` v0.0 taxonomy(MIT)에서 S1 중심 상위 5카테고리만 추려 처방 1줄로 요약했다.

**두 지점에서 소비**:
- **Pass A (생성 시점)**: AI가 글을 처음 쓸 때 시스템 프롬프트 말미에 삽입 → 사전 회피
- **Pass B (생성 후)**: 홈 노출 핵심 글은 별도 sonnet 호출로 수술적 윤문 → 사후 정리

## 철칙

1. **의미 불변** — 사실·주장·수치·고유명사·직접 인용은 100% 보존
2. **register 보존** — 입력 격식을 유지. "~습니다/~이에요"로 들어오면 그대로. 평서형 "~한다"로 바꾸지 않는다
3. **장르 유지** — 시장 브리핑을 에세이·문학으로 전환 금지
4. **변경률 ≤30%** — 초과 시 원문 유지 (Pass B 안전장치)

## Do-NOT (탐지·수정 모두 제외)

고유명사·인명·제품명·기관명·티커 / 수치·날짜·단위·통화 / 큰따옴표 안 직접 인용 / 영어 약어(AI·GPU·CEO·CFO 등) / 재무 전문 용어(PER·PBR·ROE·CAPEX 등)

## 상위 5카테고리 — 피하거나 제거

### A. 번역투

| 패턴 | 처방 |
|---|---|
| "~에 대해(서)" | 목적격으로 직결: "X에 대해 논의" → "X를 논의" |
| "~를 통해" 남발 | "~로", "~해서", "~함으로써"로 분산 |
| "~에 있어(서)" | "~에서", "~을 볼 때" |
| "가지고 있다" / have·make 직역 | 형용사·동사 환원: "경쟁력을 가지고 있다" → "경쟁력이 강하다" |
| 이중 피동 "~되어진다" | 능동 또는 단일 피동: "판단되어진다" → "판단된다" |
| "~에 의해" 피동 | 행위자를 주어로: "AI에 의해 생성" → "AI가 만든" |
| "~할 수 있다" 남발 | 단언으로: "높일 수 있다" → "높인다" (근거 있을 때) |
| 추상 주어 + 사역/인지 동사 | 구체 주어로 환원. "데이터가 보여준다" → "~에 따르면 ~이다" |

### D. AI 관용구

| 패턴 | 처방 |
|---|---|
| 결산 피벗 "결론적으로/따라서/이를 통해/요약하면" | 1~2건만, 나머지 삭제 |
| "시사하는 바가 크다/주목할 만하다" | 삭제 또는 구체 결론으로 |
| "본질적으로/핵심적으로" | 삭제 |
| hype "파격적·압도적·혁신적·치명적" 반복 | 구체 수치·사실로 환원 |
| 의인화 추상 주어 "시장이 주시한다/기술이 묻는다" | 사람·기관 주어로. "시장이 주시한다" → "투자자들이 ~에 주목한다" |
| 결말 공식 "~할 때다/~해야 한다" | 평서로 닫거나 삭제 |

### E. 종결어미·리듬

| 패턴 | 처방 |
|---|---|
| 동일 종결어미 "~습니다" 4문장 연속 | "~었습니다·~ㄴ다·~ㄹ 전망입니다·~에요" 등 교차 (**register 안에서**) |
| 진행형 "~하고 있습니다" 반복 | 단순 시제 환원 가능하면 환원: "읽고 있습니다" → "읽습니다" |
| 문장 길이 균일 | 단문·장문 섞기 |

### H. 접속사·메타 서술

| 패턴 | 처방 |
|---|---|
| 문두 "또한·따라서·즉·나아가·아울러" 5회+ | 대량 제거. 문장 자체가 흐름을 잡게 |
| 메타 진입 "이는·이 점에서·이 관점에서" 3회+ | 본문에 녹이거나 삭제 |
| "즉" 남발 | 1회로 제한 |

### I. 형식명사·의존명사

| 패턴 | 처방 |
|---|---|
| "~인 것이다/~한 것이다" 결말 | 평서형으로 |
| "X은 ~라는 점에 있다" | "X는 ~다" 직설로 |
| "~다는 뜻이다/~다는 의미다" | 본문에 풀어 쓰기 |
| "~해야 한다·~해야 합니다" 반복 권고 | 평서·단언으로 |

## Pass A 지침 (생성 시점)

내러티브·브리핑 등 글을 **처음 쓸 때** 시스템 프롬프트 말미에 아래 한 줄 삽입:

> 문체 규칙: `docs/policies/korean-style.md`의 "상위 5카테고리" 패턴을 피해 써라. 처방 열의 "후" 형태를 기본으로. 단, 의미·수치·고유명사·격식(~습니다/~이에요)·장르는 보존.

## Pass B 지침 (생성 후 폴리시)

폴리시 LLM 호출 시 아래 시스템 프롬프트:

```
너는 한국어 문체 교정 편집자다. 아래 "문체 룰"의 패턴만 수술적으로 제거하고, 원문의 의미·사실·수치·고유명사·인용·register·장르·마크다운 구조는 100% 보존해라.

- 변경률 30% 초과 금지 — 초과할 상황이면 원문 그대로 반환
- 패턴 외 다듬기 금지 (리듬이 어색해도 룰에 없으면 두어라)
- 입력이 "~습니다"면 출력도 "~습니다". 평서형으로 바꾸면 롤백
- 마크다운 헤딩·불릿은 구조 그대로

[문체 룰: 위 '상위 5카테고리' 섹션 그대로 삽입]

출력: 윤문된 본문만. 설명·전후 비교 쓰지 마라.
```

## 안전장치

- Pass B 호출 후 **고유명사·숫자 토큰 검증**: 원문에 있던 숫자·영문 토큰이 결과에도 모두 있어야 함. 하나라도 사라졌으면 원문 반환
- 결과 길이가 원문 대비 50% 미만 또는 150% 초과면 원문 반환
- 결과에 입력 register와 다른 종결어미(평서형 "~한다"가 섞였는데 입력은 "~습니다")가 섞이면 원문 반환
