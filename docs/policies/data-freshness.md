# 정책: 데이터 신선도 및 캐시

---

## 1. 캐시 TTL 정책

| 데이터 | 캐시 키 패턴 | TTL | 갱신 트리거 |
|--------|------------|-----|-----------|
| 재무제표 | `finstate:{corp}:{year}:{reprt}:{fs}` | 7일 | 분기 공시 후 |
| 공시 목록 | `disc:{corp}:{start}:{end}:{kind}` | 1일 | 매일 |
| 주가 OHLCV | `price:{stock}:{from}:{to}` | 1일 | 장 마감 후 |
| 펀더멘탈 | `fund:{stock}:{from}:{to}` | 1일 | 장 마감 후 |

## 2. 프론트엔드 React Query 캐시

| 데이터 | staleTime | 설명 |
|--------|-----------|------|
| 기업 정보 | ∞ | 거의 변하지 않음 |
| 산업군 목록 | ∞ | 수동 시딩 |
| 재무제표 | 5분 | 같은 세션에서 반복 조회 시 즉시 |
| 주가 데이터 | 5분 | |
| KPI | 5분 | |
| 공시 | 5분 | |
| IR 메모 | 0 (항상 갱신) | 사용자 입력, 최신 보장 |
| 워치리스트 | 0 (항상 갱신) | 사용자 입력, 최신 보장 |

## 3. 캐시 무효화 정책

| 시나리오 | 동작 |
|---------|------|
| 사용자가 종목 처음 조회 | 백엔드에서 DART/KRX API 호출 → DB 저장 → 캐시 등록 |
| 캐시 유효 기간 내 재조회 | DB에서 즉시 응답 (API 호출 없음) |
| 캐시 만료 후 조회 | API 재호출 → DB 업데이트 → 캐시 갱신 |
| 강제 갱신 (향후) | `?refresh=true` 파라미터 → 캐시 삭제 후 재조회 |

## 4. API 호출 한도 관리

| 소스 | 일일 한도 | 관리 방법 |
|------|---------|----------|
| DART OpenAPI | 10,000건 | 캐시 우선, 배치 ETL로 선행 수집 |
| pykrx | 제한 없음 (비공식) | 과도한 호출 시 IP 차단 가능 → 적정 간격 유지 |
| yfinance | 비공식 (느슨) | market cap fallback용, 최소한으로 |

## 5. 데이터 정확성 정책

| 규칙 | 설명 |
|------|------|
| 원본 보존 | DART 원본 금액은 원(원) 단위 문자열로 저장, 변환은 표시 시점에 |
| 계정명 정규화 | `_normalize_account_name()`으로 통일 (영업이익 = 영업이익(손실)) |
| 분기 차감 | IS/CF는 누적→개별 차감 (Q2=H1-Q1), BS는 시점 데이터 그대로 |
| CFS/OFS 우선순위 | 연결(CFS) 우선, 없으면 별도(OFS) fallback |
| 자체 계산 지표 | PER=시총/순이익, PBR=시총/자본, ROE=순이익/자본 |
