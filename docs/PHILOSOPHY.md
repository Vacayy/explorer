# Explorer — 설계 철학 (관통 원칙)

> 이 문서는 개별 결정 **뒤에 흐르는 세계관**을 한 장으로 모은다. "왜 이렇게 결정하는가"의 상수(常數).
> 문서 3층(규칙=CLAUDE.md · 상태=SYSTEM.md · 결정=DECISIONS.md) 사이에 빠져 있던 **원칙 층**.
> 느리게 변하는 reference — 새 결정이 원칙을 바꾸면 여기와 DECISIONS 둘 다 갱신한다.
>
> 각 원칙: **원칙 → 왜 → 발현(기술) → 근거(D-항목·코드·문서)**. 근거는 상세의 정박점.

---

## 0. 한 문장

> **"믿는 자동 오라클이 아니라, 출처 달린 가설을 추적하는 인과 세계모델."** (ontology.md)

시장은 물리가 아니다(markets ≠ physics). 그래서 우리는 정답을 뱉는 기계가 아니라, **사실과 가설을 분리해 쌓고, 인과로 잇고, 시간·확신·장소로 정박하며, 기계는 제안하고 사람이 판단하는** 시스템을 만든다.

---

## 1. 인식론 — 사실과 가설을 절대 섞지 않는다

- **사실/가설 분리 (비타협)** — 모든 엣지·산출물은 `epistemic_type`을 갖는다.
  - **왜**: 둘을 섞으면 월드모델이 "그럴듯한 쓰레기"가 된다. LLM 산출(태그·요약·해석·답변)은 전부 가설이다.
  - **발현**: `entity_relations.epistemic_type` ∈ `fact`(공시·지분·계약·통계) · `observed`(널리 수용된 역사 해석 — 시장 가설보다 강하고 순수 사실보다 약한 중간 티어) · `hypothesis`(LLM 추출, `confidence`+`source_doc_id` 필수). UI에서 가설=주황(hypothesis) 스타일.
  - **근거**: [[D-005]](엣지 단방향+epistemic 필수) · [[D-030]](observed 중간 티어) · ontology.md §설계원칙 · SYSTEM.md §1
- **confidence = 엣지 가중치** — 인과의 강도·확실성을 0~1로.
  - **왜**: "얼마나 강한/확실한 원인인가"를 명시해야 약한 주장이 강한 사실을 흉내 내지 못한다.
  - **발현**: `entity_relations.confidence`. 재적재 시 강화, 교차검증(`corroborated_by`)으로 누적. 노드 중력(§2)과 **직교**하는 축.
- **신호는 근거와 함께** — 근거 문서 없는 신호는 표시하지 않는다. "왜?"가 항상 1클릭.
- **정직한 보고** — "완료"는 실제 충족했을 때만. 흉내는 완료가 아니다. 불확실하면 먼저 말한다. RAG가 근거 없으면 답을 거부하는 것도 이 원칙(느슨하게가 아니라 canon으로 출처를 준다).
  - **근거**: CLAUDE.md Integrity Rules · [[D-030]](canon 인물사 배경)

## 2. 인과 세계모델 — 하나의 그래프, 여러 속도·렌즈

- **하나의 인과 그래프, 두 개의 속도** — 내러티브(빠른 층)와 지식(느린 층)은 별개 시스템이 아니라 같은 그래프의 두 속도.
  - **왜**: 빠른 서사와 느린 축적을 한 그래프에 담아야 서로를 먹인다(내러티브→반복 확인→지식 승격→다음 내러티브의 전제).
  - **발현**: `narratives`(버전 보존) + `entity_relations`(narrative_id) + `promoted_knowledge_id` 루프.
  - **근거**: [[D-023]](하나의 인과 그래프, 두 개의 속도) · [[D-031]](월드모델 모드) · [[D-022]](지식 위계)
- **노드 중력 (pace layer)** — 노드마다 변화 속도(event→flow→cycle→structure→regime). 느릴수록 무겁다.
  - **왜**: 그래프가 "평평하고 뿌리 없는" 문제. 시대의 중력(regime)과 단발 사건(event)을 같은 무게로 두면 안 된다. degree 같은 창발 지표는 말뭉치 편향에 종속되므로 **명시적 층 분류**가 더 정직.
  - **발현**: `entities.meta_json.pace_layer` · 층별 감쇠(`LAYER_DECAY`: event 1.0 ~ regime 0.1, "늙지 않는 지식") · 세계관 뷰 시각 무게 · 순회 정지(`ROOT_LAYERS`=regime/structure).
  - **근거**: [[D-030]] · consolidation.py·narrative_graph.py·WorldviewPage.tsx
- **사실은 그래프로, 프레임은 렌즈로** — 역사적 사실 체인(관세 부과 2018)은 그래프 노드, 해석 프레임(투키디데스 함정)은 렌즈(lenses.py).
  - **왜**: 프레임을 확증된 지식으로 넣으면 반증 규율과 충돌한다 — 정전도 하나의 관점이다.
  - **근거**: [[D-030]] · [[D-045]](렌즈 모듈 주입) · lenses.py
- **반사성 나선** — 피드백 루프는 시점 다른 두 엣지로 편다(플라이휠). 인과의 뿌리·중간에 person/company 행위자 노드 허용('사라지면 약해지는가' 기준).
  - **근거**: [[D-027]] · [[D-029]](both_temporal → feedback_note 물질화)
- **주장은 시간·장소로 정박** — 인과는 언제·어디서 작동하는지를 갖는다(`reference_period`·`geo_scope`). 보편 노드 + 스코프 있는 엣지.
  - **근거**: [[D-021]](시간 정박) · [[D-034]](geo_scope)

## 3. 시장 인식론 — markets ≠ physics

- **거짓 정밀 금지 · 범위 + 조건부** — 단일 목표주가가 아니라 보수/기본/낙관 **범위**와 **무효화 조건**.
  - **왜**: 시장은 물리 법칙이 아니다. 정밀한 점 추정은 거짓 확신을 판다.
  - **발현**: 업사이드 모델(`models`) 4단계(P×Q·Capa·TAM→이익률→EPS→적정주가) 범위·조건부·하방(펀더 지지선)·무효화.
  - **근거**: [[D-035]](조건부 업사이드/하방) · docs/specs/action-thesis.md
- **하방 대비 상방(비대칭)이 레이팅의 기준** — %는 상승여력이지 포트폴리오 비중이 아니다.
  - **근거**: [[D-048]](레이팅=상승여력 비대칭)
- **Forward만 본다** — trailing PER은 시장이 참고 안 하는 지표. 12M Fwd PER 추이·리레이팅/디레이팅으로.
  - **근거**: [[D-046]](Fwd PER only)
- **말뭉치 최신편향 탈출** — 수혜 종목은 "문서에 자주 언급됐나"가 아니라 **인과 논리**로 지목(아직 회자 안 됐어도 논리상 수혜면). 유니버스는 필터가 아니라 크로스체크 태그.
  - **왜**: 공동언급 스크린은 이미 회자된 것만 잡는다 — 논리상 수혜를 놓친다.
  - **근거**: [[D-036]](파급 논리로 수혜 지목) · [[D-020]](항상-켜짐 4분면 기각)
- **핵심은 결론 먼저(BLUF)** — 리포트는 지배 내러티브가 던지는 핵심 질문 + 상방/하방 결론을 최상단에, 근거는 뒤에.
  - **근거**: [[D-049]](BLUF)

## 4. 인간·기계 R&R — 기계는 제안, 사람이 판단

- **제안-전용 (승인 전 무행동)** — 시스템은 "조사해볼까요?"를 던질 뿐, 승인 전 어떤 상태도 바꾸지 않는다.
  - **왜**: 자율을 좁게 정의한다 — 자동 실행이 아니라 자동 **제안**. 판단은 사람의 것.
  - **발현**: `agent_proposals` 승인 큐(neglect·contested·devils_advocate·falsifier·vocab_merge·report_suggest). 비싼 것(리포트)·되돌리기 어려운 것(노드 병합)은 반드시 승인 게이트.
  - **근거**: [[D-020]](승인 게이트형 제안 원형) · docs/specs/agent-proposals.md · [[D-050]](노드 통합 승인) · [[D-051]](리포트 승인 후 생성)
- **반증-우선** — 지식은 확신도만이 아니라 **무엇이 그것을 틀리게 하는가**(falsifier)를 함께 갖는다. 주목(salience)과 확신(conviction)을 분리.
  - **근거**: [[D-022]](지식 위계 — salience/conviction 분리 + 반증-우선)

## 5. 데이터 소유권 · 시간 · 축적

- **소유권 분할 (vault)** — 자동수집=DB 원본→vault로 투영(generated) / 사람의 가설·메모=마크다운 원본→DB로 흡수. **대칭 sync 금지**.
  - **근거**: SYSTEM.md §1·§4-3
- **append-only 히스토리** — 리포트·내러티브·브리프는 덮어쓰지 않고 버전을 쌓는다(드리프트 추적, 과거 열람).
  - **왜**: 판단이 시간에 따라 어떻게 변했는지가 자산이다.
  - **근거**: [[D-047]](리포트 append-only) · [[D-023]](내러티브 버전 보존)
- **축적이 해자** — 질문·답변·관측·컨센서스 스냅샷을 시계열로 쌓아 나중에만 가능한 분석(추정치 revision·프록시 추이)을 연다.

## 6. UX 규율

- **층위: 홈=delta, 디테일=state** — 홈은 변화의 스트림만, 전체 맥락은 디테일 페이지.
- **URL = 상태의 단일 소스** — 모든 필터·탭이 URL(새로고침·공유 보존). useState로 모드/탭 관리 금지.
- **전 화면 5-state** — Empty/Loading/Partial/Error/Ideal + FreshnessStamp.
- **근거**: SYSTEM.md §1 · docs/policies/ui-states.md · docs/policies/navigation.md

## 관통하는 메타 원칙

1. **분리해서 쌓는다** — 사실/가설, salience/conviction, confidence(엣지)/중력(노드), 사실(그래프)/프레임(렌즈), 수집(공공재)/판단(개인). 섞으면 정보가 죽는다.
2. **정직이 정밀을 이긴다** — 모르면 모른다고, 근거 없으면 거부, 범위로 답한다.
3. **기계는 제안·사람은 판단** — 자동화는 후보 생성까지, 승인은 사람.
4. **시간을 1급으로** — 정박(언제 작동), 속도(얼마나 느린가), 축적(버전·시계열).
