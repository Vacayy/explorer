이 화면에서 검토할 세 가지

아래 정책 탭은 제안 규칙이며, 아직 제품에 적용하지 않았습니다.
01 / ORIENTATION

사업 → 가격 → 근거

사업 구조와 확인할 지표를 처음부터 표시합니다. 차트와 사업 정보가 동시에 보입니다. 날짜를 선택하면 탐색 화면으로 진입합니다. 왼쪽 차트와 오른쪽 자료를 함께 읽고 개요로 돌아갑니다.

02 / CONTINUITY

읽어도 맥락은 그대로

자료를 열고 닫아도 날짜와 차트가 유지됩니다. 원문을 닫으면 같은 위치에서 다음 자료를 읽을 수 있습니다.

03 / EVIDENCE

그때 알 수 있었던 것

당시 공개된 자료와 이후 해설을 구분합니다. 수집된 것이 없다는 사실을 “일어난 일이 없었다”로 바꾸지 않습니다.

화면의 깊이와 탐색 배치

제품 정보 구조는 개요 / 실적·사업 / 자료로 분리합니다. 개요에는 사업 소개·주가·핵심 실적·최근 자료만 남기고 전체 재무 차트와 손익계산서는 실적·사업에서 제공합니다. 현재 HTML의 개요는 이전 재무 시안을 함께 검토하도록 남겨둔 상태이며, 이번 체험 변경 범위는 차트 기반 탐색입니다.

차트에서 날짜를 선택하면 별도 탐색 상태로 진입합니다. 데스크톱에서는 좌측 차트, 우측 기간별 자료를 고정 배치합니다. 긴 원문은 상세 읽기로 열고 닫으면 같은 자료 위치로 복귀합니다. 이후 날짜 변경은 우측 결과만 갱신합니다. 모바일은 차트 아래에 자료를 배치합니다.

뉴스 및 최신 동향우리의 텔레그램·블로그·공시·컨콜·유튜브를 통합한 자료 목록.뉴스 전용 데이터처럼 포장하지 않고 실제 출처·보유 범위 표시.
컨센서스·실적확보한 값과 기간이 검증될 때 보조 영역에 표시. 없어도 주 흐름이 작동.실제/추정 구분. 애널리스트 수·전망 분포를 임의 생성하지 않음. 국내·미국 커버리지 차이 허용.
여러 탭·질문 입력창이번 개요 화면에는 복제하지 않음. 기존 재무·사업·공시 상세는 기존 경로로 연결.대화·메모·요약을 첫 화면의 필수 작업으로 추가하지 않음.

PO decision · v3.0

기업 상세의 목적과 조사 도구를 구분합니다.

“기업을 이해한다 → 가격의 흐름에서 질문을 찾는다 → 선택한 구간의 자료로 확인한다.”

차트와 기업 맥락을 나란히 배치하고 최근 자료를 아래로 이어 읽습니다. 처음부터 기업의 현재 자료에 접근할 수 있으며, 구간 선택 시 배치 변경 없이 자료의 시간 범위만 바뀝니다. 요약, 스냅샷, 기업 상세 전용 메모는 이번 범위에서 제외합니다.

우선순위제품 결정판단 이유
반드시고정된 차트·기업 맥락·자료 목록 / 선택 전후에는 자료 범위와 기간 도구만 변경사용자가 이미 하는 분석의 반복 작업을 줄임.
조용히 지원공개시점, 출처, 기간 필터, 조회 상태 유지읽는 흐름을 끊지 않고 정확도와 연속성을 확보.
이번에는 제외요약 버튼 · 스냅샷 · 새 메모 입력칸찾아 읽는 일에 생성·작성·저장의 추가 결정을 얹지 않음.
01 · UNDERSTAND

무슨 사업인가

사업 한 줄, 매출 구조, 핵심 변수. 출처와 기준일을 갖는 안정적인 기업 설명.

02 · LOCATE

언제 평가가 달라졌나

가격·거래량을 보고 날짜와 구간 선택. 급등일 외에도 장기 횡보·하락을 자유롭게 탐색.

03 · INVESTIGATE

그 전에 무엇이 있었나

기간별 근거를 바로 읽기. 원문과 반대 해석을 확인하고, 빈 구간은 별도 수집으로 보강.

진입 맥락에 따른 첫 화면

진입 상황보여줄 것이어지는 행동
처음 보는 기업나란한 사업 설명과 가격·거래량 차트 + 아래 최근 자료. 논지 작성을 선행조건으로 요구하지 않음.궁금한 날짜 선택 → 자료 확인
이전에 분석한 기업일반 기업 링크는 첫 화면. 날짜를 포함한 링크·뒤로가기는 조사 상태 복원. 같은 세션의 확대·스크롤 유지.같은 구간의 다른 자료 확인
자료에서 기업으로 이동명시적인 “이 날짜의 기업 보기” 링크는 조사 상태. 일반 기업명 링크는 첫 화면. 공개일이 불명확하면 날짜를 임의 지정하지 않음.이 주장 이전의 맥락 확인
시세 없는 비상장 기업동일한 사업·자료 구조. 날짜 타임라인을 선택 도구로 사용.기간별 활동 조사 · 빈 차트는 만들지 않음

두 화면의 구성과 전환

A · 기업 이해 / 기본 상태

선택 날짜가 없는 첫 진입

  1. 기업명·시장·종목코드
  2. 누가 왜 구매하는지, 돈 버는 구조
  3. 주요 매출 구성·성장과 악화 조건·지표 2~3개
  4. 좌측 가격·거래량 차트와 우측 사업 정보
  5. 차트 아래 분기 실적과 최근 수집 자료, 우측 사업부 구성·직접 발표

최근 자료는 전체 보유 자료에서 공개일순으로 조회하며 페이지네이션. 기본값에 임의의 30일 제한 없음. 일반적인 AI 기업 프로필·보고서를 새로 생성하지 않음.

B · 구간 조사 / 선택 상태

차트 날짜 또는 구간을 선택한 후

  1. 같은 기업과 사업 설명 유지
  2. 동일 차트에 선택일·조회 기간 표시
  3. 차트 바로 아래 당시 자료·출처·검색 필터, 그 아래 최신 실적 패널
  4. 원문을 열고 닫으며 연속 탐색
  5. “날짜 선택 해제”로 최근 자료 복귀

별도 분석 시작 버튼이나 페이지 이동 없음. 조사 상태가 되어도 장기 흐름을 임의로 다시 맞추지 않음.

레이아웃과 정보 위계

  • 데스크톱 탐색: 좌측 약 60%는 차트·기간 조작, 우측 약 40%는 자료. 우측은 최소 360px 확보. 자료를 스크롤해도 차트는 유지하고 날짜 변경 시 열 너비를 바꾸지 않음.
  • 900px 이하 탐색: 차트 → 선택 구간 자료의 단일 열. 중첩 스크롤을 해제하고 페이지 스크롤 사용. 탐색에서는 사업·실적·보조 발표를 숨김.
  • 전역 팔로우 레일은 기본 접기. 회사별 조사 공간을 확보.
  • 실제 제품 본문 14~16px, 보조 12px 이상. 주요 판단이나 출처를 9px 배지에 숨기지 않음.
  • 이벤트 마커는 선택형. 현재 보이는 구간 기준으로 중복·겹침을 줄이고 모든 날짜 선택은 항상 허용.

기존 요소의 역할 조정

  • 사업 설명: 사업 구조·확인할 지표까지 상시 노출. 펼침에 따른 차트 위치 이동을 없애고 안정적인 사업 정보와 최근 변화를 분리.
  • 차트: 확대. 최근 변동률만 강조하지 않고 기간 탐색의 중심으로.
  • 일·주·월 요약: 이번 기업 상세의 범위에서 제외. 실제 자료 열람이 과도하게 어렵다는 관찰이 있을 때 재검토.
  • PER·재무·Peer: ‘사업과 지표’로 분리. 기간·단위·출처를 함께 제공.
  • 동시 언급과 반복 신호: 관련 자료의 보조 탐색으로 이동. 단순 빈도와 경제적 연관을 구분.

P04 — 요약·기록 기능의 재검토 조건

이번 기업 상세에는 요약 생성, 분석 스냅샷, 별도 메모 작성을 넣지 않습니다. 날짜를 선택하면 저장된 자료를 조회하며 LLM 생성이나 저장 여부를 묻지 않습니다.

기록은 실제 조사 중 다시 남겨야 할 내용이 반복해서 발생할 때 기존 스터디·노트와의 연결부터 검토합니다. 스냅샷은 서로 다른 시점의 분석을 비교·재현해야 하는 필요가 확인될 때 다룹니다.

출시 예정 기능으로 고정하지 않습니다. 캐싱 정책도 생성 기능의 효용을 확인한 뒤 결정합니다.

첫 화면과 조사 상태를 URL의 mode로 구분합니다. 조사 상태의 날짜·기간·출처·공개 기준·검색어를 복원합니다. 별도 저장 개념 없이 사용하던 화면으로 돌아오는 것이 기본 동작입니다. 실제 제품은 차트 확대와 목록 위치를 세션에 보존합니다.

이전 HTML에서 저장한 브라우저 메모·스냅샷 데이터는 삭제하지 않습니다. 이번 안은 그 UI와 새 저장 동작을 제외합니다. 기존 서비스의 스터디·노트·저장 기능도 변경하지 않습니다.

조회와 분석의 실행 경로

날짜 · 기간 선택→기업 / 공개시점 필터→소스별 조회 · 중복 정리→자료 목록 먼저 표시→원문 읽기 · 차트로 복귀

제안 API: GET /api/research/{entity_id}/evidence — from, to, cutoff, sources, query, cursor. 공통 결과는 원문 ID, 발행자, 공개시점·정확도, 사건일, 수집일, 관계 유형, 관련 대목, 원문 링크, 버전을 포함합니다.

첫 버전은 기업 이해 정보와 상태 전환, 기간 조회 API와 원문 열람을 완성합니다. LLM 작업 없이 결과를 반환하고 본문 전문은 자료를 열 때 가져옵니다. 요약 API와 분석 저장 모델은 첫 버전의 의존성에서 제외합니다.

현재 로컬 DB의 단일 기업·한 달·50건 SQL: 20회 중 첫 실행 약 135ms, 중앙값 약 7ms. 통합 API나 UI 성능 보장은 아닙니다. 현 단계에서 별도 검색 서버나 DB 교체를 선행할 근거는 없습니다.

성장 시 정규화 공개시각 인덱스와 기업·시간별 조회 구조를 보강합니다. 기존 인덱스의 적용 여부는 EXPLAIN QUERY PLAN으로 확인하고, 일 단위 날짜 함수로 인덱스 활용을 방해하지 않도록 범위 조건을 사용합니다.

검증 영역통과 조건
첫 진입과 상태일반 기업 링크는 날짜 미선택·최근 자료. 사업 구조·핵심 지표가 상시 노출. 날짜 선택 후 탐색에 진입해 좌측 차트·우측 자료 표시. 탐색 중 차트 폭·표시 기간 유지. 사업·실적은 탐색에서 숨김. 날짜 포함 링크·뒤로가기·새로고침도 같은 규칙 적용.
핵심 사용성관심기업 3~5개, 갭 변동·신고가·장기 하락 등 서로 다른 구간으로 실제 조사. 날짜 선택 → 관련 자료 → 원문 → 차트 복귀를 반복 검증.
재무 정확성원 공시와 분기·연간 값 대조. 누적 재차감·단위·손실·결측·정정·연결조정 검증. 도넛 합계와 연결 매출 대사. 실제·추정과 발표일 표시. 내러티브의 분기·출처 연결 확인.
시간 정확성장전·장후·주말·미국/한국 시차·날짜만 있는 자료·늦은 수집·통계 수정 사례 테스트. 기본 당시 목록에 미래 공개 자료가 포함되지 않음.
조회 정확성기업+기간 필터를 검색 순위 계산 전에 적용. 소스 누락·중복·별칭 혼동·단순 언급을 검증. 같은 조건의 결과를 재현.
상태와 복귀빠른 날짜 변경 시 응답 역전 없음. 원문 닫기·뒤로가기·새로고침 이후 선택 복원. 0건과 실패는 다르게 표시.
성능 목표날짜 선택 피드백 100ms 이내, 로컬 저장 자료 첫 페이지 API p95 500ms 이내를 목표로 계측. 아직 달성한 수치가 아님. AI·외부 수집은 분리 측정.
접근성과 화면키보드만으로 날짜 선택·필터·원문·복귀 가능. 390px 폭과 200% 확대에서 기능 손실 없음. 색상 외에도 선택·상태를 텍스트로 제공.

성공 지표

기업 이해: 처음 본 사용자가 주 고객·돈 버는 구조·핵심 변수 하나를 자신의 말로 설명할 수 있는지 확인합니다.

조사 지표: 관심 구간을 고른 후 유효한 원문 근거에 도달하기까지 걸린 시간. 기존 구글 검색 방식과 같은 과제로 비교합니다.

보조 지표: 날짜 확인과 외부 검색 이동 횟수, 원문 열람 후 차트 복귀 성공률, 실제 도움이 됐던 자료 비율.

품질 지표: 시간 오분류, 잘못된 기업 연결, 원문 접근 실패, 자료가 있는데 검색에서 누락된 사례.

체류시간·요약 생성량 자체를 성공으로 보지 않습니다. 개인 로컬 도구에 맞게 최소한의 작업 이벤트만 계측하고 메모 본문은 분석 로그에 넣지 않습니다.

예시 HTML의 구현 범위

동작: 첫 화면·조사 상태 전환과 복귀, 차트 표시 기간, 날짜 클릭·입력, 거래일 이동, 기간·출처·검색 필터, 공개 기준, 이후 자료 분리, 예시 원문, 조회 조건 복원, 상태 전환, 인쇄.

시뮬레이션: 주가·기업·자료·분기 재무·사업부 비중은 모두 가상. 오류·로딩·보유 범위는 정책 검토용 예시. LLM 생성과 새 분석 저장은 실행하지 않음.

실제 제품 연결 전: 실데이터 API, 사업부 매출 수집, 재무 검증·정정 이력, 외부 수집, 차트 확대·드래그·키보드 직접 선택, 정교한 사건 중복 묶기는 미구현.

이 파일은 검토용 독립 HTML이며 기존 기업 상세 화면의 동작을 변경하지 않습니다.
