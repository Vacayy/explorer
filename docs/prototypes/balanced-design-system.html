02 / TOKENS

PageHeader는 페이지 h1 한 개. SectionHeader는 h2. 헤더 액션은 좁은 폭에서 다음 행으로 이동합니다. 빈 슬롯은 DOM 여백도 만들지 않습니다.

제안 API · 구현 전 계약 예시

<PageLayout
  mode="workspace"
  header={<PageHeader title="Home" />}
  overview={<IndexStrip />}
>
  <SplitWorkspace
    primary={{
      label: '시장 브리핑',
      content: <MarketBriefing />
    }}
    secondary={{
      label: '피드',
      content: <Timeline embedded />
    }}
    activePanel={view}
    onActivePanelChange={setView}
  />
</PageLayout>

PageLayout: mode="document | workspace | app", width="full | reading", header / overview / toolbar / footer / children. 조합 가능한 ReactNode 슬롯을 사용합니다. SplitWorkspace만 패널 전환과 스크롤을 담당하고 URL 상태는 페이지가 소유합니다.

앱형 입력창은 별도 ComposerLayout으로 조합합니다. sticky, split, chat, dense 같은 boolean 옵션을 한 컴포넌트에 계속 추가하지 않습니다.

새 업데이트를 가져오지 못했습니다

기존 데이터가 있으면 마지막 갱신 시각과 함께 유지. 해당 영역만 재시도.

상호작용 계약

  • hover에만 존재하는 액션을 만들지 않습니다. 키보드 focus와 터치에서도 노출합니다.
  • 스크롤 패널에는 이름과 포커스 경로를 둡니다. 탭 전환 뒤 숨은 패널에 포커스가 남지 않게 합니다.
  • 대화상자는 제목·닫기·포커스 복귀를 기본 제공하고, 복잡한 상호작용은 기존 Radix 동작을 재사용합니다.
  • 필터·페이지·모바일 패널은 URL, 임시 펼침과 메뉴는 로컬 상태. 레이아웃은 쿼리 키와 데이터를 알지 않습니다.

출시 전 검증 기준

  • 일반 텍스트 대비 4.5:1, 대형 텍스트·필수 UI 경계 3:1을 목표로 실제 조합을 측정합니다.
  • 390 / 768 / 1024 / 1440px, 레일 열기·닫기, 200% 확대, 짧은 높이, 라이트·다크를 확인합니다.
  • 탭 이동, 패널 키보드 스크롤, 모바일 Safari 입력·가상 키보드, 긴 한글 제목을 점검합니다.
  • 주요 컴포넌트에 normal / focus / disabled / pending / error 예시와 시각 회귀 기준을 둡니다.

이 HTML은 시각 기획용입니다. 제품 전체의 접근성·동작 검증을 완료했다는 의미는 아닙니다.

07 / DELIVERY

완료 조건: 컴포넌트 갤러리, 테마·밀도·상태 예시, 기존 스타일 대응표.

홈·피드에 적용

PageLayout과 SplitWorkspace를 홈에, document 패턴을 피드에 적용합니다. 출처 카드와 시스템 요약 카드는 공통 구조를 공유합니다.

완료 조건: 필터 URL·원문 링크·스크롤 유지, 모바일·레일·높이 검증.

페이지군별 확장

기업·산업·수출입 → 리포트·원문 → 대화 순서로 이행합니다. 각 군의 예외를 검증한 뒤 구 스타일과 호환 alias를 제거합니다.

완료 조건: 예외 목록 소진, 임의 글자 크기·반복 덮어쓰기 감소, 회귀 점검.

문서와 코드의 기준점은 하나씩

이 기획서는 검토용 시각 자료입니다. 채택된 토큰·컴포넌트 계약은 기존 DESIGN_SYSTEM.md에 통합하고, 진행 상태는 DESIGN_REVIEW.md에서 관리합니다. index.css가 토큰 값의 단일 원본이 되며, 같은 내용을 별도 spec으로 계속 복제하지 않습니다.
