    스크롤 책임은 세 가지로 제한

    문서형 — 페이지 전체 스크롤. 피드·리포트·문서.
    분할형 — 상단 공통, 데스크톱 두 패널 독립 스크롤. 홈·기업 탐색.
    앱형 — 본문만 스크롤, 입력 영역 유지. 대화.
    빈 슬롯은 공간을 차지하지 않습니다. 데이터 로딩·오류 상태도 동일한 구조를 유지합니다.

    어떤 페이지에 어떻게 확장할까

    페이지상단 슬롯본문 패턴
    홈제목 + 시장 지수브리핑 / 피드 · 독립 스크롤
    통합 피드제목 + 소스·유형 필터읽기 폭의 단일 타임라인
    기업 / 산업대상 개요 + 분석 탭분석 / 관련 원문
    리포트 / 원문제목 + 출처·기준 시각읽기 본문 + 선택적 목차
    대화대화 제목 + 액션메시지 스크롤 + 입력 슬롯
    세 안에서 공유하는 디자인 기준

    IBM Plex Sans / Sans KR 우선. 제목 24px, 섹션 18px, 본문 14–16px, 캡션 12px를 기본으로 제안합니다. 작은 메타 정보가 많은 이 목업은 밀도 비교용이며, 실제 구현에서는 최소 크기와 대비를 검증합니다.

    모바일은 두 패널을 탭으로 전환하고 페이지 스크롤을 사용합니다. 데스크톱 분할 여부는 레일을 제외한 실제 가용 폭으로 결정합니다. 목업은 비교를 위해 고정된 프레임 안에서 스크롤됩니다.

    추천 · 01을 공통 기반으로

    홈은 균형형으로 시작하고, 리포트에는 02의 읽기 위계, 기업 분석에는 03의 탐색 도구를 조합합니다. 세 벌의 레이아웃을 따로 유지하기보다, 하나의 슬롯 계약과 세 가지 본문 패턴을 유지하는 방향입니다.

    검토 범위: 레이아웃·정보 위계·스크롤·페이지 확장성. 버튼 중 컨셉 선택, 모바일 보기, 슬롯 표시, 모바일 패널 전환, 피드 보기는 동작합니다. 카드·필터·도크는 외형 예시입니다. IBM 웹폰트는 네트워크가 필요하며 오프라인에서는 시스템 글꼴로 표시됩니다. 실제 라우터·데이터·앱 컴포넌트는 변경하지 않았습니다.
